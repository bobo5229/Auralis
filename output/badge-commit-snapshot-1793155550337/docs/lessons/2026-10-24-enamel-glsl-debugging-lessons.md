# 珐琅徽章 GLSL 原型排查复盘

复盘日期：2026-10-24。

本次为「100 小时·成章」制作 GLSL 反光替换原型。材质拆分、贴图生成和视觉调校属于必要工作；额外耗时主要来自验收工具的启动排查、异步断言和缩放处理。最需要改进的是：更早记录失败阶段，在最小探针成功后及时转查完整脚本的差异。

本文依据本会话的执行记录、保留日志及最终源码整理。早期日志和报告曾被后续运行覆盖，未保留完整崩溃栈或各阶段计时，因此不估算耗时比例，也不把有效修正扩大为未经验证的底层根因。经验用于相似任务参考，强制约束仍以[环境与操作](../rules/environment.md)及[风险与验收](../rules/validation.md)为准。

## 1. 将不同失败混在同一条环境排查链中

首次在执行沙箱内启动 Electron，出现 Windows IPC 和缓存目录的拒绝访问错误。随后在沙箱外运行完整验收器，出现原生退出和 `crashpad ... not connected`。这两种现象没有足够证据证明属于同一个故障。

当时参考了[2026-09-28 安装目录 ACL 复盘](../reviews/2026-09-28-electron-startup-acl-crash.md)，读取权限，并将相同 Electron 二进制复制到临时目录对照。复制后完整验收器仍失败；随后最小内存页面探针成功创建 WebGL2 上下文。

走弯路的地方是：在验证完整脚本最后执行到哪里之前，投入了多轮启动、路径和入口包装尝试。旧 ACL 案例提供了排查方向，却没有证明本次故障由 ACL 触发。

后续采用以下判断顺序：

1. 区分执行沙箱拒绝、Electron 主进程退出、Renderer 崩溃、着色器编译错误和页面断言失败，分别记录错误及启动条件。
2. 先跑同一运行时的最小页面与 WebGL 探针，保留硬件加速和沙箱设置。
3. 最小探针成功后，优先比较它与完整验收器新增的初始化、调试和页面逻辑；只有出现新的路径或权限差异证据时，再继续环境分支。
4. 使用新的假设再次启动前，明确该次运行要区分什么；相同的笼统错误不能作为反复换路径的理由。

`crashpad ... not connected` 本身不能证明显卡、驱动或权限故障。历史复盘中的 SID 和修复步骤也不能直接用于另一轮任务。本轮未修改安装目录 ACL。

## 2. 阶段记录加得太晚，延迟定位验收器调用时序

增加阶段记录后，确认脚本已经完成服务创建和窗口创建，问题集中到导航前的 DevTools 接入与设备模拟。将这组调用移到 `await win.loadURL(...)` 之后，验收器首次进入有效画面和页面断言；最终也从原安装路径完成验收。

这支持将调用顺序作为本次有效修正，但没有单独分离 `debugger.attach()` 和 `Emulation.setDeviceMetricsOverride` 两个变量，也没有原生崩溃栈，不能据此规定所有 Electron 版本都禁止导航前使用这些 API。

从第一版验收器就按实际执行路径记录关键阶段，例如 Electron ready、服务与窗口创建、页面导航、调试器接入和首帧；设备模拟、材质准备仅在该路径涉及时记录。失败时保留最后完成阶段和原始错误，避免只留下进程退出码。

本轮还将隔离 profile 的设置移到主进程同步启动阶段，避免异步文件操作让默认 session 先初始化。这是防止配置时序竞争的配套调整，现有证据不足以认定它曾是本次原生退出的原因。

相关实现：[隔离验收器](../../demo/archive/enamel-milestone/glsl/verify.cjs)。

## 3. 输入断言检查得早于事件效果

首个有效运行在鼠标左倾场景出现 `AssertionError: left`。测试发送 `mouseMove` 后立即等待「没有运行中的动画」，此时输入可能还没被 Renderer 处理，页面仍处于上一轮的静止状态，等待条件已经成立。断言因此读到了零姿态。

这类失败首先应检查输入是否到达、目标状态是否改变，再判断动画是否完成。等待顺序应为：

1. 发送真实输入。
2. 等待该输入应产生的外部状态变化，例如目标倾角改变或反光开关生效。
3. 等待过渡完成，再断言最终结果。

当前验收器在鼠标输入后增加了 40ms 缓冲，并检查倾角和归位。这是本机验证使用的缓冲值；后续编写类似用例，优先等待明确的事件结果，避免将固定延时作为跨环境完成保证，也不通过替换真实事件处理逻辑让测试通过。

## 4. 将初始化与缩放竞争误当成普通尺寸检查

后续运行暴露了两个不同问题：

| 现象                                                  | 核对结果与修正                                                                                                      | 可复用判断                                                       |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `Cannot set properties of undefined (setting 'left')` | 贴图仍在加载，Renderer 已创建，camera 和 mesh 尚未创建，缩放事件提前调用了 `resize()`；增加对全部所需对象的就绪检查 | 异步初始化期间逐步创建的对象不能共用一个过早成立的「已准备」条件 |
| 设备模拟切到 DPR 1.25，渲染器仍报告约 1               | CSS 宽度不变时，原有尺寸观察不足以更新绘图缓冲；增加 resolution 媒体查询监听，并在变化后重新订阅                    | DPR 变化与 CSS 尺寸变化分别处理，检查实际绘图缓冲和渲染器比例    |

比对 DPR 时使用合理浮点容差；约 `1.00000003` 不应被当作与 1 不同的缩放状态。相关实现：[原型初始化与分辨率监听](../../demo/archive/enamel-milestone/glsl/app.js)。

隐藏窗口的动画和截图节奏也曾拖慢验收。最终使用离屏窗口并设置帧率后完成检查。隐藏窗口的测试耗时、录制期间的 rAF 帧间隔和实际 GPU 绘制耗时应分别解释，避免将验收窗口的调度节奏归因于着色器性能。

## 5. 视觉伪影要检查数据精度

实际画面中出现了反光边缘分段和细碎轮廓。生成器起初对模糊后的 8 位高度数据求差分，量化台阶被放大成法线变化，随后又被高光放大。

修正为浮点精度的高度模糊和差分，最后才编码法线贴图，并复查大小图。相关实现：[材质生成器](../../demo/archive/enamel-milestone/glsl/build-materials.mjs)。

后续遇到反光条带、轮廓台阶或闪烁时，先分别检查底色、材质遮罩、法线和遮蔽数据，判断异常出现在哪一层，再调整反射参数。数据精度问题需要修正生成过程；仅调低高光强度可能暂时掩盖伪影。

## 6. 下一次采用的排查与交付顺序

首轮方案同时包含完整对照页、两种状态、键盘交互、缩放、回退、截图和录屏，增加了用户看到第一版核心效果前的等待。后续仍完成已授权的交付范围，但把首次可看结果提前：

1. **先得到最小有效画面。** 单枚、单状态、固定尺寸，完成去除固定反光和一次真实 GLSL 渲染；提供可打开的入口。
2. **再调校材质。** 用原版、关闭动态反光和重新打光三种画面检查反光替换；保留用户认可的视觉基准。
3. **逐项加入边界验证。** 状态、尺寸、DPR、输入、减弱动态效果和回退分步加入；新增失败优先比较该步引入的差异。
4. **目标稳定后生成证据。** 截图、录屏和性能采样对应最终版本。已有检查通过后，仅为新修改、失败或未解决的问题补充复验。

每轮失败使用独立输出目录或运行编号，保留启动条件、最后阶段、错误和结果；将最新通过结果单独索引。本轮多次覆盖同名日志，增加了回顾成本，后续应在首次失败时就保留证据。

本轮最终在 Electron 38.8.6、NVIDIA RTX 5060 Laptop / ANGLE D3D11、GPU 沙箱开启的条件下通过隔离验收。最终报告与画面位于[本地验证目录](../../output/enamel-glsl-validation/)；代码和验证入口见[历史原型说明](../../demo/archive/enamel-milestone/glsl/README.md)，徽章后续维护使用[通用 GLSL 工具](../../scripts/badges/README.md)。这些结果说明本次原型可运行，不能替代其他徽章或其他机器的验证。
