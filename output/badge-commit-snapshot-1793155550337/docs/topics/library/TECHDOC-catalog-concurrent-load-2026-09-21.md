## 问题与证据

`LibraryCatalogSnapshotStore` 只保存一个快照。每次 `refresh: true` 都替换该快照；旧游标随后抛出 `Library catalog cursor refers to an expired snapshot`。
`loadLibraryCatalogSnapshot` 每次加载首批都传入 `refresh: true`。不同消费者的 generation 和请求协调器不能协调彼此。

此前以真实 Store 和加载器进行内存模拟：两个消费者交错加载 5,001 首歌曲，一个成功、另一个游标过期。5,000 是当前加载器使用的最大页长，并非缺陷只会发生于该固定规模；只要需要多页就存在风险。
主列表与智能歌单创建窗口都消费完整曲库，具备同时加载的入口。真实 GUI 尚未复现，查询时间、IPC 开销和内存峰值尚未测量。失败前的构建与传输已经发生，但不能据此声称存在无限重试。

## 目标与边界

- 同一 Renderer 的消费者共享一次完整加载；消费者卸载不能取消其他消费者需要的加载。
- 同一加载全过程绑定一个不可变快照，完整校验后才提交给搜索、分组、播放队列。
- 主进程刷新不立即破坏仍在读取的上一代快照；保留数量、时间均有界。
- 曲库变更不能被活跃请求合并逻辑吞掉；旧结果不得覆盖新 generation。
- 保持拼音排序和分页 IPC，不改用数据库 OFFSET，不为每个消费者复制一套长期全量缓存。

## 建议实现

### 1. Renderer 共享完整加载任务

在现有曲库加载工具附近实现单一共享协调入口，让主列表、智能歌单创建器等全量分页消费者统一使用。复用现有 `libraryRequestCoordinator` 的优先级和 generation 语义，避免建立平行的状态体系。

共享的是执行中的完整加载 Promise。每个调用者保留自己的 `isCurrent` 判断；不要把第一个调用者的生命周期回调传入共享底层任务。过期调用者丢弃结果，其他调用者仍可完成。

共享数据必须只读，消费方排序不得原地修改。默认不引入跨事件的长期结果缓存，防止再产生一套失效机制。
加载期间收到新刷新请求时，记录待刷新 generation；当前任务结束后合并执行一次最新刷新。前台刷新、元数据保存、后台刷新的优先级保持仓库规则。不能把旧任务结果作为新变更已被处理的证明。

### 2. 主进程保留有界的快照代际

将单一快照槽改为按 snapshotId 查找的有界存储；带游标请求只访问该 ID，不得解释为当前快照。构建仍串行完成。

建议初始上限为当前代加上一代，共两代；闲置过期时间可从 60 秒起步，作为可测试常量，实施时依据现有基准确认。它们是设计起点，不是测量结论。采用惰性清理，避免添加无必要的常驻定时器。

保留两代会增加主进程内存，应记录保留数和现有 heap 诊断，不能无限保留历史快照。容量淘汰或过期必须返回可识别的错误；高频第三次刷新仍可能淘汰旧代，因此还需要下一节的受控恢复，不能宣称支持无限并发。

### 3. 受控恢复

游标过期通过现有 IPC 错误约定表达为可判别错误；若扩展错误契约，必须同步 Shared、Main 和 Preload，不依赖 Error 自定义属性必然跨 IPC 保留。
只对该错误从第一页重新加载一次，丢弃旧聚合数组；格式错误、查询失败和取消不得重试。重试仍经过共享入口。第二次失效显示可恢复的加载错误，保留此前完整 UI 数据，禁止无限重建。

## 实施与验收

先把 5,001 首交错读取变为定向回归测试，再实现共享任务、主进程有界保留和受控恢复，最后接入所有分页消费者。不要顺带修复其他智能歌单缓存问题。

| 场景                       | 验收结果                                                   |
| -------------------------- | ---------------------------------------------------------- |
| 0、5,000、5,001 首         | 数量、顺序和分页终止正确，无重复或遗漏                     |
| 两消费者同时加载           | 同一 Renderer 合并底层任务；主进程跨代读取保持各自快照一致 |
| 一方卸载或切换条件         | 不覆盖其新状态，也不打断另一方                             |
| 加载中曲库变更             | 合并后续刷新，最终结果包含新变更                           |
| 第三代刷新、过期、错误游标 | 淘汰有界，过期最多重试一次，错误游标不重试                 |
| 成功与失败交错             | 不向 UI 提交半份数组；失败后可再次正常加载                 |

优先扩展已有 Store、加载器和协调器测试，接线改变后执行类型检查。使用合成数据记录构建次数、分页次数和保留代数；若比较耗时和 heap，须报告样本规模、环境与多次结果，不制定无依据的固定百分比指标。不要求全仓测试或 Electron smoke。
