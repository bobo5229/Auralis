# 子代理派遣与额度

父代理在满足任务质量要求的前提下，选择预期总额度最低的派遣方案，综合模型能力、思考强度、上下文长度、代理数量与返工概率。用户指定模型、思考强度或预算时遵从指定。

日常检查由施工者完成；达到[独立验收条件](validation.md#完成与独立验收)时派遣只读审查子代理。其他专项验证在可独立完成且收益超过交接成本时委派，授权范围按[项目入口](../../AGENTS.md)执行。

## 模型与思考强度

派遣前判断任务的范围、推理跨度、不确定性、失败后果和所需工具能力，再从当前可用模型及其支持的思考强度中选择配置。

| 任务复杂度         | 典型任务                                                           | 配置方向                                     |
| ------------------ | ------------------------------------------------------------------ | -------------------------------------------- |
| 简单、边界明确     | 执行已确定的检查命令、汇总日志、局部引用核对                       | 优先轻量模型，使用低或默认思考强度           |
| 中等、需要关联判断 | 多文件回归、一般缺陷定位、组件行为与测试覆盖审查                   | 选择通用编码模型，通常使用中等思考强度       |
| 复杂、判断成本高   | 并发与生命周期竞态、跨进程安全、数据完整性、证据冲突或复杂性能归因 | 选择推理能力更强的模型，并按需要提高思考强度 |

按任务风险选择判断能力与验证深度，按命令时长、日志长度和文件数量估计上下文与工具成本。分别选择模型与思考强度，以足够完成当前判断的配置为准。

## 派遣与升级

复杂任务、配置升级或用户要求说明时，简述模型与思考强度的选择依据。交接包含需求、范围、已有结果与待检查项，版本信息按[目标版本与交接](validation.md#目标版本与交接)补充。

优先复用一个适任的审查子代理完成相关验证与复验；独立验收者须未参与目标代码施工。目标相互独立、并行收益足以抵消额外额度与协调成本时增加代理，共享环境的检查按[风险与验收](validation.md)安排。

测试或环境失败时先依据证据定位。出现新的推理难度、明确的能力缺口，或继续尝试的预计成本高于升级时，提高模型能力或思考强度，并交接已有证据。

更换模型后复用有效结果，补充缺失或受影响的验证。完成与受阻时的处理按[风险与验收](validation.md)及[审查者规则](review.md)执行。
