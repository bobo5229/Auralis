# 同目录封面嵌入脚本

独立 Node 命令行工具，不启动 Auralis，不访问曲库数据库。使用项目已有的 `music-metadata`、`node-taglib-sharp`、`sharp` 和 `resources/audio/ffmpeg.exe`，无需新增依赖。

## 使用

在项目根目录的 PowerShell 中执行，目录由调用者明确指定：

```powershell
# 默认只读预览：递归扫描，每首歌曲只匹配直接所在目录的 cover.jpg
node scripts/embed-directory-covers.mjs --root 'D:\Sandbox\Music'

# 嵌入并验证，保留外部封面
node scripts/embed-directory-covers.mjs --root 'D:\Sandbox\Music' --apply

# 嵌入并验证；本次所有目标歌曲成功后，将外部封面移入备份
node scripts/embed-directory-covers.mjs --root 'D:\Sandbox\Music' --apply --clean
```

`--clean` 必须搭配 `--apply`。可用 `--ffmpeg '完整路径'` 指定解码验证程序。执行期间关闭 Auralis 和其他播放器、标签编辑器、同步工具，保持目标目录不被其他程序修改。

## 处理与验证规则

- 首版支持 MP3、FLAC、M4A 和同目录 `cover.jpg`，文件名大小写不敏感。其他图片不参与处理，不使用父目录封面，不缩放或重新编码图片。
- 无内嵌图片时添加正面封面。已有匹配的内嵌首图时仅复验；存在不同图片或匹配图片不是首图时拒绝清理，交由人工处理，不覆盖已有图片。
- 预检失败时不写入歌曲。已识别的其他音频格式、损坏文件、图片解码失败、链接文件、空歌曲目录都会阻止本次执行。链接目录不递归扫描，备份目录不参与扫描。无法识别为音频的未知扩展名不处理，使用前应查看预览中的歌曲清单。
- 在同目录暂存副本上写入，只修改封面。核验原有公共标签、原生标签及其数量、原有图片、音频属性与时长；使用 FFmpeg 完整解码并比较写前和写后的 SHA-256，解码错误也会拒绝替换。
- 暂存验证成功才备份原文件并安装替换文件，再从最终歌曲路径复验。安装使用同卷硬链接以避免覆盖已有路径或暴露未复制完成的文件；不支持硬链接的文件系统会失败并尝试恢复原文件，不降级成直接覆盖。
- 所有目录验证通过后，再次检查歌曲哈希、封面哈希和目录清单；只有指定 `--clean` 才清理封面。清理前逐目录再检查一次。任一写入或验证失败立即停止，尚未进入清理阶段时所有外部封面保留。
- 当前标签库对部分特殊文件布局不兼容，例如使用 `mdta` 标签的 M4A，可能在暂存验证中被拒绝；不绕过校验强行写入。

## 备份与中断恢复

每次实际处理会在扫描根目录生成 `.auralis-cover-backups/<运行 ID>/`：

```text
audio/<原相对路径>       修改前的完整歌曲文件，仅备份实际重写的歌曲
covers/<原相对路径>      清理时移入的原始 cover.jpg
journal.jsonl           操作意图、替换验证结果、清理结果或失败原因
```

备份不会自动删除。此次“清理”表示从歌曲目录移走封面，保留可恢复副本，不永久销毁图片。备份需要额外磁盘空间。

遇到后续失败时，之前成功的歌曲可能已嵌入封面，原音频备份保留；整批不是原子事务。再次执行会复验已有匹配封面，避免重复写入。清理阶段发生故障时，已移动的封面仍可从备份恢复，其余保留在原位置。

运行时根目录存在 `.auralis-cover.lock`。正常退出会解除锁；进程被强制结束或自动恢复失败会保留锁。脚本不会自动接管这种状态：先确认没有运行中的脚本，再结合日志中的 `replace-intent`、`verified-replacement`、`cover-move-intent` 等记录核对原路径与备份。原路径缺失时从对应备份复制恢复；原路径已有文件时先保留它，不直接覆盖。确认恢复完毕后才手动移除锁和遗留的 `.auralis-cover-work-*` 暂存文件。

## 隔离自测

```powershell
node scripts/embed-directory-covers.test.mjs
```

测试仅在系统临时目录创建短音频和 JPEG，不读取真实曲库，结束后清理自己创建的目录。覆盖默认预览不写文件、三格式真实写入、原音频备份、重复执行、未支持格式和不同封面阻止清理、M4A 暂存解码失败保留原文件和封面、解码程序缺失、成功清理的图片备份及日志。

这是施工自测。涉及音乐文件写回和清理策略，按项目规则，投入真实曲库前仍待独立验收。
