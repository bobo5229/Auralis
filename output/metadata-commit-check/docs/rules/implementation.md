# 施工者规则

## 职责与权限

父代理在用户授权范围内完成实现、配套修改、差异复查、验证协调和交付，并保留已有未提交修改。以用户需求和确认的验收行为确定目标，技术文档作为设计参考；发现冲突时说明影响。

施工时阅读相关源码、配置和既有测试，完成实现与格式整理，按行为风险补充或调整必要测试。检查相关差异、暂存内容和未跟踪文件，核对关联实现与需求边界，按实际状态选择 Git 检查命令。

按[风险与验收](validation.md)执行必要检查，运行前读取[环境与操作](environment.md)。用户限定仅施工时遵从限定；达到独立验收条件时按风险规则交接。

配套测试服务于当前需求。保留有效测试与断言，因需求变化调整时记录依据。自检发现问题后完成已授权修复并复验；对独立审查建议先核对证据，再处理实现或测试。

修改共享组件、状态或样式前，检查实际使用方，明确同步调整与保留行为，按授权范围调整默认行为或提供局部配置，并验证代表性使用方。

模块职责、依赖方向、共享代码与状态生命周期按[低耦合与高内聚](coupling-cohesion.md)执行。结构调整应解决当前任务中的具体问题，并保留既有行为与有效保障。

## 通用实现与开源复用

实现复杂通用算法、格式解析或重复的基础交互前，先检查现有实现、平台能力和已安装依赖；满足当前需求时直接使用。存在具体缺口时，再评估外部方案的 API、许可证、维护状态、集成成本和行为兼容性。小型业务计算按实现成本和维护负担判断。

复用通用能力时保留产品规则、状态同步和必要边界。性能改善按[性能验证](validation.md#短时动效与性能)对照实际调用路径，以运行证据形成结论。已识别的项目候选见[开源复用审计](../reviews/2026-10-04-open-source-reuse-audit.md)。

## 需求收缩与旧方案清理

冗余筛查或旧实现清理按[可复用经验索引](../lessons/README.md)选读案例；UI 清理参考[UI 冗余清理经验](../lessons/2026-10-06-ui-cleanup-lessons.md)。结合当前源码与任务目标，确认入口、共享边界和验证范围。

移除模式、选项或实现路径时，沿关联链检查 Renderer、状态与持久化、共享类型、Preload/IPC、后端、测试和文档，清理仅服务于旧方案的代码。保留仍有实际用途的兼容逻辑，并说明对应输入或存量状态。

## 交付与交接

实现后复查需求覆盖、关联影响和改动范围。按[目标版本与交接](validation.md#目标版本与交接)保持验证目标稳定、安排修复与复验；委派或跨会话时按[施工提示词写法](handoff-prompts.md)交接。处理审查问题时核对证据，完成已授权修复并复查差异；对结论有异议时提供可复查依据。

施工阶段交接、验证协调与最终交付按[完成与独立验收](validation.md#完成与独立验收)执行，报告内容按[证据与复用](validation.md#证据与复用)组织。Git 写操作按用户授权执行。
