Auralis UI 设计基准

面向 Agent 与协作者的视觉语言登记册：主题、色彩、字体、排版、几何、材质与设计判断基准。

快照时点
2026-10-27，HEAD 697afe94（refactor(styles): 唱片室衬线字体更名为 Auralis Serif SC），登记时工作区干净。
事实来源声明
本基准是提炼快照，不是第二事实来源。源码是唯一事实来源；每张表都标注了来源文件，引用数值前先读对应源文件核对当前值。本文件只回答"体系长什么样、规则是什么"，不回答"现在精确值是多少"。
覆盖范围
主题级 token、语义排版体系、曲库布局指标、外壳与播放条几何、材质参数与设计判断基准。不覆盖组件局部变量、UnoCSS 工具类与各页面私有几何——它们按下方"变更守则"追溯到所属规格文件。
维护方式
视觉体系发生方向性变化（新增主题、更换字体体系、调整 token 语义）时同步更新本文件；微调数值不需要每次更新，以源码为准即可。

§1如何使用本基准

  1. 建立设计观：先读 §2 设计原则，理解各表面表达强度的差异，再查具体数值。
  2. 定位事实来源：需要精确值时，按表内来源路径读取源文件；本文件的数值用于理解体系，不用于直接抄写。
  3. 引用规则而非数值：在代码、文档或方案中引用时，引用 token 名与来源文件，不把数值复制成新的硬编码。
  4. 发现漂移时：源码与本基准不一致时以源码为准，并按维护方式判断是否需要更新本文件。
核心约束：项目的规格与实现是单一事实来源，禁止另建平行 token 或把固定数值复制到新 CSS。改动共享 token 前必须核对实际使用方。

§2设计原则（判断基准）

以下原则提炼自 .agents/skills/auralis-ui/SKILL.md 与 docs/rules/renderer.md，是 UI 决策的最高层依据。

  1. 按表面区分表达强度。曲库、设置、菜单等操作界面以扫描效率、信息层级、稳定状态与熟悉的桌面交互为先；唱片室与全屏聆听可以用字体、材质、空间与动效表达音乐收藏的氛围。不把操作界面的克制变成全产品装饰禁令，也不把沉浸效果推广到每个菜单和表单。
  2. 密度服务于收藏规模。Auralis 面向个人大型音乐收藏；密度不足靠结构解决，不靠扩大留白掩盖结构问题。
  3. 层级靠对齐、间距、字重与语义色。让主要内容和当前操作先被看见，避免每个区域争夺注意力。
  4. 相同职责使用一致的控件语言。先复用已有组件，再决定局部变体；修改共享默认值前检查实际使用方。
  5. 装饰须有理由。圆角、阴影、边框、模糊与展示字体要有分组、深度、材质或内容表达上的理由，按效果判断而非一刀切。
  6. 排版按语义角色。字号与行高成对使用；结合真实中文、英文、数字与音乐元数据判断阅读密度；展示字体用于适合的内容角色，控件与数据保持清晰稳定。
  7. 状态不能只靠颜色区分。检查文字与图标在实际背景上的可读性、主次区分与焦点反馈；图标、标签与提示共同保证动作可理解。
  8. 动态取色联动语义前景色。封面取色应通过共享语义颜色变量联动所在画布内的主次文字、歌词、轨道、分隔线与交互反馈。
  9. 动效解释状态、保持空间连续或增强聆听氛围。持续旋转、材质和音频驱动效果需考虑暂停、切曲、退出及减弱动效设置；动效涉及相邻区域时核对变换后的实际占用范围与降级行为。
  10. 性能先测量。区分冷启动、首次进入与再次进入，定位资源、计算、布局、绘制或状态更新瓶颈；微基准与截图不能代表页面流畅度。
  11. 临时状态与持久状态分离。菜单高亮等临时状态随所属界面关闭而结束；播放状态等持久状态有唯一来源（usePlayback），不建立竞争状态来源。

§3主题体系

来源：src/renderer/app/styles/main.css（暗色 153–257，浅色 263–365，作用域保护 367–426）

  • 暗色为默认主题：:root, [data-theme='dark'] 定义暗色调色板；[data-theme='light'] 定义浅色调色板（冷瓷灰 Cool Porcelain Grey）。两主题各自声明 color-scheme。
  • 强调色独立定制：暗色与浅色强调色是两个独立偏好，由 public/splash/theme-boot.js 在首帧前从 localStorage（auralis-dark-accent / auralis-light-accent）解析并写入 --auralis-dark-accent、--auralis-light-accent、--auralis-light-accent-soft 等变量，避免首帧闪烁。默认值：暗色 #1dd55f，浅色 #585b5f。样式表中的 --auralis-dark-on-accent（默认 #121212）与 --auralis-light-on-accent（默认 #ffffff）承载强调色之上的文字色。
  • 作用域保护：主窗口外壳与全局浮层（.app-window、.library-overlay、.albums-overlay、.sidebar-overlay）在未显式选择浅色主题时整体重新声明暗色 token，防止局部主题覆盖漂移污染外壳。

§9Agent 变更守则

  1. 先查使用方：修改表面颜色或共享 token 前，核对 token 定义、主题覆盖与实际消费者（组件样式、UnoCSS 配置与变量别名），明确改共享 token 还是组件局部表面。
  2. 语义变量优先：沿用现有语义变量；不新建平行 token、不复制数值。新例外在对应组件或规格文件中说明用途。
  3. 排版走语义角色：普通界面用 --auralis-type-* / .auralis-type-*；唱片室用 --cd-type-*；字号与行高成对调整。
  4. 曲库几何只改 libraryLayoutMetrics.ts：CSS、虚拟高度与滚动定位共享同一数值。
  5. 状态与焦点：状态表达不只靠颜色；核对键盘操作、可见焦点、打开/关闭后的焦点交接与退出路径（点击外部、Esc、执行操作、切换视图）。
  6. 内容边界：核对长曲名、多行歌词、中英混排、缺失封面/元数据的展示、截断与获取完整内容路径。
  7. 动效与回退：动效涉及相邻区域时核对实际占用与降级；持续动效提供暂停与减弱动效路径（现有回退 token 示例：--auralis-playbar-reduced-transparency-bg）。
  8. 细线与缩放：结合实际渲染、坐标与 devicePixelRatio 判断非整数缩放问题，不凭代码推断。
  9. 验证按风险选择：样式布局以实际画面检查；交互走真实组件事件路径；不凭截图宣称交互或性能通过。
