# 文档入口

按用途查找文档，不按文件创建时间推断先后或完成度。需要逐篇查找时使用[完整索引](CATALOG.md)。

完整索引同时包含可跟踪的共享文档和保留在本机的研究资料。Git 检出不保证所有资料齐全；
链接目标在另一台机器上缺失，不等于资料已被删除或方案已失效。

## 如何理解状态

- PRD、TECHDOC、计划描述目标或方案，不等于已实现；交付与审查记录也只对应当时的范围和版本。
- 判断当前能力应核对源码、路由和适用测试；“待办”“下一步”和交接记录不构成继续实施授权。
- 已知的替代关系与歧义集中在[主题说明](topics/README.md)和[项目说明](projects/README.md)；未核实的状态不批量盖章。
- `history/` 表示按原批次保留的资料，不代表其中所有方案已废弃。
- 文档内旧命令或验收清单是任务背景；当前验收选择以[风险分级验收](rules/validation.md)及用户要求为准。

## 新文档放在哪里

- 根目录保留入口、索引和架构概览；阶段方案与施工提示词按项目归档。
- 可复用协作约束进入 `rules/`，并由根 `AGENTS.md` 路由；本入口不重复规则。
- 独立主题方案进入 `topics/<主题>/`；同一多阶段项目的材料放在 `projects/<项目>/`。
- 可复用经验复盘进入 `lessons/`，由相关规则按任务路由；具体证据记录仍进入 `reviews/`。
- 审查记录进入 `reviews/`，任务交接进入 `handoffs/`。
- 独立演示统一进入仓库的 [demo/](../demo/README.md)，本地草稿进入 `demo/local/`。
- `history/` 保留旧批次结构；不要把所有新文档按日期持续堆入其中。
- 新增、迁移或替代文档时更新相关入口和[完整索引](CATALOG.md)，保留有效的相互引用。
