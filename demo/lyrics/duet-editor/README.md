# 歌词互转与对唱标记 Demo

隔离的浏览器界面 + 本机 Node 服务，直接调用 Auralis 已有歌词字符串后端。仅加载本目录原创模拟歌词，不启动 Electron、不连接 SQLite、曲库、音乐文件或应用设置，不创建 IPC。没有额外安装依赖。

在项目根目录运行（Node 22.13+，复用现有 node_modules 中的 esbuild）：

```powershell
node demo/lyrics/duet-editor/start.mjs
```

手动打开 <http://127.0.0.1:4186/>，`Ctrl+C` 停止。不是可直接双击的静态 HTML。端口被占用时：

```powershell
$env:AURALIS_LYRICS_DEMO_PORT = '4187'
node demo/lyrics/duet-editor/start.mjs
```

## 操作

1. 页面自动加载 `sample.lrc`，调用真实 `convertLrcToTtml`，创建两位演唱者与共同演唱定义。不会自动猜测每句角色。
2. 勾选歌词行，点击“演唱者 1”“演唱者 2”“合唱”或“清除”。右侧预览对应左、右、居中排版；未分配保持独立状态。示例包含两句时间完全相同的歌词，可分别分配。
3. 修改姓名后点击“保存姓名”，已有分配继续保留。修改、载入和重新加载示例可撤销，最多保留 20 步，同时受文本总量限制。
4. 点击“生成 TTML”保留分唱标记；“生成 LRC”输出带毫秒逐行时间戳的歌词，显示演唱者、逐字时间等损失提示。导出不会替换当前 TTML。修改文档后旧导出结果失效，需重新生成。
5. 点击“下载”，由浏览器保存为新文件。可将输出粘贴到左侧、选择对应格式，再“载入并编辑”验证往返流程。

输入原文与编辑文档分开保存；输入框改变不会立即修改文档。刷新页面重置内存状态，无自动保存、文件覆盖、服务器上传存储或外部网络资源。

## 边界

- 本原型是静态歌词排版预览，无音频、播放计时或逐字高亮。
- 标记与转换使用真实后端，只有歌词输入为模拟数据。前端不重新实现格式解析或 XML 修改。
- 后端字符串接口仍限制最多两位个人演唱者、一个共同演唱组；不支持的文档只读预览。句内混合分唱行不可选择。
- 为避免大量 DOM，列表和预览最多显示前 300 句，全选只覆盖可见可编辑行，导出包含完整文档。输入上限沿用后端的 8 Mi 个 UTF-16 代码单元。
- 默认 TTML→LRC 使用 Apple/AMLL 绝对时间模式；此 demo 不提供父级相对时间模式切换。
- 实际 XML 标记修改可能改变空白、转义或属性顺序；导出 TTML 直接返回当前编辑原文，不再重建转换。
- 服务只监听 `127.0.0.1`，静态资源使用固定白名单；API 校验 Host、Origin、随机页面凭证和 JSON 请求，执行的能力仅为字符串处理。没有任意路径读取、文件写回或通用命令执行接口。
- 启动时将 `backend.ts` 与既有字符串后端打包到系统临时目录 `auralis-lyrics-demo-*`；正常退出清理本次目录。强制终止进程可能留下临时构建文件，其中不包含用户歌词。不会向正式应用的 `out/` 写入产物。
