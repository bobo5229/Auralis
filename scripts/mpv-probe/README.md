# mpv 隔离验证原型

此目录仅用于选型验证，不接入 Auralis 的 UI、数据库、播放队列或统计。
脚本使用 Node 内置模块，经 Windows 命名管道调用 mpv JSON IPC，没有新增 npm 依赖。
默认测试关闭静音裁剪、交叉淡化及 ReplayGain，固定 `gapless-audio=yes`。
这会保持既定输出格式，不代表混合采样率播放不重采样。

## 运行

人工连续信号的文件输出验证，以及静音的 Windows 音频控制验证：

```powershell
node scripts/mpv-probe/probe.mjs --mpv artifacts/mpv-probe/bin/mpv.exe --audio-output wasapi
```

省略 `--audio-output wasapi` 时使用 null 输出，用于排查 IPC 与输出时钟差异。
每次运行创建独立目录，输出 `report.json`、事件记录及 PCM 文件。
脚本退出成功代表控制断言执行完成，格式资格应查看报告，尤其是 AAC 额外采样。

读取真实连续音轨（当前测试入口限定 44.1kHz 双声道，避免隐式重采样）：

```powershell
node scripts/mpv-probe/real-tracks.mjs --mpv artifacts/mpv-probe/bin/mpv.exe '完整路径/第一首.m4a' '完整路径/第二首.m4a'
```

输出完整解码对照、`boundary-20s.wav` 和报告；测试前后核对原文件 SHA-256 与修改时间。

实际试听及交互控制（会发声，默认音量 20；先暂停 Auralis）：

```powershell
node scripts/mpv-probe/listen.mjs --mpv artifacts/mpv-probe/bin/mpv.exe '完整路径/第一首.m4a' '完整路径/第二首.m4a'
```

输入 `p` 暂停/恢复，`seek 320` 跳转，`next`/`prev` 切歌，`status` 查询进度，
`list` 查看队列，`add 路径` 添加，`remove 1` 删除第二项，`move 2 1` 调整顺序，`q` 退出。
这只是命令行验证工具，不是正式播放器后端。歌词同步目前只验证了可订阅进度事件，
尚未接入歌词面板。

## 本轮实测结果

合成信号由同一段连续非静音 PCM 精确切为三首，每首 132437 帧，44.1kHz 双声道。
切分点刻意不对齐 MP3/AAC 编码帧。

| 格式                  | 连续输出与逐首解码拼接 | 与原始总帧数差值 | 结论                                              |
| --------------------- | ---------------------- | ---------------- | ------------------------------------------------- |
| WAV                   | 逐字节一致             | 0                | 连续输出还与原始 PCM 完全相同                     |
| FLAC                  | 逐字节一致             | 0                | 连续输出还与原始 PCM 完全相同                     |
| MP3 / LAME 320k       | 逐字节一致             | 0                | 本样本编码填充处理正确；有损音质不与 PCM 等同     |
| AAC / FFmpeg 256k M4A | 逐字节一致             | +2049            | 每首 +683 帧，约 15.49ms；不能宣称所有 AAC 已解决 |

AAC 差异在单首输出中已经存在，不是队列切换额外引入；仍需调查容器时长、
编码填充元数据及解码链行为，不能通过音量阈值裁剪来掩盖。

Windows WASAPI 静音控制验证完成：暂停/恢复、精确跳转、音量/静音、添加/移动/移除队列、
手动前后切换、自然衔接、进度事件。
暂停时跳转到 1.25 秒，WASAPI 返回约 1.249992 秒；null 输出返回约 1.07 秒，
恢复后进度正确。因此该偏差与测试输出后端相关，本轮没有为此修改产品逻辑。

用户指定现场专辑：陈奕迅2010 Duo演唱会，第 1 首《今天等我来 (Live)》、
第 2 首《好歌献给你 (Live)》。标签确认同碟音轨 1/36、2/36。

- AAC，44.1kHz 双声道；解码帧数分别为 14639104、11535360，与音频流时长对应。
- 连续 PCM 输出等于逐首解码拼接，未插入或丢失采样。
- 交界前后 100ms RMS 约 -9.79／-12.96dBFS，均不是静音。
- WASAPI 静音运行完成自动切换，下一曲进度继续增加。
- `file-loaded` 到下一曲正进度约 247ms；这是加载/输出缓冲事件时序，不能据此认定存在声音断层。
- 原文件哈希与修改时间均保持不变。
- 真实样本报告：`artifacts/mpv-probe/real/2026-09-22T09-48-13-547Z/report.json`。
- WASAPI 控制报告：`artifacts/mpv-probe/runs/2026-09-22T09-46-37-351Z/report.json`。

## 结论与下一步

### 后续试听纠正与整张专辑检查

用户在第一组试听中听到了短空白。进一步检查确认：连续输出未额外插入采样，
但第二首自身的解码开头存在全零区，不能据此把第一轮数字输出验证说成听感无缝。
16 位输出中计数为 1986 帧；浮点解码复核为 1984 帧（44.9887ms），多出的两帧
是量化后归零的极弱声音。后续严格使用所有声道的浮点采样等于零作为判定。

整张专辑检查入口：

```powershell
node scripts/mpv-probe/album-boundaries.mjs --album '专辑目录完整路径'
```

流式解码，只保留每首前后各六秒，不写回源文件。对照版输出为 24 位 WAV；
先在浮点域只删除全零区，再统一转换原版和处理版，没有使用交叉淡化或音量阈值。

34 首实际文件、33 处相邻边界检查结果：

- 29 首开头有 1984 帧全零区，2 首有 1024 帧（23.2200ms）；其余为更长的开头。
- 29 处符合标签上的同专辑、同碟、连续音轨，且全零总长不超过试验筛选上限 100ms。
- 2 处跨碟、2 处同碟音轨标签跳号排除。文件名连续不代表音轨标签连续，未修改标签。
- 跨碟两处的全零合计约 604ms、673ms，本轮不裁剪。
- 100ms 仅用于筛选试听，尚未证明是通用的安全阈值；无法仅凭全零判断停顿是否刻意保留。
- 抽取 02→03（44.989ms）、17→18（23.220ms）、24→25（两侧合计49.342ms）三组试听。
- 所有源文件 SHA-256 与修改时间保持不变。
- 报告与试听：`artifacts/mpv-probe/boundaries/2026-09-22T10-00-34-130Z/`。

用户已确认扩大后的三组对照听感均良好，并授权正式接入。

mpv 通过本轮真实样本的数字输出连续性验证，值得作为后端候选继续推进。
本轮有用户对试听文件的听感确认，但没有声卡回环录音，PCM 文件输出不能代替所有设备的连续性保证。
也没有证明原文件在母带层面没有重复或缺失，需要连续原始参考音频才能判断。

### 播放器接入

开启现有“无缝播放”后优先使用 Main 托管的 mpv；缺少 mpv 时使用原 Web Audio 后端并记录诊断。
运行时播放错误直接报告，不静默换后端重播。UI 队列、歌词、统计仍由现有控制器负责。
Preload 只暴露曲目 ID、播放、暂停、跳转、音量及下一首预载等有限操作，不传递任意路径或 mpv 命令。
窗口重载、崩溃、关闭及应用退出会释放子进程。

“跳过边界数字静音”是默认关闭的独立选项。仅在自动预载的同专辑、同碟、已知连续编号间生效，
两侧全零合计上限 100ms，声道数和采样率必须一致。FFmpeg 流式分析 float32，保留非零采样，
mpv 通过每文件 start/end 播放范围跳过静音，源文件不变。时间仍采用原歌曲时间轴，供歌词同步使用。
无可靠标签、扫描失败、较长静音或临近曲末来不及准备时保留原音频。此规则不是 AAC 编码填充的通用修复。
扫描缓存仅存在内存，以文件路径、大小、修改时间为键，最多 32 首；不写数据库、不写旁车缓存。

开发和打包统一从 `resources/audio/` 读取 `mpv.exe` 和 `ffmpeg.exe`，不改 PATH 或全局安装。
本机已放入本轮验证的 mpv CI 二进制及现有 FFmpeg 8.0.1。目录沿用仓库忽略规则，不提交二进制。
换机器时可通过以下命令准备本地运行时，再构建；脚本不自动下载或选择其他版本：

```powershell
powershell -File scripts/mpv-probe/stage-runtime.ps1 -MpvExecutable 'mpv.exe完整路径' -FfmpegExecutable 'ffmpeg.exe完整路径'
```

`package.json` 的 extraResources 将该目录复制到安装资源中。本轮未制作或发布安装包；对外分发前须
为实际选择的构建保留对应许可证、来源及源码材料，不能将测试构建视为已经完成分发审查。

定向验证入口：`nativePlaybackService.test.ts` 在运行时存在时使用隔离合成 FLAC，检查控制操作、
自动衔接，并对 44.1/48/96kHz 的输出逐样本比较。无运行时时明确跳过该集成测试。
