# foobar2000 SDK 的 M4A 播放中写标签隔离测试

这是独立实验，未接入 Auralis。第三方 SDK、foobar2000、配置、生成的音频及 PCM 证据均放在本次创建的临时目录；不读取真实曲库，不运行安装程序。

使用官方 [SDK 2026-10-01](https://www.foobar2000.org/SDK) 和 [foobar2000 2.26.1 x64](https://www.foobar2000.org/windows)。SDK 的 `file_lock_manager` 实现由宿主提供，实际解码器、标签写入器来自宿主。实验调用真实 API，没有模拟文件锁、解码器或标签写入器，也没有以独立实现替换它们。

## 运行

需要 Windows、Python、7-Zip、MSVC v143 和 Windows SDK。本机已安装的工具足够，不需要安装额外依赖。在项目根目录执行：

```powershell
& scripts/foobar-sdk-probe/run.ps1 -MSBuild 'D:\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\amd64\MSBuild.exe'
```

脚本创建唯一临时目录，下载并解压固定版本，编译测试组件，生成八个十秒 M4A，然后启动独立 portable 宿主。仅自动确认该子进程第一次启动的外观选择框，运行结束自动退出。播放使用 Null Output，无声，不调用声卡。结果位于打印出的目录的 `results` 下；保留现场，不自动删除。

组件需要 `AURALIS_FB2K_PROBE_ROOT` 和 `ISOLATED_SYNTHETIC_ONLY` 标记才能启动测试。`samples.txt` 仅允许文件名，测试只对生成文件的 `work` 副本写入。

## 覆盖

| 编码   | 采样率   | 声道   | moov 位置 |
| ------ | -------- | ------ | --------- |
| AAC-LC | 48 kHz   | 双声道 | 前、后    |
| AAC-LC | 44.1 kHz | 单声道 | 前、后    |
| ALAC   | 48 kHz   | 双声道 | 前、后    |
| ALAC   | 96 kHz   | 双声道 | 前、后    |

每个样本验证两条路径，每条三次写入：短标题、128 KiB 标题、再缩短标题，同时修改艺术家，并重新读取确认。

1. **显式协作解码**：调用 SDK 获取读锁、真实解码；另一线程请求写锁；读端确认 `is_release_requested()`，释放解码器与锁；真实写入完成后重新获取锁、打开解码器，按已输出帧数定位并继续。比较完整 PCM 与同一宿主解码的原始对照。
2. **实际宿主播放**：通过 SDK 创建隔离播放列表并播放，用 `playback_stream_capture` 记录 PCM，在已交付音频约 2、4、6 秒时从工作线程获取写锁、调用 `input_info_writer` 写入。与未编辑播放对照及原始解码结果逐字节比较，记录 EOF、编辑事件和回调间隔。

另外解析 MP4 顶层原子，对比写入前后 `mdat` SHA-256，并检查原有 COMMENT 保留。这里没有使用 Auralis 的 M4A 写入器。

## 2026-10-13 结果

已完成两轮：第一轮分步搭建；第二轮从新临时目录通过上述脚本完整复现，包括下载、编译、首次外观选择、播放和分析。两轮每轮 48 次写入全部成功，24 次播放中编辑均收到宿主编辑事件，全部正常 EOF，无错误事件。合计 96 次写入，其中 48 次发生在实际宿主播放期间。

- 八个样本三次关闭、写入、重开后的完整 PCM，均与原始对照逐样本完全一致。
- 八个样本的实际播放捕获，共同区间均逐样本完全一致。两组捕获各自都与原始解码结果的同长度前缀完全一致；修改点之后未发现插入、跳过、重复或数值变化。
- 所有写入副本的 `mdat` 哈希不变，COMMENT 保留。大标签写入及缩小后的读取均正确。
- 首轮协作路径最大锁等待 15.36 ms、最大写入与回读总时间 54.77 ms；实际播放路径分别为 0.331 ms 和 110.75 ms。这是本机合成样本观测值，不是性能上限。
- 完整脚本复测中，协作路径对应最大值为 16.47 ms / 52.00 ms，实际播放路径为 0.354 ms / 55.25 ms，其余验证结果一致。
- 对实际播放中的 ALAC 文件进行外部独占读取探测，返回文件被其他进程占用。测试并非仅在停止播放后写入。

**尾部证据限制**：部分播放捕获在 EOF 时尾部帧数不同，首轮差异最大 13.13 ms，复测最大 17.53 ms，未编辑组也出现；共同前缀完全一致。没有把捕获回调的尾部差异解释成写标签造成的跳音，也没有据此宣称完整输出逐帧一致。原因尚未单独定位。

本次未测试 WASAPI/声卡输出及实际听感，也未覆盖 HE-AAC、DRM、损坏文件、超大文件、封面与所有未知原子、多曲衔接、下一首预加载、暂停时写入、并发写入和异常退出恢复。AAC 对照使用宿主自身的解码输出，未验证编码器 padding 与原始合成 PCM 的长度一致性。

## 对 Auralis 的意义

实验证明：foobar2000 宿主提供的文件协调、M4A 写入和准确重开定位，在本次样本上能协作工作。它支持“播放时编辑 M4A 是成熟可实现的功能”的判断。

SDK 文件锁只协调同一宿主内的参与者，不会自动让外部 mpv 释放文件或保存解码状态。宿主解码器及其重开行为也不包含在可独立使用的 SDK 中。因此不能把 SDK 链接进 Auralis，就视为已经解决 mpv 的播放恢复问题。迁移需要单独验证 mpv 对应的文件生命周期与样本连续性；本实验未改变正式播放器的可编辑格式限制。

第三方材料仅保留于临时测试目录，未将宿主二进制或 SDK 源码加入仓库。SDK 许可证已阅读；官方安装包原样下载，未重新分发解压产物。
