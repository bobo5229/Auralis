## 歌词强调效果 MVP 原型（docs/prototypes/lyrics-emphasis-demo.html）

- 产出：单文件 HTML 原型，模拟普通歌词面板 + 播放时钟 + 参数实验台，含普通 LRC（整行强调）与增强 LRC（片段强调）两条演示曲目。
- 复用基线：`parseLrc` 的 `LyricLine/LyricSegment` 模型、`useLyricLineSeek` 的点击跳转、`useTrackLyrics` 的 `currentTime` 派生、`LyricLineText` 在普通面板与全屏双端共用。
- 核心设计判断：动效是 `progress(mark, t)` 的纯函数，由 `currentTime` 逐帧求值写 `--ep-lift/--ep-scale/--ep-glow`，因此暂停冻结、跳转恢复、重播重放都不需要额外状态机。
- 数据模型：`(trackId → 歌词指纹桶 → marks)`，桶内用「时间 + 文本」锚点解析，处理歌词改写（换桶）与片段重划（锚点失效）两类变化；整行与片段标记互斥，整行优先、片段标记保留为"被覆盖"。
- 实现坑（已实测）：
  - 片段要 transform 必须 `inline-block`，而父级 `text-decoration` 不会覆盖 atomic inline 子项 → 选中线改用内联盒 `background` 渐变绘制，位置稳定且不被子级 transform 带走。
  - `hidden` 属性会被 `.toolbar{display:flex}` 覆盖，需显式 `[hidden]{display:none}`。
  - 标记变更整表重建会丢焦点/打断动效；正式实现应就地更新受影响节点（v-memo 边界）。
- 验证：无头 Chrome + CDP 写了 20 条交互断言（模式隔离、选择、撤销、试听、暂停冻结、降级、覆盖、指纹换桶、行高稳定），全部通过；临时脚本与截图已清理。
