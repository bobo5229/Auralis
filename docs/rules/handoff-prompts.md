# 施工提示词写法

适用：用户要求输出可发给其他会话或 Agent 的施工提示词。

## 写法

- 直接给可复制的提示词，面向执行者说清楚「要做成什么」和「怎么做」。
- 先写目标与可见效果，再写关键实现位置、操作和需要保留的现有行为；只交代完成任务所需的背景。
- 已确认的文件、组件和机制用准确名称指出；设计选择已明确时给出具体值或效果，不让执行者重新猜测。
- 用一句话划清实际范围，例如只改 demo、默认保持原样或某项效果不受开关控制；不要堆叠假设性禁令。
- 视觉任务写出最能判断效果的对照场景，让执行者围绕实际画面调整。

## 删减

- 删除通用的「先调研、先制定计划、全面测试、完整汇报」流程套话；只有任务确实需要时才提出对应动作。
- 不重复仓库已有的安全、编码和工具规则，不为局部改动预设新架构。
- 不用大量「不要……」解释意图；优先正面描述目标，只保留会改变结果的边界。
- 不替用户追加下一阶段需求。提示词交给执行者后，用户能直接用成果判断本轮效果。
