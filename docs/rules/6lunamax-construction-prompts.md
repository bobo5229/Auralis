# 6LunaMax 施工提示词撰写规则

为 6LunaMax 编写施工提示词时，与[通用交接规则](handoff-prompts.md)一起使用。默认采用普通模式；用户指定模型不自动要求逐步给出全部代码。任务权限、验证职责和完成条件沿用项目规则。

## 模式选择

- **普通模式**：用于一般功能、局部修复和界面调整。确定目标、范围、关键方案和必须保留的行为，让执行者完成范围内的局部实现判断。
- **严格模式**：用于机械迁移、精确复现、用户明确要求逐步执行，或确需锁定实现的任务。撰写者给出可直接执行的步骤及关键代码。

按任务需要选择并在提示词中写明模式。高风险任务需要明确关键决策和独立验收，但不要求把无关的局部细节全部写成机械步骤。

## 普通模式

交接前阅读当前源码、实际调用方及相关未提交修改，定位关键入口。历史记录用于寻找线索，方案依据以当前代码为准。

提示词说明：

- 用户能观察到的目标与完成条件。
- 允许修改的功能范围或文件、关键入口，以及已有修改的保留方式。
- 已确定的接口、产品行为和关键方案，包括影响结果的参数、兼容及错误处理要求。
- 必须保留的数据、行为和资源清理约束。
- 必要检查的责任、阶段停止点、交接对象与剩余验收安排。

局部命名、代码组织、机械引用修正，以及已授权目标所需且在约定范围内的配套修改，由执行者依据现有结构完成。提示词可以限定到具体文件；范围明确限于文件清单时，增加文件需先协调。

涉及改变已确定的接口、扩大范围、增加真实数据风险、引入新依赖或推翻关键方案时，先报告影响并协调决定。遇到他人并发修改或事实与方案冲突时，暂停受影响部分，保留已有修改；仍可推进不依赖该决定的工作。一般可逆细节不触发反复确认。

## 严格模式

撰写者先完成源码检查、方案设计、依赖选型和关键实现取舍，再按依赖顺序给出步骤。每步应明确以下内容；简短步骤可合并字段：

| 信息 | 内容 |
| --- | --- |
| 位置 | 文件路径及函数、模板节点、选择器或唯一代码片段 |
| 前提 | 当前代码形态或前置步骤 |
| 动作 | 新增、删除、替换或移动操作 |
| 内容 | 准确代码、参数，或无需设计选择的变换规则 |
| 结果 | 完成后应存在和应移除的内容 |

用符号或唯一片段定位，行号仅作辅助。锁定实现的步骤应补齐算法、结构、名称、参数、兼容策略及错误处理；新增状态机、异步控制或跨模块接口时，给出完整代码或完整分支与数据定义。依赖方案写明版本、API、集成与许可处理。

删除或替换实现时，列出实际受影响的导入、调用、绑定、状态、资源释放、测试、语言键及文档；无需把不相关的检查项加入步骤。重复机械变更可合并，但要列清目标位置和替换规则。大型任务按依赖拆成有明确起始条件与完成结果的批次。

施工者先核对起始条件。目标缺失、步骤与当前代码或他人修改冲突、需要清单外的文件或实现决策、无法满足目标或会破坏保留行为时，暂停受影响步骤并报告，等待补充方案。报告位置、实际差异、已完成内容和待决定事项。

## 写法、验证与交付

先写目标，再写动作与结果；只保留影响执行的背景。说明已确定的决定与执行者可自行判断的部分，避免用模糊措辞掩盖尚未解决的关键方案。

施工者按约定完成实现、差异复查及必要检查；用户限定仅施工时遵从限定。自检结果、阶段交接与最终交付按[风险与验收](validation.md#完成与独立验收)报告。需要独立验收时，由父代理安排未参与目标代码施工的审查子代理，自检通过不能替代独立验收。

输出载体按[通用交接规则](handoff-prompts.md)选择，不设置字符数或行数阈值。需要保存时使用 UTF-8 Markdown，默认路径为 `docs/handoffs/YYYY-MM-DD-<任务英文短名>-construction.md`，日期使用用户当前时区；用户指定载体或路径时遵从指定。同一任务修订原文档，保留无关内容；同名文档属于其他任务时使用数字后缀。

保存后复查内容，在对话中提供绝对路径 Markdown 链接及简短说明，无须重复全文。

## 提示词模板

按任务填写相关字段，省略不适用项；普通模式无需逐项展开代码。

```text
项目与规则入口：<路径>
模式：<普通 / 严格>
接收职责与停止点：<最终交付 / 阶段任务，完成后交给谁>

目标与完成条件：
<可观察的结果>

范围与关键入口：
<功能范围或文件、相关起始条件、已有修改>

已确定的关键方案：
<接口、关键参数和行为>
必须保留：
<数据、产品行为、兼容与资源清理约束>

实施：
<普通模式：关键方向及可自行判断的细节>
<严格模式：按位置、前提、动作、内容、结果列步骤>

验证与交付：
<必要检查责任、独立验收安排、结果及缺口的报告要求>
异常处理：
<本任务需要暂停协调的条件>
```

## 严格模式示例：双圈改为单圈并放大勾

下面示例展示严格模式的步骤粒度。用于实际任务前，撰写者须重新核对源码起始条件。

假定起始条件：`SaveProgressIcon.vue` 中有 `outer`、`inner`、`check` 三个路径，`segments` 数组按此顺序初始化，成功勾由 `segments[2]` 绘制。图标大小为 20 × 20 px，`viewBox` 为 `0 0 120 120`。

目标：保留一个圆形加载轨迹；成功勾横向占图标区域约 75%；按钮尺寸、成功后的 300 ms 停留、取消和销毁清理保持现有行为。

所有步骤作用于 `D:\VSCode\Auralis\src\renderer\shared\feedback\SaveProgressIcon.vue`：

1. 删除模板中 `ref="inner"` 的 `<path>` 节点，保留 `outer` 和 `check` 节点。
2. 删除脚本中的 `inner` ref 声明及整个 `spinInner()` 函数。
3. 在 `onMounted` 的路径检查中，删除 `!inner.value` 条件；在 `drawCheck` 的路径检查中做同样删除。
4. 将初始化数组 `[outer.value, inner.value, check.value]` 替换为 `[outer.value, check.value]`，保留原来的 Segment 构造方式。
5. 删除 `onMounted` 中的 `spinInner()` 调用，保留 `spinOuter()` 及减少动效分支。
6. 将 `complete()` 中的 `segments.length !== 3` 改为 `segments.length !== 2`。
7. 删除 `drawCheck` 中设置 `inner.value.style.visibility` 的语句。
8. 删除成功收尾分支中原内圈的 `segments[1].draw('100%', '100% + 0.1', 0.12, ...)` 调用，保留外圈收尾回调。
9. 将绘制勾的 `segments[2].draw(...)` 改为 `segments[1].draw(...)`；将起止参数改为 `0`、`'100%'`，保留原时长和完成回调。
10. 将 `check` 节点的 `d` 替换为 `M 15 60 L 48 93 L 105 27`，保留图标尺寸、viewBox、线宽、描绘和轻微弹入动效。
11. 按以上位置复查差异：`inner` ref、模板节点、函数、调用及可见性操作均已删除；数组有两个路径，勾使用下标 1；AbortSignal、卸载清理和后台结束兜底保持原逻辑。

这组步骤同时给定路径几何与完整描绘范围，避免施工者只放大 SVG 外框，或改大路径后仍只显示末尾 50 个长度单位。

## 发送前核对

确认目标、范围、关键决策和保留行为明确，模式与任务匹配，验证责任和阶段停止点清楚。普通模式为局部判断保留空间；严格模式检查步骤是否具备执行条件。保存文档时复查内容和链接，不额外要求固定检查轮数。
