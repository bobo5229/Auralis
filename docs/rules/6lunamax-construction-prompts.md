# 6LunaMax 施工提示词撰写规则

按[通用交接规则](handoff-prompts.md)说明目标、授权范围、保留行为与完成条件。撰写前核对当前源码、实际调用方和相关未提交修改。

## 模式选择

默认使用普通模式：确定产品行为、接口与关键方案，由执行者完成局部命名、代码组织、测试及必要配套修改。

需要精确复现、固定算法结果或保证迁移顺序时，对相关部分使用严格模式，写清锁定的决策、起始条件和验收结果。用户要求逐步执行时，按指定范围给出步骤和代码。

## 关键决策

状态机、异步控制和跨模块接口说明外部契约、关键状态转换、错误处理及清理责任。已选依赖注明版本、兼容与许可要求。高风险任务按[风险与验收](validation.md#完成与独立验收)安排独立验收。

删除或替换实现时说明受影响的调用链与保留行为，执行者完成引用、测试、语言键和文档调整。用符号或唯一片段定位，行号作辅助；大型任务按依赖分批。

执行者核对起始条件，自行适配代码位置变化和局部实现。需要改变锁定决策、扩大授权、引入新依赖、增加真实数据风险，或与他人修改冲突时，报告影响并协调，继续可独立完成的工作。文件边界按[通用交接规则](handoff-prompts.md)执行。

## 载体与简短模板

交接载体按通用规则选择。需保存时使用 UTF-8 Markdown，默认路径为 `docs/handoffs/YYYY-MM-DD-<任务英文短名>-construction.md`，日期采用用户时区。用户指定路径时遵从指定；同一任务修订原文档，同名其他任务使用数字后缀。保存后提供绝对路径 Markdown 链接。

按任务需要填写以下信息：

```text
目标与完成条件：<可观察结果>
范围与入口：<功能、关键入口、已有修改、明确的文件所有权限制>
关键决策与保留行为：<接口、参数、数据和资源生命周期>
实现：<普通模式的方向，或严格模式锁定的部分>
验证与交接：<检查责任、独立验收安排、阶段停止点与接收者>
```
