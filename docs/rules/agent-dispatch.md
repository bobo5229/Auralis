# 子代理派遣与额度

父代理以满足任务质量要求的最低预期总额度选择派遣方案，综合模型能力、思考强度、上下文长度、代理数量和返工概率。用户指定模型、思考强度或预算时遵从指定。

日常检查由施工者直接完成。达到[独立验收条件](validation.md#完成与独立验收)时必须派遣；其他专项验证在可独立完成且收益超过交接成本时再委派。创建代理的授权范围以[项目入口](../../AGENTS.md)为准。

## 模型与思考强度

派遣前判断任务的范围、推理跨度、不确定性、失败后果和所需工具能力，再从当前可用模型及其支持的思考强度中选择配置。

| 任务复杂度         | 典型任务                                                           | 配置方向                                     |
| ------------------ | ------------------------------------------------------------------ | -------------------------------------------- |
| 简单、边界明确     | 执行已确定的检查命令、汇总日志、局部引用核对                       | 优先轻量模型，使用低或默认思考强度           |
| 中等、需要关联判断 | 多文件回归、一般缺陷定位、组件行为与测试覆盖审查                   | 选择通用编码模型，通常使用中等思考强度       |
| 复杂、判断成本高   | 并发与生命周期竞态、跨进程安全、数据完整性、证据冲突或复杂性能归因 | 选择推理能力更强的模型，并按需要提高思考强度 |

任务风险用于确定所需判断能力和验证深度。检查命令的运行时长、日志长度和文件数量用于估计上下文与工具成本，不能单独决定模型档位。模型与思考强度分别选择，采用足以完成当前判断的配置。

## 派遣与升级

派遣时用一句话说明所选模型、思考强度与任务匹配的理由。交接保留需求、范围、已有结果与待检查项；版本信息按[目标版本与交接](validation.md#目标版本与交接)按需补充。

需要委派时，优先复用一个适任的审查子代理完成相关验证与复验；独立验收者须未参与目标代码施工。目标相互独立、并行收益足以抵消额外额度与协调成本时，再增加代理；共享环境的检查按[风险与验收](validation.md)安排。

测试或环境失败先依据证据定位。任务出现新的推理难度、当前配置存在明确能力缺口，或继续尝试的预计成本高于升级时，提高模型能力或思考强度，并交接已获得的证据。

更换模型后复用仍有效的结果，只补充缺失或受影响的验证。达到验收目标后结束本轮验证；受环境限制时按[审查者规则](review.md)报告缺口并清理本轮进程。
