# 子代理派遣与额度

选择足以可靠完成任务的模型与思考强度。能力相当且成本信息可用时优先较低成本配置；用户指定模型、思考强度或预算时遵从指定。

## 何时委派

日常小任务直接完成。边界清楚、可独立推进且交接收益明确的施工或专项验证可委派；授权范围按[项目入口](../../AGENTS.md)执行。达到[独立验收条件](validation.md#完成与独立验收)时，交由未参与目标代码施工的只读审查子代理验收。

施工委派明确功能责任、文件或模块所有权、接口和保留行为。子代理共享工作区，保留他人修改；父代理协调重叠修改、集成结果并承担交付责任。文件范围按[施工提示词写法](handoff-prompts.md)明确。

## 配置与升级

从当前可用模型及其支持的思考强度中，按任务难度、失败后果和工具能力选择配置：

- 边界明确的命令执行、日志汇总或局部引用核对，可使用轻量配置。
- 多文件实现、一般缺陷定位和回归审查，使用能可靠完成关联判断的编码配置。
- 并发、生命周期、信任边界和数据完整性任务，优先保证推理与验证能力。

配置升级、明确预算取舍或用户要求说明时，简述依据。失败先定位原因；确有能力缺口或新的推理难度时再升级，保留已有有效证据。

优先复用适任子代理。只有任务独立且并行收益明确时增加代理，共享缓存、构建输出和原生环境按[风险与验收](validation.md)协调。交接内容按[施工提示词写法](handoff-prompts.md)，完成和受阻处理按[风险与验收](validation.md)执行。
