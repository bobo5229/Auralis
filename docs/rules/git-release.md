# Git 与发布

适用：用户明确要求提交、推送、分支发布流程、PR、打包或发布。授权边界遵守根目录 AGENTS.md。

## 提交与推送

- 提交前检查暂存差异，只纳入本次授权的内容；其他未提交修改可以留在工作区。
  验证按 [风险分级验收](validation.md) 选择，不另设固定的全仓门禁。
- 使用中文 conventional commit，例如 `fix：修复队列焦点`、`docs：整理协作规则`。
- 推送前核对当前分支、目标远端和将要推送的提交；工作区无需清空，但不能把无关提交推送出去。
- 只有用户明确要求完整分支发布流程时，才在 `dev` 提交并推送、合并到 `master`、再推送 `master`。
  创建 PR 时写明改动和实际验证；有适用截图时附上，不虚构验收结果。

## 构建与发布

- 按 [风险分级验收](validation.md) 验证发布改动；原生依赖准备见 [环境与操作](environment.md)。
- 需要应用构建时运行 `npm.cmd run build`；需要目录包或安装包时，按目标运行 `npm.cmd run pack`
  或 `npm.cmd run dist`。`npm.cmd run pack:dir` 只打包已有构建，使用前确认构建是最新的。
- 检查实际产物；本地命令成功不代表远端 CI 或安装验证已经完成。
