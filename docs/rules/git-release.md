# Git 与发布

适用：用户明确要求提交、推送、分支发布流程、PR、打包或发布。授权边界遵守根目录 AGENTS.md。

## 提交与分支

- 提交前检查差异，只纳入授权范围；不把用户已有修改或其他任务产物一起提交。
- 使用中文 conventional commit，例如 `feat：新增专辑详情`、`fix：修复队列焦点`、
  `refactor：调整曲库刷新流程`、`chore：更新检查脚本`、`docs：整理协作规则`。
- 用户明确要求完整分支发布流程时：在 `dev` 提交并推送，合并到 `master`，再推送 `master`。
  执行前确认分支与工作区状态，不把这条流程当作自行切分支或提交脏文件的授权。
- PR 包含简短摘要、实际验证命令；UI 改动附适用截图，原生模块/数据库改动说明影响。
  无法提供截图时说明原因，不虚构验收材料。

## 构建与打包

- 发布按 [风险分级验收](validation.md) 的 D 级验证；原生依赖准备见 [环境与操作](environment.md)。
- `npm.cmd run build`：应用构建，包含当前配置的类型检查、语言生成/校验与产物预算检查。
- `npm.cmd run pack`：构建后生成目录包；`npm.cmd run pack:dir` 只打包已有构建，使用前确认其最新。
- `npm.cmd run dist`：按当前脚本构建并生成安装包/便携包，具体目标以 `package.json` 为准。
- 按交付目标检查实际生成的产物；本地命令成功不代表远端 CI、安装验证或发布已经完成。

这里的命令只用于被授权的发布任务，不是日常小改动的验收步骤。
