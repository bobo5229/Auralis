# 审查者规则

## 独立检查

审查者按任务范围保持只读，根据风险选择源码复查、定向测试及必要的运行、视觉和性能验证。父代理可以直接完成普通审查与诊断；独立验收须由未参与目标代码施工的只读审查子代理负责，触发条件按[风险与验收](validation.md)判断。

从用户需求和已确认行为独立推导检查项，再核对当前源码、测试与施工报告。施工报告是证据来源，不能替代验收标准。检查遗漏边界、错误假设、回归影响，以及模拟是否绕过待验证逻辑。

审查期间保持产品代码、配置、既有测试和规则文件只读。允许运行必要检查，以及在临时、隔离位置编写验收用例；预期产物按[环境与操作](environment.md)管理，保护真实曲库和用户偏好。运行未知脚本前先核对副作用。

子代理保留验收目标和既有断言，持久化测试与修复建议交给父代理施工。提交、推送和其他 Git 写操作由父代理按用户授权处理。

版本定位、开跑前与回报前的核对，以及相关并发修改后的证据处理，按[目标版本与交接](validation.md#目标版本与交接)执行。

## 验证与结论

审查冗余或旧实现清理时，按[可复用经验索引](../lessons/README.md)选读案例，核对当前入口、保留用途和删除边界；历史清理结论不能替代本次证据。

遵循[风险与验收](validation.md)，复用有效证据，补充缺失场景和必要复验。文件占用、原生运行、性能和视觉结论使用相应运行证据；源码推断、模拟测试与真实运行分别报告。

问题记录包含位置、触发条件、预期与实际行为、影响和证据。区分已复现缺陷、源码可证明的问题与待验证风险；不能把猜测作为已确认故障。

结论使用“通过”“发现问题”或“证据不足”，说明检查范围、实际命令或复查步骤、结果和重要未验证项；版本证据按[目标版本与交接](validation.md#目标版本与交接)记录。“通过”对应已声明范围，父代理据此核对最终交付。

环境受阻时围绕当前现象做有界排查；仍无法运行则报告验证缺口，并清理本轮启动的服务与进程。后续修复与复验按[目标版本与交接](validation.md#目标版本与交接)执行。
