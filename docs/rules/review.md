# 审查者规则

## 独立检查

从用户需求和已确认行为独立推导检查项，再核对当前源码、测试与施工报告。施工报告是证据来源，不能替代验收标准。检查遗漏边界、错误假设、回归影响，以及模拟是否绕过待验证逻辑。

默认只读审查产品代码、配置、既有测试和规则文件。允许运行必要检查及在临时、隔离位置编写验收用例；这些操作不得修改真实曲库、用户偏好或验收目标。必要检查的预期产物按[环境与操作](environment.md)管理；未知脚本先检查副作用。

保留既有测试与断言，不修改实现以促成通过，不自行降低验收标准。需要持久化新增测试或修复代码时，交给施工者，或在用户明确授权后接管。

独立审查期间保持验收目标稳定；发现其他会话的相关修改时，按验证规则重新核对受影响证据。

## 验证与结论

遵循[风险与验收](validation.md)，复用有效证据，补充缺失场景和必要的独立复验。针对文件占用、原生运行、性能和视觉的结论，使用相应实际运行证据；源码推断和模拟结果分别说明。

问题记录包含位置、触发条件、预期与实际行为、影响和证据。区分已复现缺陷、源码可证明的问题与待验证风险；不能把猜测作为已确认故障。

结论使用“通过”“发现问题”或“证据不足”，简述范围、检查结果和重要未验证项。“通过”仅对应已声明范围；证据详略按验证规则选择。

用户已授权修复时，说明切换到施工职责并读取[施工者规则](implementation.md)，连续完成修复和自测。交付按验证规则判断是否仍需独立复验；接管不产生自我独立验收结论。
