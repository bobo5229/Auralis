# 低耦合与高内聚

让业务变化集中在负责该行为的模块内，让模块通过明确的数据和操作协作。按当前需求、实际调用方、依赖方向和状态归属划分职责。

## 依赖方向

- 应用外壳、路由和 IPC 装配层连接模块与转交请求；业务决策、数据访问和独立交互流程由对应模块承担。
- Renderer 的 `app` 组装 `features` 与 `shared`；功能模块和共享模块不得反向依赖应用外壳。功能间通过明确契约协作，各自维护内部状态、界面和持久化实现。
- 数据访问层维护查询、写入和持久化约束，不反向依赖扫描、页面或播放编排。播放决策核心依赖领域规则和输入数据。
- 调整依赖时检查循环引用，包括类型、重导出和样式。共同能力放到双方都能依赖的位置，双向配合由上层协调。
- 跨进程能力按[架构与 IPC](architecture.md)暴露。

## 按职责组织代码

维护同一规则、状态或资源生命周期的代码放在一起。拆分针对具体的职责混杂、依赖越界、重复规则或生命周期问题；职责一致的长代码可以保留。

拆分时一并迁移逻辑、内部状态和清理责任，调用方负责组合。优先直接调用；需要隔离实现或缩小依赖时，传入所需数据、回调或窄接口。抽象应有当前需求或实际使用方支撑。

## 共享代码的位置与语义

- 同一业务规则复用同一实现与契约。合并前核对输入、输出、顺序、大小写、空白及缺省值语义；有意不同的行为保留各自契约。
- 跨进程纯类型、契约与领域规则放在 `src/shared`；Renderer 通用组件、交互工具和样式放在 `src/renderer/shared`；单功能代码留在功能内。
- 共享模块不得依赖消费它的功能内部实现。主题、显示与交互差异通过参数传入，功能特有的业务决策由功能模块负责。
- 移动共享组件或样式时检查实际使用方，同步引用并保留样式作用域、加载顺序、资源路径和构建扫描行为。

## 状态、操作与资源归属

每项业务状态由一个模块维护，对外提供只读视图和修改操作，包括对象与数组的更新。展示值从业务状态派生，可使用已有响应式能力。负责操作的模块统一触发副作用。跨模块或跨进程同步确需通知时，再发布变更并按需订阅；持久化变更通知在写入成功后发送。

资源所属模块管理定时器、动画、监听、订阅和异步请求的创建、失效与清理；组合层协调跨模块清理顺序。迁移时保留取消、过期结果丢弃、会话校验、焦点交接、缓存有效范围及离页后的回调保护。

## 重构与必要验证

重构保持已支持的行为与契约，包括播放队列与匹配、完整数据与顺序、错误反馈、交互优先级、转场和资源释放时序。安全、数据完整性、恢复、兼容与无障碍保障随责任迁移，查清用途后再决定保留、收窄或删除。

按[风险与验收](validation.md)验证受影响的行为与依赖边界，交付说明职责变化和行为保持情况。
