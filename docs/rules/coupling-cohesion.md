# 低耦合与高内聚

新增、修改和重构代码时遵守本规则：让业务变化集中在负责该行为的模块内，让模块通过明确的数据和操作协作。以职责边界、依赖方向和状态归属判断设计质量。

根据当前需求、实际调用方和已有保障确定边界，施工范围限于本次授权涉及的实现及必要配套。

## 依赖方向

- 应用外壳、路由和 IPC 装配层负责连接模块与转交请求；业务决策、数据访问和独立交互流程由对应模块承担。组合层通过各模块的操作接口协调流程。
- Renderer 的 `app` 组装 `features` 与 `shared`；功能模块和共享模块不得反向依赖应用外壳。功能间通过明确的数据和操作契约协作，避免读取对方私有状态或引用其内部界面、持久化实现。
- 数据访问层负责查询、写入和持久化约束，不反向依赖扫描、页面或播放编排的内部实现。播放决策核心依赖领域规则和输入数据，与具体页面、曲库展示和设置界面解耦。
- 新增或调整依赖时检查循环引用，覆盖类型、重导出和样式引用。将共同规则或底层能力放到双方都能依赖的位置，由上层协调需要双向配合的流程。通过调整职责与依赖方向消除循环。
- 跨进程访问继续遵守[架构与 IPC](architecture.md)的类型化接口与信任边界。

## 按职责组织代码

将维护同一规则、状态或资源生命周期的代码放在一起，按实际变化原因划分模块。数据加载、播放队列决策、菜单交互和场景渲染各有独立输入、状态与清理责任时，应分别组织和验证。

拆分时，将逻辑、内部状态和清理责任一并交给新模块，原调用方主要负责组合。每组临时状态由所属模块维护。

优先复用现有实现、平台能力和已安装依赖。直接函数调用能清楚表达关系时保持直接调用；需要隔离具体实现或缩小依赖范围时，传入所需数据、回调或窄接口。接口只暴露当前责任所需的数据和操作。

拆分或增加间接层须解决具体的职责混杂、依赖越界、重复规则或生命周期问题。职责一致的长代码可以保留；服务层、事件总线、工厂或转发包装等抽象须有当前需求或实际使用方支撑。

## 共享代码的位置与语义

- 多个模块使用同一业务规则时，复用同一实现与契约。合并前核对输入、输出、顺序、大小写、空白及缺省值语义；有意保留的不同行为继续遵循各自契约。
- 跨进程使用的纯类型、契约与领域规则放在 `src/shared`；Renderer 通用组件、交互工具和样式放在 `src/renderer/shared`。仅服务单个功能的代码留在该功能内。
- 共享模块不得依赖消费它的功能内部实现。主题、显示策略和交互差异由调用方通过明确参数提供，功能特有的业务决策留在所属功能内。
- 移动共享组件或样式时检查实际使用方，同步调整引用并保留样式作用域、加载顺序、资源路径和构建扫描行为。

## 状态、操作与资源归属

每项业务状态由一个模块维护。共享状态对外提供只读视图，调用方通过明确的操作接口修改状态，包括其中的对象和数组。展示派生值按需计算，保持业务状态的单一来源。

负责完成操作的模块统一触发副作用。写入成功后发布数据变更通知，调用方通过既有订阅更新展示。

由所属模块管理定时器、动画、监听、订阅和异步请求的创建、失效与清理，组合层协调跨模块的清理顺序。拆分时保留取消、过期结果丢弃、会话校验、焦点交接、共享缓存的有效范围，以及离页后对失效状态的回调保护。

## 重构与必要验证

结构重构应保持已支持行为与契约，包括播放队列与匹配规则、完整数据与顺序、错误反馈、交互优先级、转场和资源释放时序。安全校验、数据完整性、恢复、兼容性和无障碍保障应随责任迁移；先查清作用再决定保留、收窄或删除。

按[风险与验收](validation.md)选择验证范围，优先复用现有依赖守卫和仍适用的测试证据。新增断言验证实际边界、状态变化或外部结果。界面与交互检查覆盖真实组件和事件路径，报告中区分隔离验证与完整应用验收。

当前责任已完成、必要验证通过且范围内无已知阻塞时，结束施工。交付说明职责划分、行为保持情况和验证范围。普通实现选择按项目既有流程直接推进。
