# 风险与验收

父代理负责选择必要验证、处理问题、核对最终代码并交付。施工者可直接执行测试、类型检查、语言键检查、Lint、格式检查、构建及必要的应用运行、视觉和性能检查。独立验收由未参与目标代码施工的只读审查子代理执行。

按失败后果、可恢复性和人工发现难度选择最小充分验证，达到验收目标后结束。具体检查按本次行为影响确定：

| 任务类型                         | 默认流程                                                     |
| -------------------------------- | ------------------------------------------------------------ |
| 文档、文案等低风险修改           | 实施 → 差异复查 → 交付                                       |
| 普通功能、局部缺陷修复           | 实施 → 必要检查 → 交付；发现问题时先修复并复验受影响范围     |
| 高风险任务或用户明确要求独立验收 | 实施及必要自检 → 独立验收 → 交付；发现问题时先修复并独立复验 |

布局与交互改动按下文选择实际画面或组件行为检查；涉及共享行为、数据、安全边界、原生依赖或发布风险时，按影响补充验证。独立验收条件见[完成与独立验收](#完成与独立验收)。

选择检查命令前，核对 package.json 中的脚本调用关系及 pre/post 钩子，复用组合脚本已通过的检查。共享缓存、构建输出或原生环境的检查串行执行，独立检查可并行。普通检查由施工者完成；专项验证有明确委派收益时，按[子代理派遣与额度](agent-dispatch.md)安排。

## 目标版本与交接

同一会话、同一工作区中的普通验证，利用当前会话与工具结果定位相关改动、复用已有结果并确定待检查项。跨会话、存在实际并发修改、高风险验收、发布或准备长期复用证据时，用基准提交号与相关差异定位代码状态，仍难准确标识时补充内容哈希。未提交内容须通过相关差异定位，文件数量不作为生成哈希的条件。

检查期间保持目标代码及验证依赖稳定。委派验收时，冻结目标与相关依赖至本轮验收结束；子代理在开跑前和回报前核对目标变化，父代理收到报告后复查相关工作区差异、暂存区及未跟踪文件。发生变化时复验受影响范围，其余有效证据继续复用。

修复与复验串行进行。自检发现问题后，施工者完成已授权修复并复验。独立验收发现问题后，子代理报告证据，由父代理核对、修复后交其复验。优先复用同一适任审查子代理，保留需求与失败证据的上下文。

## 缺陷回归与界面证据

测试断言需求行为与外部结果，模拟外部依赖时保留待验证逻辑，按风险选择有价值的回归用例。测试失败先定位原因；因需求变化调整断言时记录依据，按角色职责交接修改。不得通过跳过测试、删除有效断言或替换关键逻辑制造通过结果。

修复缺陷时，优先复现用户报告的操作路径，验证修复后的外部结果，并按风险补查相邻边界。以行为和边界覆盖判断验证质量。

菜单显示、隐藏和交互问题检查真实组件的渲染结果与事件路径，保留待验证的组件逻辑；涉及动态菜单时，补查受影响的键盘导航。布局、文字裁切、细线或吸顶问题使用实际渲染画面，必要时测量坐标、尺寸与缩放条件。状态与几何计算测试可提供补充证据。

隔离运行验证须说明保留的真实组件或模块、模拟的外部依赖及覆盖范围，并明确结果属于组件运行验证还是完整应用验收。

## 原型与音频效果

技术能力不确定、正式集成成本高，或需比较明显不同的方案时，用小型可运行原型验证核心差异。已有组件的颜色、间距、布局和动效调整直接在真实界面中迭代、检查。比较时保持关键条件一致；交付原型时提供启动方式，并确认本次目标所需的素材加载、播放出声和交互反馈。

音乐驱动的视觉效果分别检查算法或时序正确性与实际听感。按效果风险选择代表性曲目或片段，并验证相关暂停、跳转和切曲场景；记录曲目之间的表现差异及用户试听反馈，作为方案选择的依据。

## 短时动效与性能

诊断进入或切换动效的卡顿时，先区分冷启动、首次进入和再次进入，测量出现问题的阶段，再按发现的瓶颈补充对照。结合单帧耗时、长任务及相关资源准备、布局和绘制开销判断原因。

算法微基准与页面流畅度分别记录测量范围。底层实现替换的性能结论使用实际调用路径对照，页面体验使用实际运行证据，并记录影响比较的输入和环境。

## 完成与独立验收

委派或跨会话交接时，明确接收者承担最终交付还是阶段任务。阶段执行者按约定完成实现、差异复查和必要检查，向父代理报告结果与待验证项；“仅施工”阶段完成必要自检，父代理承担剩余验证与最终交付；用户明确禁止检查时遵从限定。新会话接任父代理时承接同样职责；创建新会话或委派施工子代理仍须取得用户授权。

仅需差异复查的任务，复查后即可交付，并说明未运行测试。普通任务完成必要检查、处理发现的问题后交付。阶段交接与最终交付均按实际检查结果报告，明确尚未执行的检查。

用户明确要求独立验收，或改动可能造成难以恢复的数据损失、安全越界、难以通过局部检查发现的关键行为回归时，必须独立验收。典型情形包括改变数据库迁移、音乐文件写回或删除策略、IPC 信任与权限边界，以及复杂播放并发或窗口生命周期行为。文案、样式和文档修改同样按实际行为影响判断风险。

达到独立验收条件时，说明待验证行为及关联影响，交由未参与目标代码施工的只读审查子代理验收。子代理按需求独立推导检查项；父代理完成修复后再交其复验。结果返回前标记“待独立验收”或“待独立复验”，必需的独立验收通过后才能完成交付。

父代理核对需求覆盖、失败与跳过项、验证缺口及报告对应的最终版本，形成交付结论，注明验证来源与范围。报告本次相关检查的结果及影响交付结论的未验证项；测试、运行、视觉和性能结论与实际证据对应。

涉及跨模块影响、影响范围难以确定或明确的发布要求时，按需要安排全量回归，说明原因与负责阶段。同一目标已有有效结果时，其他阶段按风险选择独立抽查或补充验证。

## 证据与复用

交付或阶段交接说明改动、实际检查与结果、重要未验证项；运行检查时记录命令或复现步骤及退出结果，并区分自检与独立验收来源。父代理核对证据对应的最终代码并承担交付责任，报告详略按任务风险确定。

跨会话复用证据、高风险交接或发布时，补充覆盖范围及影响结果的环境信息，按[目标版本与交接](#目标版本与交接)记录代码状态。优先使用交付消息；需持续修订、复用或跨会话传递完整方案时，再保存独立文档。

相关代码、测试、配置、依赖和运行环境仍适用时，复用已有结果，只核对影响当前结论的部分。适用性不明、相关内容变化、证据缺失或存疑、新增风险或场景，以及关键行为需独立复现时，补做对应检查并说明原因，其余有效证据继续复用。

模拟测试验证受控条件下的逻辑，真实工具运行验证集成行为，画面检查验证视觉效果；结论应与证据类型一致。验收者可阅读实现与现有测试，并按需求独立判断。
