# 轻量风险验收

适用：修改后的本地验收与发布验证。只读探索、解释和方案讨论不要求运行应用检查。

Auralis 是单人开发、仅开发者本人使用的个人项目。验收以避免个人数据损坏、应用无法启动和
核心功能明显回归为目标，选择足以覆盖最终状态主要风险的最小验证集合，达到目标后停止。

## 风险分级

| 等级   | 典型改动                                                                       | 默认验证                                                                     |
| ------ | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 轻微   | 文档、文案、局部 CSS、颜色、间距、圆角、动画和直接可见的布局调整               | 检查本次差异；方便运行时手动查看受影响区域，否则注明未视觉验证               |
| 常规   | Renderer 局部行为、路由、普通业务逻辑、共享 composable、可恢复的窗口行为       | 从定向测试、`typecheck`、手动操作中选择能覆盖主要风险的检查                  |
| 高风险 | 数据库迁移、音频标签写回、文件删除或移动、扫描器、IPC 安全边界、原生依赖、发布 | 使用隔离数据验证关键正常与失败路径；按实际影响增加测试、构建、启动或产物检查 |

- 按失败后果、可恢复性和人工发现难度分级；文件数量、共享组件或 Electron 本身不触发升级。
  影响真实音乐文件、数据库或不可逆状态的改动按高风险处理。
- 自行选择等级，扩大验证时说明具体风险，无需另行征求等级或撰写验收计划。
- 对直接可见、容易复现且可立即回退、不损坏数据的 UI 问题，开发者实际使用确认可以替代
  自动化运行时验收、截图和 Electron smoke test。
- 视觉检查只覆盖受影响的页面、状态和断点；共享规则传播到多个使用方时抽查相关界面。
  没有方便的 GUI 环境时注明“未进行视觉验证”，无需搭建额外截图平台。

## 按需命令

以下命令都是按需入口，不是顺序执行的清单。脚本定义以 `package.json` 为准。

| 用途                     | 命令                                                       |
| ------------------------ | ---------------------------------------------------------- |
| 定向普通测试             | `npm.cmd run test:unit -- <实际测试文件或路径>`            |
| 普通测试集合             | `npm.cmd run test:unit`                                    |
| Electron ABI 原生测试    | `npm.cmd run test:native`                                  |
| 静态视觉作用域检查       | `npm.cmd run test:library-scope`                           |
| 类型契约检查             | `npm.cmd run typecheck`                                    |
| 定向 lint                | `npm.cmd exec -- eslint --max-warnings 0 <实际文件>`       |
| 定向格式检查             | `npm.cmd exec -- prettier --check <实际文件>`              |
| 全仓格式检查             | `npm.cmd run format:check`                                 |
| 完整测试                 | `npm.cmd test`（包含普通、native 和静态视觉作用域检查）    |
| 全仓 lint                | `npm.cmd run lint`                                         |
| 构建                     | `npm.cmd run build`（含类型检查及当前 pre/postbuild 步骤） |
| 已有构建的 Electron 冒烟 | `npm.cmd run smoke:electron`                               |

- 修改已有受测逻辑时优先运行现有定向测试；仅为容易复发、人工难以验证或失败影响较大的逻辑
  新增测试。数据测试使用隔离的临时数据，不能修改用户真实曲库或音乐文件。
- `typecheck` 用于类型契约、公共接口、跨模块调用或较广泛的代码改动；lint 和格式检查按需定向运行。
- build 用于入口、Preload、IPC 接线、构建配置、依赖或生产构建问题。成功构建已覆盖同一状态的
  类型检查，无需重复单独运行 `typecheck`。
- Electron smoke test 用于启动、窗口创建、Preload、安全策略或正式构建接线等运行时风险；
  能方便地人工确认时可采用人工验收，普通布局和样式改动不默认运行。
- 完整测试、全仓 lint、全仓格式检查、打包和产物验证用于稳定版本、发布、高风险数据/依赖改动，
  或只能由对应检查发现的具体故障，仍按实际风险选择。

## 最终状态与交付

- 结束修改前检查最终差异并完成适用验证。已有自动检查或用户确认仍覆盖最终状态时直接复用；
  后续改动使其失效时，只补查受影响部分。
- 提交或推送沿用相同的风险分级，不额外触发全仓门禁；提交前检查将要提交的差异。
- TECHDOC、PRD、历史记录和测试矩阵作为参考；只有用户明确要求按其施工或执行指定矩阵时，
  才将相应验收项纳入当前范围。
- GitHub CI 与本地日常验收独立，无需在本地重复整套 CI；本规则不授权修改、跳过或禁用 CI。
- 无关的历史失败或环境限制单独说明，不默认接手修复。交付简述实际修改、已做检查、未运行项和
  重要剩余风险；静态检查不能表述为运行或视觉验收通过。
- 低风险未验证项不阻止个人开发继续进行；涉及真实数据损坏、应用无法启动或不可逆操作的关键
  风险未确认时，不宣称高风险修改已经完成。
