# 风险分级验收

适用：修改后的本地验收与发布验证。只读探索、解释和方案讨论不要求运行应用检查。

验收用于降低本次改动的实际风险，不用于完成固定流程。
默认采用最低适用等级，完成最小充分验证后结束；升级必须有具体风险理由。

## 选择等级

| 等级                | 典型改动                                            | 默认验证                                                                                                        |
| ------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| A：文档或纯表现     | 文档、文案、局部像素/颜色/间距/圆角                 | 检查差异；文档检查格式与受影响链接，视觉检查受影响区域。不默认运行单测、全仓 lint、类型检查或构建               |
| B：局部行为         | 单按钮禁用、菜单开关、独立纯函数、局部筛选          | 验证正常路径与本次新增边界，有对应测试则定向运行；新增逻辑按需补测，必要时定向 lint                             |
| C：共享逻辑或契约   | 共享播放状态、公共组件行为、IPC、跨模块接口         | 检查受影响调用方并运行相关模块测试；类型契约变更运行 typecheck；涉及构建产物的入口/preload/IPC 接线时增加 build |
| D：系统性或数据风险 | 迁移/恢复、原生依赖或构建系统变更、大范围重构、发布 | 完整测试与必要构建；数据变更检查失败/恢复路径，打包变更检查对应产物                                             |

- 按影响范围和失败后果分级，不按文件后缀、行数或“改了代码”统一分级。
- 局部 CSS 通常是 A；影响全部 owner 的全局 token 或 virtualizer 几何要按实际传播范围升级。
- 局部 TypeScript 改动不自动要求全量回归；一行迁移 SQL 也不能因此视为低风险。
- 每次任务不必征求用户选择等级，也不必撰写验收计划；有升级理由时用一句话说明即可。
- 不为满足更高等级的流程而扩大实现，不为局部按钮需求顺手重构播放引擎。

## 视觉检查的范围

- 只检查受影响 owner，以及被改动实际覆盖的状态。按钮检查默认/hover/active/disabled 中相关项；
  不把每次像素调整扩大为全应用巡检。
- 只有共享风格规则受影响时才覆盖 modern/manuscript；只有主题逻辑受影响且实际提供相应模式时
  才覆盖该主题。当前 dark-only 不要求人为启用 light 验收。
- 只有布局受影响时才检查相关断点；主窗口布局涉及 `xl` 时检查其两侧。
- 根据改动选取加载、错误、空状态、缺失封面、长文本、搜索、选择、队列、菜单、overlay、焦点等场景，
  不是全部必选。
- 改风格切换/效果生命周期时，检查重复切换、停止、清理与恢复；改 Library 视图/几何时，
  检查相关 flat/cover 和虚拟滚动；改 Albums 视图时，检查相关 grid/perspective。
- 明确排除的 owner 通过作用域/调用关系判断是否会被影响；没有传播路径就不要求逐个启动检查。
- 已有可用运行环境时直接查看相关区域；不要为 1px 或单色调整搭建截图平台、安装浏览器依赖
  或执行全套构建。没有可用 GUI 时如实报告视觉未验证，不用单测代替视觉结论。

## 测试与命令选择

以下是按需入口，不是顺序执行清单。脚本定义以 `package.json` 为准。

| 用途                     | 命令                                                       |
| ------------------------ | ---------------------------------------------------------- |
| 定向普通测试             | `npm.cmd run test:unit -- <实际测试文件或路径>`            |
| 普通测试集合             | `npm.cmd run test:unit`                                    |
| Electron ABI 原生测试    | `npm.cmd run test:native`                                  |
| 静态视觉作用域检查       | `npm.cmd run test:library-scope`                           |
| 类型契约检查             | `npm.cmd run typecheck`                                    |
| 定向 lint                | `npm.cmd exec -- eslint --max-warnings 0 <实际文件>`       |
| 定向格式检查             | `npm.cmd exec -- prettier --check <实际文件>`              |
| 完整测试                 | `npm.cmd test`（包含普通、native 和静态视觉作用域检查）    |
| 全仓 lint                | `npm.cmd run lint`                                         |
| 构建                     | `npm.cmd run build`（含类型检查及当前 pre/postbuild 步骤） |
| 已有构建的 Electron 冒烟 | `npm.cmd run smoke:electron`                               |

- 测试与被测模块相邻，普通测试使用 `*.test.ts`；原生测试使用 `*.native.test.ts`，在匹配的
  Electron ABI 下运行。数据测试使用隔离的临时数据，不修改用户真实曲库。
- 可独立测试的状态、索引、搜索、几何逻辑可提取测试，但不为像素值或现有测试已覆盖的行为
  创建额外测试框架、重复用例或大量源码字符串断言。
- 使用仓库实际支持的测试筛选方式，不能声称跑了工具并不支持的“定向 native 测试”。
- D 级或用户明确要求完整检查时再运行全量；不要每轮编辑都重跑。

## 去重、失败与停止条件

- 已成功构建且覆盖当前改动，不重复 typecheck；已运行完整测试，不重复其子检查。
- 同一结果仍覆盖当前差异时复用，不为交付措辞重复执行。后续只复跑被新改动影响的检查。
- 与本次无关的历史失败或环境限制单独说明，不默认接手修复。若本次风险无法确认，明确保留
  未验证项，不把失败或缺失结果说成通过。
- A/B 级达到对应验证目标后停止，不自动追加打包、性能基准或完整回归。
- 完整 CI/合并门禁与本地小改动验收分开；本规则不授权修改、跳过或禁用已有 CI 门禁。
- 最终简述改动、实际检查、剩余风险。小改动无需长报告；用户明确要求的验收材料按要求提供。
