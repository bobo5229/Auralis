# 风险与验收

按失败后果、可恢复性和人工发现难度，选择覆盖最终状态主要风险的最小充分验证；达到目标后停止，不因文件数量或固定清单机械扩大范围。

文档或局部可见改动通常检查相关差异；共享行为、数据、安全边界、原生依赖或发布风险需要时，再增加定向测试、类型检查、构建或运行验证。交付时说明实际运行和未运行的检查，并区分静态检查与运行时、视觉验收。

## 完成与独立验收

普通任务由同一会话完成实现、必要自测和差异复查后交付，说明“已完成”及实际验证结果，无需另开审查会话。关键验证未完成时说明缺口，不宣称已验证通过。

用户明确要求独立验收，或改动可能造成难以恢复的数据损失、安全越界、难以通过局部检查发现的关键行为回归时，需要独立验收。典型情形包括改变数据库迁移、音乐文件写回或删除策略、IPC 信任与权限边界，以及复杂播放并发或窗口生命周期行为。按实际行为影响判断；这些模块中的文案、样式或文档修改不自动升级。

需要独立验收时，施工完成自测后标记“实现完成，待独立验收”，提供交接信息，由用户安排审查。审查者独立推导检查项并补充遗漏场景，不默认重复全部自测。自己的修复只构成自测，仍需复验的部分标记“待独立复验”。

全量回归用于跨模块影响、影响范围难以确定或明确的发布要求。需要时说明原因并指定负责阶段；同一目标已有有效结果时，另一阶段按风险选择独立抽查或补充验证。

## 证据与复用

日常交付简要记录改动、检查命令或复现步骤、结果和重要未验证项；无需固定报告模板、内容指纹或完整环境清单。

跨会话复用证据、高风险交接或发布时，再补充覆盖范围、可定位的代码状态和影响结果的环境信息。代码状态可用基准 commit 加相关文件差异，或相关内容指纹记录；未提交工作区不能只用 commit 判断一致。优先写在交付消息中，复杂交接再使用独立文档。

已有结果在相关代码、测试、配置、依赖和运行环境仍适用时可以复用；仅核对影响当前结论的部分。无法确认适用、发生相关变更、证据缺失或可疑、新增风险或场景、关键行为需要独立复现时，补做受影响检查并简述原因；有效的其他证据继续复用。

模拟测试用于控制条件与检查逻辑，真实工具运行用于验证集成行为，画面检查用于验证视觉效果；三类证据不能互相冒充。验收者可访问实现与现有测试，独立性来自按需求自行判断。
