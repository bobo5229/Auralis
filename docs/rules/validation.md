# 风险与验收

父代理负责选择必要验证、处理发现的问题、核对最终代码并交付。施工者可直接执行测试、类型检查、语言键检查、Lint、格式检查、构建及必要的应用运行、视觉和性能检查；独立验收由未参与目标代码施工的只读审查子代理执行。

按失败后果、可恢复性和人工发现难度选择最小充分验证，达到目标后停止。默认流程如下，具体检查按本次行为影响确定：

| 任务类型 | 默认流程 |
| --- | --- |
| 文档、文案等低风险修改 | 实施 → 差异复查 → 交付 |
| 普通功能、局部缺陷修复 | 实施 → 必要检查 → 交付；发现问题时先修复并复验受影响范围 |
| 高风险任务或用户明确要求独立验收 | 实施及必要自检 → 独立验收 → 交付；发现问题时先修复并独立复验 |

布局与交互改动按下文选择实际画面或组件行为检查；共享行为、数据、安全边界、原生依赖或发布风险需要时，增加相应验证。高风险与独立验收条件见[完成与独立验收](#完成与独立验收)，自检通过不能替代必需的独立验收。

选择检查命令前，核对 package.json 中的脚本调用关系及 pre/post 钩子，复用组合脚本已覆盖且通过的检查。共享缓存、构建输出或原生环境的检查串行执行；独立检查可并行。普通检查无需单独派遣代理；可独立完成且有明确收益的专项验证可按[子代理派遣与额度](agent-dispatch.md)委派。

## 目标版本与交接

同一会话、同一工作区中的普通验证，记录目标文件、当前相关差异、已有结果和待检查项即可。跨会话、存在实际并发修改、高风险验收、发布或准备长期复用证据时，补充可定位的代码状态：可用基准提交号加相关差异，难以准确标识时再补充内容哈希。仅因工作区未提交文件较多，不要求生成哈希；未提交工作区不能只用提交号判断一致。

检查运行期间保持目标代码及其验证依赖稳定。委派验收时，在该轮验收结束前冻结目标及相关依赖；子代理开跑前和回报前核对目标是否变化，父代理收到报告后复查相关工作区差异、暂存区及未跟踪文件。发生相关变化后，只复验受影响范围；其他有效证据继续复用。

修复与复验串行进行。自检发现问题时，施工者完成已授权修复后复验；独立验收发现问题时，子代理报告证据，父代理核对并修复后再交其复验。优先复用同一适任审查子代理，保留需求与失败证据的上下文。

## 缺陷回归与界面证据

测试应断言需求行为与外部结果，模拟外部依赖时保留待验证逻辑。根据风险选择有价值的回归用例，不为形式完整添加测试。测试失败先查原因；确因需求变化而需要调整断言时记录依据，按角色职责交接修改，不通过跳过测试、删除有效断言或替换关键逻辑来制造通过结果。

修复缺陷时，优先复现用户报告的操作路径，并验证修复后的外部结果；按相关风险补充相邻边界，不以测试数量判断覆盖质量。

菜单显示、隐藏和交互问题检查真实组件的渲染结果与事件路径，保留待验证的组件逻辑；涉及动态菜单时，补查受影响的键盘导航。布局、文字裁切、细线或吸顶问题使用实际渲染画面，必要时测量坐标、尺寸与缩放条件。状态与几何计算测试可提供补充证据。

隔离运行验证应说明保留的真实组件或模块、模拟的外部依赖及覆盖范围，区分组件运行结果与完整应用验收。

## 原型与音频效果

技术能力不确定、正式集成成本高，或需要比较明显不同的方案时，先用小型可运行原型验证核心差异。已有组件的颜色、间距、布局和动效调整默认直接在真实界面中迭代，并检查实际效果。比较时保持关键条件一致；交付原型时提供启动方式，并实际确认本次目标所需的素材加载、播放出声和交互反馈。

音乐驱动的视觉效果分别检查算法或时序正确性与实际听感。按效果风险选择代表性曲目或片段，并验证相关暂停、跳转和切曲场景；记录曲目之间的表现差异及用户试听反馈，作为方案选择的依据。

## 短时动效与性能

诊断进入或切换动效的卡顿时，先区分冷启动、首次进入和再次进入，测量出现问题的阶段，再按发现的瓶颈补充对照。结合单帧耗时、长任务及相关资源准备、布局和绘制开销判断原因。

算法微基准与页面流畅度分别记录测量范围。底层实现替换的性能结论使用实际调用路径对照，页面体验使用实际运行证据，并记录影响比较的输入和环境。

## 完成与独立验收

委派或跨会话交接时，明确接收者承担最终交付还是阶段任务。阶段执行者按约定完成实现、差异复查和必要检查后，向父代理报告结果与待验证项；用户限定仅施工时不运行检查。父代理处理剩余验证并形成最终交付。由新会话接任父代理时，同样承担验证协调与最终交付职责；职责说明不替代创建新会话或施工子代理所需的用户授权。

仅需差异复查的任务可直接交付，说明本次仅做差异复查、未运行测试。普通任务完成必要检查并处理发现的问题后交付。阶段交接与最终交付均按实际完成的检查报告状态，未运行测试时明确说明。

用户明确要求独立验收，或改动可能造成难以恢复的数据损失、安全越界、难以通过局部检查发现的关键行为回归时，需要独立验收。典型情形包括改变数据库迁移、音乐文件写回或删除策略、IPC 信任与权限边界，以及复杂播放并发或窗口生命周期行为。按实际行为影响判断；这些模块中的文案、样式或文档修改不自动升级。

识别到上述触发条件时，说明需要独立验证的行为及关联影响，交由未参与目标代码施工的只读审查子代理验收。子代理按需求独立推导检查项，父代理完成修复后再交其复验。结果返回前标记“待独立验收”或“待独立复验”。

父代理核对需求覆盖、失败与跳过项、验证缺口及报告对应的最终版本后形成交付结论，注明验证来源和范围。未执行、发现问题或证据不足的项目分别列明；测试通过与运行、视觉、性能通过分别表述。

全量回归用于跨模块影响、影响范围难以确定或明确的发布要求。需要时说明原因并指定负责阶段；同一目标已有有效结果时，另一阶段按风险选择独立抽查或补充验证。

## 证据与复用

交付或阶段交接简述改动、实际检查与结果、重要未验证项；运行检查时记录实际命令或复现步骤及退出结果。父代理核对自行检查或子代理报告对应的最终代码并承担交付责任，报告详略按任务风险确定。自检与独立验收分别注明来源。

跨会话复用证据、高风险交接或发布时，补充覆盖范围和影响结果的环境信息，代码状态按[目标版本与交接](#目标版本与交接)记录。优先写在交付消息中；需要持续修订、复用或跨会话传递较完整方案时，再使用独立文档。

已有结果在相关代码、测试、配置、依赖和运行环境仍适用时可以复用；仅核对影响当前结论的部分。无法确认适用、发生相关变更、证据缺失或可疑、新增风险或场景、关键行为需要独立复现时，补做受影响检查并简述原因；有效的其他证据继续复用。

模拟测试用于控制条件与检查逻辑，真实工具运行用于验证集成行为，画面检查用于验证视觉效果；三类证据不能互相冒充。验收者可访问实现与现有测试，独立性来自按需求自行判断。
