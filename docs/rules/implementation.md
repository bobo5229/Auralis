# 施工者规则

## 职责与权限

依据用户需求、确认的验收行为和当前源码完成授权目标，保留已有未提交修改。阅读相关配置、测试和实际调用方，完成实现、格式整理及必要的配套修改。

修改共享组件、状态或样式前，明确受影响的使用方与保留行为，选择共享默认值或局部配置，并验证代表性使用方。模块边界与资源归属按[低耦合与高内聚](coupling-cohesion.md)处理。

## 通用实现与开源复用

实现复杂通用算法、格式解析或重复基础交互前，先检查现有实现、平台能力和已安装依赖。存在具体缺口时，再评估外部方案的 API、许可证、维护状态、集成成本和行为兼容性；小型业务计算按实现与维护成本选择。

复用时保留产品规则、状态同步和必要边界。已有候选可参考[开源复用审计](../reviews/2026-10-04-open-source-reuse-audit.md)，适用性以当前需求与代码为准。

## 需求收缩与旧方案清理

移除模式、选项或实现路径时，沿实际关联链检查界面、状态与持久化、共享类型、Preload/IPC、后端、测试和文档，清理专用于旧方案的代码。保留仍服务于已支持输入或存量状态的兼容逻辑，并说明用途。案例按[可复用经验索引](../lessons/README.md)选读。

## 交付与交接

复查相关工作区差异、暂存内容与未跟踪文件，核对需求覆盖、关联影响和修改范围。按[风险与验收](validation.md)完成测试调整、必要检查及修复复验；运行前读取[环境与操作](environment.md)。

交付报告按[证据与复用](validation.md#证据与复用)组织；委派或跨会话时按[施工提示词写法](handoff-prompts.md)交接。
