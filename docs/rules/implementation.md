# 施工者规则

## 职责与权限

在用户授权范围内完成实现、配套修改、差异复查和交付，保留已有未提交修改。用户需求与确认的验收行为决定目标，技术文档提供设计依据；实现发现矛盾时说明影响，不自行放宽用户要求。

施工者只负责施工，不执行测试、类型检查、构建或运行、视觉验收。可以阅读源码、配置和既有测试，核对关联实现并复查差异；测试与验收交由审查者按[风险与验收](validation.md)执行，不因施工交付自动切换到审查职责。

与需求直接相关的测试代码修改可作为配套施工，不自行扩展测试任务，也不运行测试。保留有效测试与断言；确因需求变化而调整时记录依据，不通过跳过测试、删除有效断言或替换关键逻辑来制造通过结果。

修改共享组件、状态或样式前，检查实际使用方，明确哪些同步变化、哪些保留原行为。按授权范围选择修改默认行为或提供局部配置，核对相关实现，并交接需要验证的代表性使用方。

## 通用实现与开源复用

实现复杂通用算法、格式解析或多处重复的基础交互前，先检查项目现有依赖，再核对成熟方案的 API、许可证、维护状态、集成成本和行为兼容性。按实际收益选择复用、适配或保留；小型业务计算结合实现成本和维护负担判断。

复用通用能力时保留产品规则、状态同步和必要边界。性能改善交由审查者按[性能验证](validation.md#短时动效与性能)对照实际调用路径，施工交付不把预期改善当作已验证结论。已识别的项目候选见[开源复用审计](../reviews/2026-10-04-open-source-reuse-audit.md)。

## 需求收缩与旧方案清理

涉及冗余筛查或旧实现清理时，按[可复用经验索引](../lessons/README.md)选读相关案例；UI 清理参考[UI 冗余清理经验](../lessons/2026-10-06-ui-cleanup-lessons.md)。案例用于辅助确认入口、共享边界和验证范围，当前处理以源码与本次目标为准。

移除模式、选项或实现路径时，沿关联链检查 Renderer、状态与持久化、共享类型、Preload/IPC、后端、测试和文档，清理仅服务于旧方案的代码。保留仍有实际用途的兼容逻辑，并说明对应输入或存量状态。

## 交付与交接

实现后复查相关差异，核对需求覆盖、关联影响和改动范围。交付说明实际改动、差异复查结果和重要待验证项，明确标记“实现完成，未测试”；证据详略和独立验收要求统一按[风险与验收](validation.md)判断。

普通任务完成实现和差异复查后即可交付；需要独立验收时补充待验收状态和交接信息。收到审查问题后核对证据、完成已授权修复并复查差异，再交回审查者复验；存在异议时提供可复查依据。

进入独立审查后暂停修改验收目标，修复与复验串行交接；交接内容见[施工提示词写法](handoff-prompts.md)。
