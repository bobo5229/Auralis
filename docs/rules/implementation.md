# 施工者规则

## 职责与权限

父代理在用户授权范围内完成实现、配套修改、差异复查、验证协调和交付，保留已有未提交修改。用户需求与确认的验收行为决定目标，技术文档提供设计依据；实现发现矛盾时说明影响。

施工包括阅读源码、配置和既有测试，编辑产品与配套测试代码，整理格式，以及使用 `git status`、`git diff`、`git diff --cached`、`git diff --check` 核对改动。差异复查覆盖未跟踪文件、暂存区、关联实现和需求边界。

施工者可按[风险与验收](validation.md)执行定向测试、类型检查、语言键检查、Lint、格式检查、构建，以及必要的应用运行、视觉和性能检查。准备运行前读取[环境与操作](environment.md)。用户限定仅施工时遵从限定；需要独立验收的任务按风险规则交接。

配套测试代码服务于当前需求，保留有效测试与断言；确因需求变化而调整时记录依据。自检发现问题后完成已授权修复并复验；收到独立审查建议时核对证据，再处理测试或实现。

修改共享组件、状态或样式前，检查实际使用方，明确哪些同步变化、哪些保留原行为。按授权范围选择修改默认行为或提供局部配置，核对相关实现，并将代表性使用方纳入必要验证。

## 通用实现与开源复用

实现复杂通用算法、格式解析或多处重复的基础交互前，先检查项目现有依赖，再核对成熟方案的 API、许可证、维护状态、集成成本和行为兼容性。按实际收益选择复用、适配或保留；小型业务计算结合实现成本和维护负担判断。

复用通用能力时保留产品规则、状态同步和必要边界。性能改善按[性能验证](validation.md#短时动效与性能)对照实际调用路径，以运行证据形成结论。已识别的项目候选见[开源复用审计](../reviews/2026-10-04-open-source-reuse-audit.md)。

## 需求收缩与旧方案清理

涉及冗余筛查或旧实现清理时，按[可复用经验索引](../lessons/README.md)选读相关案例；UI 清理参考[UI 冗余清理经验](../lessons/2026-10-06-ui-cleanup-lessons.md)。案例用于辅助确认入口、共享边界和验证范围，当前处理以源码与本次目标为准。

移除模式、选项或实现路径时，沿关联链检查 Renderer、状态与持久化、共享类型、Preload/IPC、后端、测试和文档，清理仅服务于旧方案的代码。保留仍有实际用途的兼容逻辑，并说明对应输入或存量状态。

## 交付与交接

实现后复查相关差异，核对需求覆盖、关联影响和改动范围。目标稳定性及修复复验顺序按[目标版本与交接](validation.md#目标版本与交接)执行；需要委派或跨会话时，再按[施工提示词写法](handoff-prompts.md)准备交接。收到审查问题后核对证据，完成已授权修复并复查差异；对结论有异议时提供可复查依据。

施工阶段交接、验证协调与最终交付按[完成与独立验收](validation.md#完成与独立验收)执行，报告内容按[证据与复用](validation.md#证据与复用)组织。Git 写操作按用户授权执行。
