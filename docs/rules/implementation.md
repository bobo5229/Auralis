# 施工者规则

## 职责与权限

在用户授权范围内完成实现、配套修改和必要自测，保留已有未提交修改。用户需求与确认的验收行为决定目标，技术文档提供设计依据；实现发现矛盾时说明影响，不自行放宽用户要求。

施工者负责发现并修复自测问题。根据风险补充有价值的回归测试，运行受影响的定向检查；全量测试、构建和运行验证按[风险与验收](validation.md)选择。小型可逆改动无需为形式完整添加测试。

测试应断言需求行为与外部结果，模拟外部依赖时保留待验证逻辑。测试失败先查原因；确因需求变化而调整断言时记录依据。不得通过跳过测试、删除有效断言或替换关键逻辑来制造通过结果。

修改共享组件、状态或样式前，检查实际使用方，明确哪些同步变化、哪些保留原行为。按授权范围选择修改默认行为或提供局部配置，并验证受影响的代表性使用方。

## 通用实现与开源复用

实现复杂通用算法、格式解析或多处重复的基础交互前，先检查项目现有依赖，再核对成熟方案的 API、许可证、维护状态、集成成本和行为兼容性。按实际收益选择复用、适配或保留；小型业务计算结合实现成本和维护负担判断。

复用通用能力时保留产品规则、状态同步和必要边界。声称性能改善时，按[性能验证](validation.md#短时动效与性能)对照实际调用路径。已识别的项目候选见[开源复用审计](../reviews/2026-10-04-open-source-reuse-audit.md)。

## 需求收缩与旧方案清理

涉及冗余筛查或旧实现清理时，按[可复用经验索引](../lessons/README.md)选读相关案例；UI 清理参考[UI 冗余清理经验](../lessons/2026-10-06-ui-cleanup-lessons.md)。案例用于辅助确认入口、共享边界和验证范围，当前处理以源码与本次目标为准。

移除模式、选项或实现路径时，沿关联链检查 Renderer、状态与持久化、共享类型、Preload/IPC、后端、测试和文档，清理仅服务于旧方案的代码。保留仍有实际用途的兼容逻辑，并说明对应输入或存量状态。

## 交付与交接

实现后复查相关差异，确认需求覆盖、回归风险和改动范围。交付说明实际改动、执行的检查及结果、重要未验证项；证据详略和完成状态统一按[风险与验收](validation.md)判断。

普通任务完成必要自测和差异复查后即可交付；需要独立验收时提供交接信息。收到审查问题后核对证据、完成已授权修复并重跑受影响检查；存在异议时提供可复查依据。

进入独立审查后暂停修改验收目标，修复与复验串行交接；交接内容见[施工提示词写法](handoff-prompts.md)。
