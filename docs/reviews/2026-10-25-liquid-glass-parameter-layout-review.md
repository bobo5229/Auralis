# 液态玻璃参数设置项：布局审查与建议方案

审查日期：2026-10-25  
对象：Auralis「液态玻璃参数」设置分组（折射、色散、模糊、饱和）  
结论：**发现布局问题（基于截图）**；推荐方案待确认、待实施、待真实界面验收。

## 2. 现状与问题

截图采用同一行横向排列「参数名 / 滑块 / 数值」：参数名靠左，约 240 px 的滑块靠中，数值位于容器最右。整体对齐规整，但相关元素距离过远。

| 编号 | 优先级 | 观察与影响 | 证据性质 |
| --- | --- | --- | --- |
| L-01 | P0 | 参数名与滑块之间、滑块与数值之间各留出大段空白；用户难以把三个元素快速视为一个控件组，视觉焦点分散。 | 截图可见 |
| L-02 | P0 | 数值贴近容器右边缘，距离滑块明显过远；拖动后需要横向扫视才能读取反馈，微调效率低。 | 截图可见 |
| L-03 | P1 | 在较宽的设置区域内，滑块自身只占有限宽度；空间宽敞却没有用于增强控件组的整体性。 | 截图可见 |
| L-04 | P1 | 四行各占约 70 px 高度，辅助信息很少；目前信息密度偏低。是否需要压缩，应结合整页设置密度和点击目标验证。 | 截图观察与设计判断 |
| L-05 | P2 | 纯文本数值缺少输入框外观，也没有展示取值范围；截图无法判断是否支持直接编辑、键盘精调或其他提示。 | 可发现性问题；实际能力待验证 |
| L-06 | P2 | 大尺寸白色滑块手柄较醒目，标题、数值和轨道的视觉权重相对弱。绿色填充是否符合现有主题语义，需与实际主题 token 一起核对。 | 设计判断，非功能缺陷 |

**补充判断**：折射显示为负值，并不意味着滑块位置错误。各参数可能具有不同的最小值、最大值、步进和映射方式；仅凭截图不能据此认定计算或填充比例有误。「折射 / 色散」与「模糊 / 饱和」可以形成语义分组，但这不是本轮改动的必要前提。

### 应保留的基础

- 四个名称左对齐、四个数值右对齐，纵向扫描顺畅。
- 行高一致，结构简单，没有不必要的卡片嵌套。
- 标题下方有用途说明，「恢复默认」处于分组头部，入口易找。
- 整体深色、低对比度分隔线的表达克制；建议优先调整几何结构，不整体重做材质或配色。

## 3. 推荐布局：受约束的三列控件组（方案 A）

推荐在宽屏下保留**单行三列**，但让标签、滑块、数值在同一个有限宽度的控件组中，而不是分别占据整个面板的左、中、右边缘。

| 区域 | 建议布局 | 目的 |
| --- | --- | --- |
| 分组容器 | `width: 100%; max-width: 720–800px`，优先与内容起点左对齐 | 避免在宽屏下被无意义空白拉散 |
| 参数名称 | 固定列约 `120–140px`，文本左对齐 | 建立稳定扫描起点，兼容较长翻译 |
| 滑块 | `minmax(0, 1fr)`，桌面端可用轨道宽度优先保证约 `220px` 以上 | 承担主要弹性空间 |
| 当前数值 | 固定列约 `64–80px`，数字右对齐并使用等宽数字 | 与滑块紧邻，避免数值跳动引发横向位移 |
| 列间距 | 先以 `16–20px` 作为设计起点 | 建立明确的标签—控件—反馈关联 |
| 行高 | 先比较 `56px` 与 `60px`，不要仅为压缩牺牲可点击区域 | 提高信息密度并保留操作舒适度 |

建议视觉顺序：

1. 左侧参数名固定列，四行使用相同起点。
2. 中间滑块使用剩余可用宽度；数值与滑块间隔控制在一个常规控件间距内。
3. 右侧数值列固定宽度。第一阶段可继续使用当前展示形式；是否改为可编辑数字输入框，待核对现有调节/持久化语义后单独决定。
4. 标题、说明及「恢复默认」保留现有层级。若整体分组限宽，可让重置入口与该分组右边缘对齐，避免标题操作独自漂到页面最远端。

**不建议**单纯把滑块拉到全屏宽度，或只把数值向左挪动而保留过大的标签—滑块间距。这两种做法都没有从根本上收拢完整的控件关系。

### 窄窗口降级（方案 A 的响应式形态）

- 容器足够宽时维持三列，逐步缩小间距和标签列，但不得让滑块压缩到难以操作。
- 当三列无法同时容纳时，改为两行：第一行「参数名 — 右对齐数值」，第二行「占满可用宽度的滑块」。
- 分组内禁止水平溢出；长文案需有可预测的换行或省略策略，并检查实际语言切换。
- 不把具体断点视为已定实现值；在真实设置页中测量后再选择，例如优先观察内容宽度约 600px 附近的切换行为。

## 4. 推荐实施顺序与边界

### 第一批：仅优化布局（P0 + 必要 P1）

1. 定位目标四个参数的真实组件、CSS、响应式规则和参数状态来源，排查共享滑块样式的其他消费者。
2. 将四行组织为统一的局部网格/布局容器，落实固定标签列、弹性滑块列、邻近数值列。
3. 对照当前窗口布局调整分组最大宽度、列间距和行高；必要时同步调整「恢复默认」的横向对齐。
4. 增加窄窗口降级，检查文本裁切、边界和缩放。

**明确不改**：折射/色散/模糊/饱和的数学含义、取值区间、步进、默认值、实时渲染链路、偏好保存、重置逻辑及主题色 token。若需修改共享 `.settings-range-control`，必须先列出实际消费者与回归范围；优先使用目标组件局部规则，避免无意影响其他设置。

### 第二批：精调体验（另行确认）

- 核实数值是否已支持直接输入；若没有，再评估是否加入数字输入与合法范围校验。
- 为范围不直观的参数考虑 hover/focus 提示，解释作用但不增加常驻文字噪声。
- 统一滑块手柄尺寸、轨道对比度、焦点态，并在深浅主题下使用现有语义变量。
- 需要额外语义分组时，再评估「光学 / 表面」分类，不与第一批强绑定。
