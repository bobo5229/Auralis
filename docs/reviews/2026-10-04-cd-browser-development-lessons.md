# CD 浏览页开发复盘

复盘日期：2026-10-04。

CD 浏览页的开发涉及空间布局、动效、音频反馈、动态配色和开源复用。最有价值的经验是：先用小原型明确体验，再验证真实操作与关联状态，最后将稳定做法写入项目规则。

本复盘以本次对话中的需求变化、用户反馈和原型选择为依据。性能与运行结果查阅对应任务的验证记录。

## 案例与经验

| 本次案例 | 得到的经验 | 后续应用 |
| --- | --- | --- |
| 鼓点检测在一定程度上准确，用户仍觉得效果不完全符合原曲律动；换曲试听后又发现触发偏少 | 技术正确性和听感分别验收，曲目之间的表现差异也属于效果评估 | 用不同鼓点密度、长贝斯和安静段的代表性片段试听，结合触发时序与同步行为判断效果 |
| 用简单方块对比两种震动后，用户明确接受左侧方案 | 小原型能快速回答主观效果选择问题 | 保持音源、片段和显示对象一致，先比较核心算法或动效差异，再接入碟片完整渲染 |
| HTML 原型出现打不开、听不到声音的问题 | 原型交付需要覆盖启动到体验的完整路径 | 提供可复现的启动方式；按原型目标确认素材加载、解码、播放出声和操作反馈 |
| 用户能在多张碟片首次展开并滑入时观察到一两次卡顿 | 短时卡顿需要观察实际发生的阶段与单帧开销 | 区分冷启动、首次进入和再次进入，测量问题阶段，再检查相关资源准备、布局和绘制 |
| Composer 隐藏滚动条后仍无法用滚轮滚动；旋转后的歌词与信息区冲突，降级位置也引发疑问 | 滚动行为和空间降级需要明确约定，并通过真实操作与完整几何验证 | 长内容先确定完整显示或局部滚动；旋转、长歌词和尺寸变化进入空间检查，降级采用已确定的位置或隐藏策略 |
| 背景取强调色后，用户继续指出歌词字体和轨道也需要适配 | 动态背景影响整套前景语义色 | 用共享颜色上下文管理主次文字、歌词、轨道、分隔线与交互反馈，按实际启用范围校验可读性 |
| 自写 FFT 的替换工作延伸到整个项目的开源复用审计 | 通用能力可以复用成熟实现，产品规则和适配仍由项目维护 | 优先检查已有依赖，再核对候选方案的行为、维护成本与集成成本；性能收益通过实际调用路径测量 |
| 背景取色从两种模式收缩为强调色开关，入口也从文字选项收缩为图标开关 | 需求收缩应同步收缩实现链 | 检查界面、状态、持久化、类型、IPC、后端、测试和文档，清理仅服务于旧方案的分支 |

## 把关联检查放进首次交付

声音、滚轮、歌词颜色和首次进入流畅度都直接决定功能能否达到预期。将这些关联检查放进对应功能的首次交付，可以减少用户发现问题后再补充验证的往返。

检查范围跟随改动的实际影响。音频原型检查音源与同步，滚动改动检查真实输入，背景取色检查参与该画布的前景颜色，进入动画诊断检查发生卡顿的阶段。

## 使用方法

开始相似任务时，从本次目标中识别体验选择、空间变化、配色联动、性能或复用问题，再读取对应规则。主观效果先比较原型，选定方案后验证实际使用路径；需求变化后重新核对关联行为并清理旧分支。
