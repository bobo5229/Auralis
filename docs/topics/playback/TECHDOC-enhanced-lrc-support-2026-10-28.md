# 增强型 LRC 首期支持技术方案

日期：2026-10-28  
状态：L1 至 L4 已完成，独立复验通过；全应用 smoke 的既有字体检查阻塞见第 10 节  
源码基准：`7b8b6ecac8f023221f9705c0ffb28c843e5600ae`

首期在现有歌词链路上增加 Enhanced LRC 的行内计时解析、普通面板与全屏的逐片段同步点亮，以及现有原文编辑和整行调时的安全适配。采用扩展现有解析器、共用文本渲染组件的方案，保持现有歌词来源、播放状态、滚动、排版和保存事务。

本期高亮以文件提供的字、词或音节片段为单位，到开始时间时整段点亮。片段内部平滑扫色、逐字打轴工具、TTML/YRC/QRC/SPL、多声部和在线歌词服务不纳入本期。

## 3 首期格式契约

以下规则是 Auralis 的首期兼容约定，格式差异不依赖自动猜测。

### 3.1 支持的写法

```lrc
[00:12.000]<00:12.000>我<00:12.400>听见<00:13.100>雨声<00:14.000>
[00:15.000]这一句是普通 LRC
[00:18.000]先唱<00:18.500>后唱
[00:22.000]<00:22.200>Hello <00:22.900>world
[00:25.000]
```

- 行首继续使用现有方括号时间语法；行内仅解释成对的 `<时间>`。分钟为一位及以上数字，秒为两位且在 00–59，分数秒一至三位，允许句点或现有冒号兼容，均换算为整数毫秒后运算。
- 行内时间为整首歌曲的绝对时间。标签与下一个标签之间的文本属于一个片段；不按空格、汉字、Unicode 代码单元重新分词。
- “听见”可以是一个计时片段；emoji、组合字符与标点保持源片段，不自行拆分。
- 第一枚行内时间前的非空文本，起点沿用该行时间。第一片段晚于行时间时，期间文字可见但尚未点亮。
- 保留片段间空格、制表符及标点，不调用逐片段 `trim()` 或自动插入空格。普通 LRC 的既有首尾去空白行为保持；增强正文保留源正文空白，源文档始终独立保留。
- 最后一枚标签之后没有文本时，它是前一片段的结束边界，不创建可见空词。连续时间标签可以表达片段结束与下一片段开始之间的间隔；纯空白文本仍保留。
- 普通行、增强行和空时间行可以混排；空时间行保留，用于间奏与既有活动行切换。

### 3.2 时间计算与边界

继续使用 [lrcTiming.ts](../../../src/shared/utils/lrcTiming.ts) 的补偿方向：`显示时间 = 文件时间 - offset`，正 offset 使歌词提前。行、片段起点和结束边界使用同一个 offset；最后一个有效 offset 生效。不要改用候选库的默认补偿或额外加入默认延迟。

内部先用整数毫秒检查顺序和安全整数边界，再转为现有 Renderer 秒单位。显示时沿用零点截断，原始负偏移结果不写回文件；截断导致的同时间片段同时点亮。

片段区间采用左闭右开。非末片段的结束取紧随其后的时间标签，末片段仅在存在显式结束标签时具有文件提供的结束时间。缺少结束时间的末片段在开始时点亮，保持到活动行切换；不默认补一秒，也不插值伪造演唱时长。

后续更晚的行时间、空时间行及曲目结束限制当前行的展示时段。显式结束早于下一行时，保留已点亮正文并结束“当前片段”状态，不新增自动清屏行为。末片段开始晚于下一行时，该行的片段同步降级为整行展示，不修改原时间。

### 3.3 歧义与异常降级

| 情况                                 | 首期规则                                                                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `[00:10][00:20]重复句`               | 保留原有重复行展开，稳定排序，维持同时间最后一行活动的现状                                                                  |
| 多个行首时间与尖括号时间并用         | 展开各行并展示去除有效时间标签的正文，但整组不启用片段同步；不推测词时间应平移还是保持绝对值                                |
| 行内方括号 `[00:10]词[00:11]词`      | 首期不按增强格式解释；行首普通语义保留，正文方括号按字面显示，不自动转成 A2                                                 |
| 词时间倒退、早于行时间或结束早于开始 | 该行退回整行同步，不重排文字或修改原文件；不影响其他正常行                                                                  |
| 起点相同或零长度区间                 | 保留文本顺序，到边界同时点亮，不除以零                                                                                      |
| 无有效行首时间，仅有尖括号时间       | 保持普通文本路径，不新增无行首时间的增强方言                                                                                |
| 无效或不完整标签、普通尖括号文本     | 仅移除已识别的完整时间标签；其余文字原样转义显示，含时间样式的无效标签使该行取消片段同步                                    |
| 没有任何可同步行                     | 沿用现有纯文本回退                                                                                                          |
| 超大行的片段数量                     | 每行最多 1024 个文本片段，全篇最多 16384 个；超限行及耗尽全篇额度后的行仅清理有效标签并按整行展示，正文不截断，编辑原文不变 |

扫描按源码顺序完成，不使用可能反复回溯的嵌套正则。只解析时间标签，不使用 `v-html`、HTML 或 XML 解释正文。各项数量限制仅限制增强对象和 DOM 的扩张，不降低既有歌词读取或编辑文本上限。

## 4 数据与模块设计

### 4.1 派生模型

扩展现有 [LyricLine](../../../src/renderer/features/lyrics/types.ts)，原字段保持兼容，新增可选片段。以下是建议接口，位置限于歌词功能：

```ts
interface LyricSegment {
  text: string
  startTimeSeconds: number
  endTimeSeconds: number | null // null 表示文件未提供结束边界
}

interface LyricLine {
  id: string
  timeSeconds: number
  text: string
  enhanced?: true // 保留增强正文空白，降级后仍有效
  segments?: readonly LyricSegment[] // 缺省为普通行或降级行
}
```

`text` 始终是可供整行展示、跳转标签与辅助技术读取的正文；有片段时必须等于片段文本拼接。只有通过时间校验的行具有 `segments`。无正文的结束标签不进入文本片段，但参与前一片段结束时间推导。

原文及时间标签的字符范围由扫描结果保留，服务编辑器的定点替换；显示模型不承担原文序列化。稳定 ID 延续“源行及出现次序”的身份，繁简切换和活动时间变化不重建身份。普通歌词调用方无须构造单词对象。

### 4.2 共享时间规则与解析位置

在 `src/shared/utils/lrcTiming.ts` 提取方括号与尖括号共用的时间数字读取规则，保留现有导出和行首正则语义；增加纯函数扫描单行内的尖括号时间及字符范围。主进程的格式分类继续只依赖已有行首识别，不因 UI 增强扩大可接受的文档类型。

`parseLrc.ts` 负责组合行首时间、正文 token、offset、重复行和时间校验。不要分别在普通面板、全屏、编辑器实现三个增强解析器。编辑器只消费共用的时间扫描结果，在原字符串中替换时间范围。

`useTrackLyrics.ts` 保持单例和异步请求过期保护，额外暴露只读活动片段状态。纯函数可放在 `utils/getActiveLyricSegment.ts`：输入当前行与歌曲时间，输出最后已开始片段索引和仍在区间内的片段索引；相同起点片段一起开始。两个视图使用同一结果，单词变化不重建整份行列表。

### 4.3 播放时间来源

首期按片段开始边界点亮，直接使用 `usePlayback().state.currentTime`；不新增独立歌词计时器、第三方 Runner 或每个片段一个定时器，不向播放状态回写插值时间。

暂停保持当前点亮状态；seek、重复播放、切歌和歌词重载时根据最新歌曲时间重新计算，禁止仅递增片段索引。旧歌词读取返回不得影响新歌曲。拖动滑块的预览时间不冒充已提交播放时间。

在真实 mpv 与 Web Audio / HTML Audio 回退路径分别记录时间上报间隔、片段开始至显示更新的延迟。应用收到跨过边界的时间快照后，必须在下一次 Vue 更新及绘制中反映新片段。用人工生成的每 500 毫秒一个片段的音频/歌词采集各后端至少 100 个边界，首期目标为连续播放时相对实际媒体位置的点亮误差 P95 不超过 150 毫秒、最大不超过 300 毫秒；seek 单独记录，不混入连续播放样本。

上述目标是 L2 的验收门槛，并非现有链路已达到的结果。若时间上报导致超标，先定位当前时间发布路径并在原播放时间所有者内修正，不用歌词私有自由运行时钟掩盖延迟；修正后的播放时序按实际影响补充回归与独立验收。未通过前不能将 L2 标为完成。

### 4.4 繁简显示

源歌词与编辑原文保持原语言。普通行继续整行转换；增强行先转换各片段并拼接，同时计算现有整行转换结果：

- 两者相同时，使用转换后的片段和原计时，`line.text` 从这些片段拼接。
- 因跨片段词组转换产生差异时，该行使用正确的整行转换文本并取消片段同步；其他行不受影响。
- 不按相同字符数、UTF-16 下标或字符串切片把整行转换结果强行套回源片段。
- 字体、繁简、窗口尺寸或全屏排版偏好变化触发现有文字重测；不更改行时间、歌词来源或保存内容。

这项逐行降级用于保持现有词组转换结果。未来若需要跨片段转换仍保留逐字高亮，再单独引入可验证的文本映射能力。

## 5 展示与交互

新增 `components/LyricLineText.vue` 负责正文和片段视觉状态，普通面板与全屏共同使用。外层继续拥有行焦点、点击跳转、滚动、缩放、模糊和菜单；新组件不自行 seek 或控制滚动。

当前增强行中已开始的片段保持点亮，未开始片段使用当前画布的次级语义前景色；片段结束后可以保留点亮状态，时间间隔内不伪造新的活动片段。普通行与降级行继续使用原整行状态。首期不增加逐词弹跳、缩放、扫色或额外设置项。

片段使用可自然换行的 inline 文本，避免全段 `inline-block` 改变英文长词和窄窗口换行。增强正文使用局部 `white-space: pre-wrap` 保留空白，普通行维持原排版。纯空白片段不成为独立控件。正文只渲染一份，避免高亮叠层使复制文本和辅助技术读取重复。行的可访问名称使用去除时间标签的完整正文；逐词变化不进入 aria-live。

修改两处 `v-memo` 时把片段数据身份及当前行片段状态纳入失效条件；只让活动行响应词边界变化。普通面板保留现有整行 DOM 结构，全屏继续只构造可见行。非活动行可使用整行文本，不为整首歌挂载所有片段节点。

保留空行、开场倒计时、手动滚动后的暂停跟随、键盘 Enter/Space 跳转和菜单焦点恢复。点击任意片段仍跳转到整行起点，首期不新增“点击单词跳转”。唱片室继续原语言整行展示；不因该组件引入唱片室繁简转换或新动画。

## 6 编辑与保存适配

### 6.1 原文保留

继续编辑打开时绑定歌曲的歌词原文。现有换行规范化为 LF 的行为保留；不经过解析模型重新生成歌词，不排序、合并重复行、删除元数据、折叠空格或统一时间精度。保存为外部 LRC 与歌曲标签都传递原文字符串。

不把增强 LRC 当作 TTML；保持已有 TTML 文档拒绝与内嵌标签保护。手工编辑后暂时存在不完整时间标签仍可保存原文，播放按逐行降级规则处理；保存端不新增“所有时间必须有效”的限制。

### 6.2 整行打点与微调

对只有一个行首时间且行内时间合法的增强行，“更新当前行时间”和 ±0.1 秒均表示整行整体移动：

1. 根据用户目标播放时间和全局 offset，算出新行首文件时间。
2. 用整数毫秒计算 `delta = 新行首文件时间 - 原行首文件时间`。
3. 给该行行首、全部行内起点及结尾边界加相同 delta。
4. 从后向前替换原文中的时间范围，其他字符保持不变；作为一次撤销记录。

例如：

```lrc
# 原行
[00:12.000]<00:12.000>我<00:12.400>听<00:13.000>
# 整行后移 0.1 秒
[00:12.100]<00:12.100>我<00:12.500>听<00:13.100>
```

新改写的增强时间统一三位毫秒，未修改的时间格式保持原样。避免既有两位分数秒格式器丢失增强时间精度；普通 LRC 的原打点格式与行为保持。

整体移动若使任何文件时间为负、超出安全整数或时间序列无效，则不修改任何字符，说明无法整体移动；不对各时间单独归零。多行首时间、畸形行内时间或只有尖括号但没有行首时间的行禁用自动调时，仍允许原文编辑和保存。

工具栏在增强行说明“整行调时将同步移动行内时间”。切歌后依照现有规则禁用播放打点；不切换编辑对象。撤销/重做、输入法、光标位置和草稿关闭保护必须覆盖整体移动后的原文。

### 6.3 写入保护

增强文本沿用 `saveLrcEditor`、`writeLyricsStagingTag` 和外部 LRC 发布事务。MP3/FLAC/M4A/OGG/Opus 的标签格式支持范围不变，AAC/WAV 继续外部 LRC；文件版本冲突、会话失效、播放占用及缓存对账复用现有结果。

为增强文本补充隔离读回验证：内嵌与外部文本的所有尖括号时间、元数据行、空格和毫秒精度保留。按已有 LF 规范比较编辑文本，不要求容器文件字节相同。还需验证媒体内容及其他受保护标签没有被歌词写回改变。

保存后通过原有库变更订阅重读并解析，不让 Renderer 手工覆盖已选择来源。“保存成功但另一个更高优先级来源仍生效”的提示继续保留。
