# TECHDOC：跟随主题的 Logo 开屏动画

日期：2026-09-29  
状态：技术方案，待实施。

## 目标与交互

每次冷启动 Auralis 时，主窗口先显示一张覆盖整个客户区的开屏画面。背景沿用上次退出时保存的深色或浅色主题；首次启动及存储值无效时沿用当前默认深色主题。画面中央始终显示连续波形与 `Auralis` 文字。波形和沿线移动的光点使用当前主题强调色，文字使用当前主题正文色。

光点从波形左端沿真实曲线移动至右端，只运行一次。波形在全过程中完整可见。运动采用平滑的非匀速缓动，起步和收尾较慢，中段较快。正常启动下，从窗口显示到开屏淡出完成约 1.5 秒；建议光点运动约 1.2 秒，淡出约 0.3 秒。动画不可通过点击或按键跳过。主界面若尚未就绪，光点停在右端，完整 Logo 保持显示；主界面就绪后执行淡出。系统启用 `prefers-reduced-motion: reduce` 时，静态显示完整 Logo，主界面就绪后直接切换。

本功能只在应用冷启动的新主窗口播放。窗口最小化后恢复、路由切换和主题切换均不重播。开屏覆盖左上角窗口控制区，退场后正常显示主界面及红绿灯按钮。开屏期间主界面不可获得焦点，但系统级关闭窗口操作仍由 Electron/操作系统处理。

## 当前实现与切入点

- [`resources/icons/auralis-icon.svg`](../../../resources/icons/auralis-icon.svg) 包含一条从左到右连续的 Lucide 波形路径；方形底板和旧蓝色不进入开屏。侧边栏的 `i-ph-waveform` 是五条独立竖线，不能作为这次光点的运动轨道。
- [`src/renderer/composables/useTheme.ts`](../../../src/renderer/composables/useTheme.ts) 将 `light` / `dark` 写入 `localStorage` 的 `auralis-theme`。默认值为 `dark`。[`src/renderer/main.ts`](../../../src/renderer/main.ts) 在加载应用组件前调用 `initTheme()`，为 `documentElement` 设置 `data-theme` 和 `color-scheme`。
- [`src/renderer/app/styles/main.css`](../../../src/renderer/app/styles/main.css) 当前深色 `--auralis-bg: #121212`、`--auralis-theme-accent: #f472b6`、`--auralis-text: #f3eee6`；浅色对应 `#f0f1f2`、`#585b5f`、`#292b2d`。开屏使用同义的背景、强调色与正文色，不另定品牌色。
- [`src/main/app/createWindow.ts`](../../../src/main/app/createWindow.ts) 创建隐藏的 BrowserWindow，目前等待 `app:renderer-ready` 后才显示，另有 5 秒超时兜底；原生 `backgroundColor` 固定为深色。仅在 Vue 挂载后叠加开屏无法覆盖主界面加载较慢的阶段，也会让 1.5 秒动画可能在窗口显示前已经结束。
- [`src/renderer/index.html`](../../../src/renderer/index.html) 当前只有 `#app`。现有 CSP 的 `script-src 'self'` 不允许内联启动脚本，早期主题脚本应作为同源静态资源加载。

## 启动结构

在 HTML 壳中加入独立于 Vue 的开屏节点，采用本地静态样式与脚本。头部的同步同源脚本先读取 `auralis-theme`，按 `useTheme.ts` 的有效值规则设置根节点 `data-theme`；开屏背景、波形、光点和文字在首次可见绘制前获得主题颜色。静态开屏资源应打包到正式应用中，开发和打包后的路径均要可解析。对受 CSP 约束的脚本保留 `script-src 'self'`，不使用内联 JavaScript 或放宽 CSP。

启动壳需要少量首帧色值。将深浅背景、强调色、正文色的启动值与 `main.css` 对应 token 建立单一维护契约，并用测试检查两端一致；不得让开屏引用旧 SVG 中的蓝色。原生 BrowserWindow 的 `backgroundColor` 与当前主题也应一致：在窗口可见前完成主题判定及底色设置，避免浅色主题从深色原生底色闪入。主题读取失败时使用现有默认深色。正式主题状态仍由 `initTheme()` 管理，启动壳不建立第二套可变主题状态。

将窗口展示条件分为两个信号：

1. **开屏可绘制**：静态节点、主题和关键样式已准备好，主进程可以显示窗口。增加明确的、已做发送方与顶层 frame 校验的启动通知；通过现有显式 Preload/IPC 契约暴露，不能让 Renderer 直接调用 `ipcRenderer`。通知携带经枚举校验的 `light` / `dark`，主进程先据此调用 `window.setBackgroundColor()` 对齐原生底色，再显示窗口。此时 Vue 可以继续加载。
2. **主界面就绪**：沿用现有 `app:renderer-ready`，在路由就绪、Vue 挂载及下一帧后由 `main.ts` 发出。它只允许开屏退场，不应独自决定开屏最短显示时长。

开屏计时从主窗口**实际变为可见**时开始，不从 HTML 解析、模块加载或隐藏窗口中的 CSS 动画开始。普通模式满足“光点已抵达终点”与“主界面已就绪”两个条件后开始淡出；减少动态效果模式仅等待主界面就绪。开屏状态由一次性启动控制器管理，处理信号先后顺序，保证淡出与节点移除各执行一次。主界面在开屏退场前保持 `inert`，开屏节点提供 `Auralis` 可访问名称；退场后解除 `inert` 并将焦点交给正常应用入口。

原有 5 秒显示兜底仍可防止窗口永久隐藏，但它不能将未完成加载的空页面当作正常开屏。启动控制器在兜底路径保留已可用的 Logo；页面加载失败或 Renderer 进程退出则进入现有错误处理路径，不能无限等待主界面就绪。

## 曲线与动画实现

开屏 SVG 复用应用图标波形的原始 `path d`，单独渲染为无底板的线条，保持 `stroke-linecap`、`stroke-linejoin` 的圆润形态。光点和路径使用同一 `viewBox`，避免缩放、窗口尺寸变化或高 DPI 下产生轨迹偏离。波形与 `Auralis` 字样从第一帧起完整显示，字样沿用当前 UI 字体角色；可用响应式尺寸保持整个标志在窗口正中。

动画开始时读取路径总长一次；每帧将 0–1 的缓动进度映射到 `getPointAtLength(progress * totalLength)`，设置 SVG 光点坐标。只更新光点位置，保持波形路径和字样不变。缓动选用明确的三次贝塞尔或等价函数，使起点、终点速度接近零且中段自然加速；不使用线性计时。最后一帧将光点精确放在路径右端，随后保持静止直至退场。退场结束取消 `requestAnimationFrame`、计时器和监听器并移除启动节点。

`prefers-reduced-motion: reduce` 分支不启动逐帧动画，也不执行淡出；光点可隐藏，保留完整静态波形与字样。启动期间窗口尺寸变化仅改变 SVG 整体尺寸，不重新开始光点行程。开屏动画与应用内其他页面动效相互独立。

## 实施范围与验收

预计涉及 HTML 启动壳及其静态资源、主题首帧引导、开屏控制器、`main.ts` 的就绪通知和 `createWindow.ts` 的展示时序。新增 IPC 时同步修改 [`src/shared/ipc/channels.ts`](../../../src/shared/ipc/channels.ts)、类型契约、Preload 暴露、主进程处理器与运行时校验。SVG 资源可以抽取共享路径常量或生成专用开屏 SVG，但开屏轨迹须与当前应用图标的连续波形一致。侧边栏、关于页和桌面歌词窗口的图标与启动行为不在本次范围内。

验收覆盖：

1. 深色、浅色分别保存后完全退出并重启；从窗口第一帧到主界面出现，背景与当前主题一致，无反色闪屏，标志颜色正确。
2. 正常启动记录窗口可见时间、光点终点时间和淡出完成时间；整体约 1.5 秒。逐帧确认光点沿曲线移动、波形与文字始终完整，右端停靠准确。
3. 人为延迟 Vue/路由就绪超过 1.5 秒；动画结束后静态停留在完整 Logo，主界面就绪后只淡出一次。再检查提前就绪、窗口关闭、页面加载失败及超时兜底。
4. 启用“减少动态效果”后冷启动；静态 Logo 保持到主界面就绪并直接切换。恢复窗口、路由切换和主题切换不重播。
5. 在开发版与打包版核对启动资源路径、CSP、浅色原生窗口底色、键盘焦点和窗口控制区交接。运行主题单元测试、启动时序测试、类型检查与实际 Electron 画面验收。

本文为施工方案，记录当前代码的切入点与目标行为；实现状态以源码和实际窗口为准。
