# TECHDOC：深色模式自定义强调色

日期：2026-10-02

状态：施工方案，待实现。本文依据当前工作树和用户提供的开源调研制定；本轮交付文档。

## 1. 目标与施工范围

在“设置 → 外观”增加“深色强调色”，允许用户通过预设色板、取色面板和 HEX 输入修改深色主题的强调色。默认值为当前霓虹玫红 `#F472B6`，提供“恢复默认”，有效选择立即生效并保存。

使用 `vue-color@3.3.3` 的 `SketchPicker`。取色、滑块、颜色格式输入和色板复用该项目；设置持久化复用现有 Renderer `localStorage` 模式，颜色应用复用 `--auralis-*` 语义变量。当前主题没有通用设置 IPC，本轮沿用实际存储机制。

本轮覆盖当前消费主题强调色的普通主界面、Sidebar、歌曲与歌单视图、设置、弹窗、Teleport 浮层、常驻 PlayerBar，以及深色开屏波形。共享组件同步生效。专辑封面取色、CD 浏览独立配色、全屏播放器的封面配色管线、声迹复古界面的独立色板、桌面歌词的专属颜色保持各自来源。

保持深色中性底色、浅色主题、正文及辅助文字、语义错误/成功颜色、窗口红绿灯、图片内容和普通中性悬停效果。现有强调色使用位置及状态优先级延续当前实现；字号、行高、虚拟列表几何、播放与选择行为保持现状。

本方案补充[深色主题配色文档](TECHDOC-dark-theme-midnight-rose-2026-09-27.md)中固定强调色的规定；沿用其背景层级和独立配色边界。开屏相关规则以当前源码为准，保留后来修复的光点辨识度和刷新跳过行为。

## 3. 设置交互

### 3.1 入口与展开方式

两种主题均显示“深色强调色”。设置行显示当前用户选色的色块和六位 HEX，点击后在该行下方展开 `SketchPicker`；复用设置页当前布局与容器样式。内嵌展开可避免设置页滚动裁切和额外浮层定位。

深色模式下选择立即更新应用。浅色模式下选择只更新深色偏好和该设置的颜色预览，切换至深色后体现。浅色时显示说明：“仅作用于深色模式，切换后生效。”

有效选择直接保存，关闭面板保留选择；“恢复默认”是显式回到玫红的操作。无需另设保存/取消流程。

### 3.2 面板与色板

具名导入 `SketchPicker` 和所需公共工具，导入 `vue-color/style.css`；不注册整套取色组件。样式优先随设置页模块加载，检查构建产物确认实际分包结果。

配置 `disableAlpha=true`、保留内置颜色字段、设置 `presetColors`。初始色板采用八个不透明颜色：

| 名称             | HEX       |
| ---------------- | --------- |
| 霓虹玫红（默认） | `#F472B6` |
| 紫罗兰           | `#C084FC` |
| 靛紫             | `#818CF8` |
| 天蓝             | `#60A5FA` |
| 青色             | `#22D3EE` |
| 翡翠绿           | `#34D399` |
| 琥珀             | `#FBBF24` |
| 橙色             | `#FB923C` |

色板提供候选颜色，每次仅采用一个强调色。色板、输入和“恢复默认”汇入同一更新入口。

### 3.3 草稿、有效值与错误

区分组件内部编辑值与应用已接受的颜色。输入不完整或非法时，应用和存储保留上一有效值，避免每次键入触发默认色回退。

应用设置入口及存储格式仅接受规范化的 `#RRGGBB`，去除首尾空白、统一大写。组件内置 HEX 字段允许短写和省略 `#`，可按其现有规则转换后提交；这不要求改造第三方输入控件。对外部传入值和存储值实施严格校验。

`disableAlpha` 只隐藏透明度控件。适配层应检查组件颜色事件的实际 Alpha，拒绝透明颜色，并将面板同步回上一有效的不透明颜色。使用版本提供的 `update:tinyColor` 或其他已核实事件取得实际颜色对象，不能仅对可能已丢弃 Alpha 的 HEX 输出做正则检查。带透明度的八位 HEX 输入应保持上一有效颜色并说明“强调色需为不透明颜色”。

保存失败时，当前会话仍应用有效选择，设置旁显示“颜色已应用，本次保存未完成”。后续选择或恢复默认可重试；重复同一颜色时，若上次保存失败仍允许重试。反馈复用现有外观偏好中的 `persistFailed` 和诊断方式。

### 3.4 键盘、语言与缩放

展开入口和恢复默认使用原生按钮，设置行有明确标签；展开入口提供 `aria-expanded` 与 `aria-controls`。面板内 `Escape` 收起并返回入口焦点，避免同时关闭设置页；面板关闭后，隐藏内容退出 Tab 顺序。内嵌面板保持正常焦点顺序。

接入后实测库内滑块、HEX、RGB 字段及色板的键盘行为。该版本色板源码支持焦点和空格选择；核对 Enter 操作以及空格是否导致页面滚动，必要时在适配组件补充事件处理。HEX 输入和可选 RGB 字段构成键盘选色通路。

用户可见文案接入当前语言资源。检查库内英文标签的辅助技术读法，优先通过公开 API、属性和局部适配补齐必要名称。取色面板在当前最窄设置布局及 125%/150% 缩放下完整显示，页面纵向滚动可达底部。

## 4. 偏好与主题隔离

| 配置                   | 规定                                                     |
| ---------------------- | -------------------------------------------------------- |
| 存储键                 | `auralis-dark-accent`                                    |
| 缺省值                 | `#F472B6`                                                |
| 持久化格式             | 单个规范化六位 HEX 字符串                                |
| 初始化                 | 应用挂载前读取并应用，与开屏引导得到相同结果             |
| 缺失、非法值、读取异常 | 内存使用默认值；启动阶段保留原存储，下一次有效编辑再写入 |
| 恢复默认               | 应用默认值，并通过同一持久化入口保存                     |
| 主题切换               | 保留深色偏好；浅色继续使用当前浅色 token                 |

只存储用户选色，显示色和状态色由规则派生。规则调整后无需迁移多份颜色数据。

根元素可保存深色专用输入变量，例如：

```css
/* 由偏好及显示色规则写入根节点；这些变量本身不切换主题。 */
--auralis-dark-accent-source: /* 用户选色 */;
--auralis-dark-accent: /* 实际显示色 */;
--auralis-dark-on-accent: /* 实心强调按钮上的文字/图标 */;
```

深色 CSS 作用域引用这些变量。浅色 `--auralis-theme-accent` 保持当前 `#585B5F`，软背景和按钮前景保持当前浅色定义。根元素内联样式仅写深色专用变量，避免内联 `--auralis-theme-accent` 覆盖浅色选择器。

同一 Renderer 中由共享 composable 管理偏好；本功能沿用当前窗口的主题机制，不增加跨窗口同步协议或主进程设置存储。

## 5. 显示色与可读性

### 5.1 用户选色与显示色

用户选色保留原值，用于存储、HEX 和取色面板。界面显示色根据当前强调色所在背景检查对比度：足够时原样使用，不足时沿同一颜色向白色逐步混合，采用满足目标的最小提亮量。

这是本次可读性的实施规则。选择很暗的颜色时，应用保留原选色，界面使用较亮版本。设置页同时给出小型实际效果预览；发生提亮时显示“已适当提亮，以保证深色界面可读”。以中性色选择黑色时，提亮结果仍为中性灰。

派生只负责本应用的主题规则。通用颜色解析与格式转换复用库的公共 `tinycolor` 导出；亮度计算优先复用项目已有 `getRelativeLuminance`。不再引入第二个颜色处理库，也不复用封面提取/量化流程。

### 5.2 对比度检查对象

功能文字采用至少 `4.5:1`，功能图形与焦点标识采用至少 `3:1`。这是本功能受影响元素的验收目标，依据 [WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)及[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

检查最终合成背景，包含实际出现的默认、悬停、按下和激活状态。当前中性表面为 `#121212`、`#1A1A1A`、`#202020`、`#262626`；Sidebar 的 12%/16% 强调背景、曲目播放背景和控件按下背景按各自实际宿主合成。不要只计算原色与页面底色的对比度。

可优先派生一个满足现有文字与图形使用位置的显示强调色，使不同控件保持同一颜色。背景合成应随候选色重新计算，不能用固定玫红的合成结果检验其他选色。默认玫红在原有使用位置通过时保持原值。

实心按钮前景从 `#121212` 和 `#FFFFFF` 中选择满足目标、对比更高的颜色；默认玫红继续使用近黑前景。项目现有播放器前景函数使用 `#1F1F1F`，复用时核对参数和实际阈值，保持既有封面配色调用的行为。

对比度计算用共享纯函数按选色变化执行；实测用于检查 CSS 级联、内联覆盖和背景合成。避免在取色拖动中逐个读取整页 `getComputedStyle()`。

### 5.3 变量映射

| 当前角色                                                           | 深色目标来源                                                       |
| ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `--auralis-theme-accent`                                           | `var(--auralis-dark-accent, #f472b6)`                              |
| `--auralis-control-primary-bg`                                     | 主题强调色                                                         |
| `--auralis-control-primary-text`                                   | `var(--auralis-dark-on-accent, #121212)`                           |
| 焦点框、Sidebar 激活图标/标记/已有强调文字、进度和音量填充         | 主题强调色                                                         |
| `--auralis-control-active-bg`、曲目播放背景、Sidebar 激活/选中背景 | `color-mix(in srgb, var(--auralis-theme-accent) 12%, transparent)` |
| Sidebar 激活悬停背景                                               | 同一强调色 16%                                                     |
| `--auralis-selection-bg`                                           | 同一强调色 28%；保留当前选中文字前景                               |
| 中性悬停、分割线、表面、阴影结构                                   | 原有来源                                                           |

逐处处理根节点、主窗口/overlay、PlayerBar 的重复声明。已有消费主题 token 的组件无需逐个新增颜色 prop。查到硬编码或局部内联色时，按所属主题和用途判断；默认回退中的玫红常量可以保留。

普通 PlayerBar 的深色分支继续引用主题强调色，浅色分支继续走原封面取色。核对播放按钮、模式/队列等激活控件、音量与模式浮层，以及减少透明度等现有回退规则。颜色变化保持黑灰表面和关闭封面染色的当前效果。

## 6. 开屏首帧与刷新

`theme-boot.js` 在首次绘制前读取 `auralis-theme` 与 `auralis-dark-accent`，分别处理读取异常。保持同步经典脚本及当前加载顺序，避免等到 Vue 挂载后才换色。

首帧采用与 Renderer 相同的规范化和显示色派生。优先共享无 Vue 依赖的纯颜色规则；如果按现有主题引导模式保留必要的脚本镜像，必须用实际脚本执行测试对同一组输入比较完整结果，覆盖默认、极端色、非法值和存储异常。共享方式由施工者结合当前构建入口选择，首帧不加载完整取色组件。

深色 `--splash-accent` 引用动态显示色，浅色开屏保留当前灰色。开屏背景、品牌文字及波形轨迹保持现状。默认光点继续采用正文色填充、页面底色描边；若用户选择的强调色接近光点颜色，核对底色描边是否足以分隔光点与曲线，必要时仅调整光点的局部填充/描边对比处理。光点沿曲线移动应始终可见，不能回到同色光点难以辨认的状态。

首帧与应用初始化后使用同一显示色，含自动提亮的颜色也不能闪回默认玫红。保持动画时长、应用就绪条件、淡出、减少动态效果与错误画面处理。

普通刷新及 `Ctrl+Shift+R` 继续跳过动画，冷启动继续播放；跳过标记仍只隐藏 `role="img"` 的开屏，启动失败的 `role="alert"` 错误画面应可见。

## 7. 第三方组件接入

锁定 `vue-color@3.3.3`，安装时保留工作区既有 `package.json` 和锁文件修改。该版本支持 Vue 3，公开导出 `SketchPicker` 与 `tinycolor`，提供 `vue-color/style.css`；其运行依赖为 `tinycolor2` 和 `material-colors`。依据[官方 README](https://github.com/linx4200/vue-color)、[SketchPicker 文档](https://github.com/linx4200/vue-color/blob/main/docs/components/SketchPicker.md)和[该版本 npm 元数据](https://registry.npmjs.org/vue-color/3.3.3)。

该版本内置深色变量选择器是 `:root.dark`，普通 `.dark` 包装层无法触发。Auralis 沿用 `data-theme`：在取色组件宿主局部映射 `--vc-body-bg`、输入背景/文字/边框、Sketch 标签与色板边界等库变量，使用现有主题 token。核对库内控件的焦点样式，兼容当前全局焦点规则。局部样式覆盖以已安装版本的实际变量和选择器为准。

保持第三方代码由 npm 管理，样式及事件适配集中在设置组件；只有公开能力确实不足时才做最小适配。组件输出通过验证后进入偏好更新入口，避免把取色库允许的所有 CSS 格式直接写到 DOM 或存储。

仓库 [LICENSE](https://github.com/linx4200/vue-color/blob/main/LICENSE) 为 MIT，版本 npm 元数据未填 `license`。安装后核对发布包内许可证并保留原声明；如项目已有依赖许可记录，按其格式登记，不因元数据缺失直接推断无许可证。

版本源码核对基于 npm `gitHead`：[`db9106f438c2d7d947fd0644dfe355936d3c57f6`](https://github.com/linx4200/vue-color/tree/db9106f438c2d7d947fd0644dfe355936d3c57f6)。其中 `HexInput.vue` 支持短写和八位输入，`SketchPicker.vue` 色板使用可聚焦元素及空格选择，`variables.css` 使用 `:root.dark`；接入时以发布包实测确认。

### 9.1 自动化检查

新增或更新有行为价值的定向测试，沿用当前 Vitest 工具链：

- 颜色规则：默认值不变、合法大小写规范化、非法/透明输入拒绝、黑/白/饱和蓝/灰的派生结果、实际状态背景下的对比度、按钮前景。
- 偏好：缺失或损坏存储的默认行为、有效选择保存、刷新/重建状态恢复、恢复默认、读写失败、失败后的相同值重试、无效编辑保持上一值。
- 第三方适配：使用实际包的颜色事件验证 Alpha 校验及受控值同步；不能把取色组件替换成永远输出合法 HEX 的模拟后宣称完成集成验收。
- [useTheme.test.ts](../../../src/renderer/composables/useTheme.test.ts)：已有主题切换继续成立；补充深色偏好保留和浅色 token 隔离的必要行为检查。
- [themeBoot.test.ts](../../../src/renderer/app/splash/themeBoot.test.ts)：执行真实首帧脚本，按不同键分别返回存储值，补充选色、异常与刷新场景。现有始终返回 `light` 的存储模拟应改成按键读取。
- [splashContract.test.ts](../../../src/renderer/app/splash/splashContract.test.ts)：将“强调色必须是 HEX 字面量”的旧静态断言改为动态来源、默认回退及首帧结果一致的契约；保留轨迹、字体、时长与光点辨识度检查。如果光点改用动态对比色，将其固定填充断言更新为默认与近白强调色下的结果检查。
- [splashController.test.ts](../../../src/renderer/app/splash/splashController.test.ts)：复用或运行现有冷启动/刷新跳过检查；只有改变控制器行为时新增场景。

可按上述建议命名运行新增测试，并合并运行 `src/renderer/app/splash` 与 `useTheme.test.ts`。执行实际测试文件清单，核对 Vitest 的选中范围和跳过原因。

新依赖、Vue 组件接入和 CSS 打包是本轮构建验证理由：运行 `npm.cmd run typecheck`、受影响文件的 ESLint/Prettier、`npm.cmd run build`；当前 build 包含语言键检查和资产预算。已有当前工作树的构建基线可复用，据此记录 renderer JS/CSS 的实际增量；基线不适用时记录当前产物并说明无法准确比较增量。npm 解包大小不作为 bundle 增量。
