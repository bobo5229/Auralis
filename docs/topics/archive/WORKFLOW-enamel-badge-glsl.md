# 珐琅徽章 GLSL 美化工作流

版本：2.1；更新日期：2026-10-25。

目标：复用已认可的「100 小时·成章」材质方向，让后续徽章按同一流程完成反光替换。固定渲染、生成与验证方法，每枚只适配自身的图层语义和材质参数。

## 当前状态与入口

- 已适配现有全部 11 枚、22 个外观状态：小时系列 10／100／500／1000，天数系列 7／30／100／365／520，专辑系列 1／live。
- 视觉基准是 `hours-100`「100 小时·成章」；此前样板不是 100 天徽章。它的原有 12 份派生产物保持逐字节一致。
- [通用工具](../../../scripts/badges/README.md)将单枚适配、生成、观察、导出和检查分离。配置入口为 [profiles.mjs](../../../scripts/badges/profiles.mjs)，运行清单由 manifest 生成，无须维护另一份 11 枚文件列表。
- [收藏匣](../../../src/renderer/features/archive/components/ArchiveMilestoneCase.vue)与图鉴缩略图使用 GLSL 导出图；[三维检视](../../../src/renderer/features/archive/runtime/badgeInspectRenderer.ts)使用同一套实时 GLSL。每个打开的图鉴只有一个徽章上下文。

当前是设计图鉴，点亮／未点亮切换用于查看外观，不代表真实解锁；本次未新增成就统计或修改用户数据。

## 已确定的视觉与技术约定

| 项目       | 默认约定                                                                      |
| ---------- | ----------------------------------------------------------------------------- |
| 优化目标   | 保留原始几何和配色身份，移除固定反光，再由 GLSL 打光                          |
| 表现形式   | 正面 2.5D 浅浮雕；不扩展成完整可翻转三维模型                                  |
| 光照与姿态 | 固定摄影棚光，鼠标使徽章微倾斜，最大 ±8°，离开归位                            |
| 材质组织   | 金属、介电材料、局部虹彩分区计算；finish map 区分罩釉、纸张、绒布等表面       |
| 色彩空间   | base 按 sRGB；material、normal、AO、finish 为线性数据；沿用 ACES 与 sRGB 输出 |
| 贴图分辨率 | 先沿用 1320×1480，保留 330×370 的几何比例；产品分辨率优化另按显示尺寸处理     |
| 调度       | 姿态或状态改变时绘制，静置停止，隐藏页面暂停，退出释放资源                    |
| 可访问性   | 方向键调整、Home 复位；减弱动态效果停用悬停倾斜；WebGL 失败显示静态资产       |
| 原始资产   | 保留历史 SVG、PNG，派生产物独立存放，记录源文件哈希                           |

现有粗糙度起点为银色 `0.22`、珐琅 `0.12`、虹彩 `0.18`、未点亮 `0.65`。这是成章样板的基准，新徽章在该基准上调整，不作为所有材料的固定物理值。

## 每枚只需维护的适配配置

施工时核对下表，将实际参数写进 `profiles.mjs`；公共流水线不添加徽章 ID 分支。来源哈希独立保存在 `source-hashes.json`。

| 字段       | 内容与判断标准                                                        |
| ---------- | --------------------------------------------------------------------- |
| 身份与输入 | 徽章 ID、名称、点亮／未点亮 SVG、原版 PNG、源文件 SHA-256             |
| 保留几何   | 外框、数字、纹样、孔洞、裁切和叠放关系；不能随去反光一起删除          |
| 旧光照     | 应移除的罩面高光、光斑、偏移亮线，以及应被均匀底色替换的材质渐变      |
| 材质分区   | 每组几何对应的银色、珐琅、虹彩或其他材料；记录预期存在的遮罩通道      |
| 层次高度   | 边框、底池、数字、饰件的相对高低；来自结构语义，不从原图明暗推断      |
| 接触遮蔽   | 哪些阴影表达叠放接触，应转入 AO；哪些只是固定方向的投影，应移除或修正 |
| 配色与参数 | 底色、局部颜色组织、各材料粗糙度及需要偏离基准的理由                  |
| 差异检查   | 这枚特别容易损失的细节，以及小尺寸下必须保留的辨识特征                |

示例：30 天原图包含 `metallunar-*`、`cliplunar-*`、`lunar-enamel`、`white-pearl` 等结构；成章使用 `metal0`、`clip1` 等命名。共享步骤处理命名家族与几何，单枚配置明确将 `white-pearl` 映射为 pearl。珍珠沿用局部虹彩通道，通过 finish map 调整粗糙度与罩层，不另复制 shader。

## 固定执行顺序

### 1. 核对源图，完成适配表

查看原版大小图和 SVG 图层，核对两种状态、源哈希、裁切引用与关键几何。只记录这枚与基准的差异，不重新设计光源、观察台和交互方式。

源文件变化或出现未识别的材质引用时，先修正适配规则；不要静默当作普通珐琅继续生成。

### 2. 去除固定反光，生成可检查的底色

移除明确的光斑、罩面亮区和偏移高光，以均匀材料底色替换受光渐变；保留属于设计本身的色块与虹彩碎片。对照原版确认轮廓、数字、纹样和透明区域完整。

此时先提供「原版／去反光底色／新材质正面」三种对照，尽早看到核心效果。首轮可先做点亮状态；完成交付时仍需补齐未点亮状态。

### 3. 生成材质数据，沿用公共流水线

```text
原始 SVG + 单枚适配规则
  → base / material / height / AO / finish
  → 对高度做浮点模糊与差分 → normal
  → manifest → 共享 GLSL 渲染器
```

- `base`：去除固定受光后的底色与透明度。
- `material`：RGB 分别代表金属、介电材料、局部虹彩的覆盖权重。
- `height`：用于生成法线的结构高度，也是诊断产物；运行时不加载。
- `normal`：在浮点精度下完成模糊与差分，最后编码；避免量化台阶被高光放大。
- `AO`：接触遮蔽，不承担另一套固定高光。
- `finish`：RG 分别为粗糙度和罩层强度；纸张、绒布保持哑光，金色使用金属反射。兼容基准的成章保留原有着色行为。
- `manifest`：记录徽章身份、源哈希、移除项、两种状态的贴图及材质参数。

图层识别、底色与高度差异留在单枚配置；尺寸、栅格化、法线生成、引用检查和哈希记录由公共流水线负责。未知渐变或材料直接报错，不能静默套用珐琅。支持的源 SVG 协议及扩展例子见工具说明。

### 4. 接入共享渲染器，只调本枚参数

沿用 [badgeShaders.ts](../../../src/renderer/features/archive/runtime/badgeShaders.ts) 的固定光照与材质模型，通过贴图和参数表达差异。产品与观察台共用 [badgeMaterialRenderer.ts](../../../src/renderer/features/archive/runtime/badgeMaterialRenderer.ts)。优先按以下顺序检查：

1. 关闭反光：数字、配色与表面分区是否完整。
2. 查看法线与 AO：凸凹方向是否正确，有无条带、接缝或错误阴影。
3. 开启反光并倾斜：银边、数字、珐琅各自响应合理，高光不遮住主要图案。
4. 最后调整粗糙度、罩层强度和虹彩范围。

同类材料优先改贴图或参数。确需改变共享着色器时，同时复查已认可的成章样板，保留其视觉基准。

### 5. 按变化选择验证范围

| 变化                         | 必要验证                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------- |
| 新增单枚适配或调整贴图       | 源哈希、尺寸与透明度、SVG 引用、预期遮罩覆盖；两种状态、反光开关、正面与四向倾斜的真实画面         |
| 新增单枚参数或调整材质       | 大图、96px 对照，以及收藏匣实际约 70px／窄窗约 44px 的表现；深浅背景与麂皮底材上的可读性           |
| 修改共享生成步骤             | 重生成成章和受影响徽章，比较输出与画面；相同输入重复生成结果一致                                   |
| 修改共享渲染、输入或生命周期 | 补查 DPR、尺寸切换、键盘、静置停止、隐藏暂停、减弱动态效果、上下文丢失与静态回退                   |
| 接入产品页面                 | 使用真实组件检查加载、切换、离开与重新进入；按场景管理上下文和资源，不为每枚静态预览常驻一个渲染器 |

遮罩检查核对每个可见像素的材料覆盖及预期金属／介电区域，不要求每枚都包含虹彩。未点亮状态不含介电材料。另用 synthetic 新徽章配置测试扩展能力，并检查未知材料失败、透明孔洞、结构高度与颜色分离，以及基准兼容性。

先复用仍适用的环境与共享能力证据，仅补充本次变化影响的验证。rAF 间隔只描述采样路径，不等于 GPU 单帧耗时。

### 6. 保存结果与交接

每枚保存一份适配记录、两套材质及 manifest、原版对照、实际小尺寸图和验证结果。失败尝试使用单独运行目录，最新通过记录指向最终版本。

完成条件：原始资产保持不变，固定反光已被替换，关键几何与辨识特征保留，大小图均可读，本次涉及的交互和回退检查通过。中途得到首张有效画面，不等于完成全部交付。

## 通用命令与维护边界

默认处理全部配置；`build` 和 `check` 支持 `--badge` 选择单枚或逗号分隔的子集：

```powershell
npm.cmd run badges:build
npm.cmd run badges:check -- --materials-only
npm.cmd run badges:render
npm.cmd run badges:check
npm.cmd run badges:preview

npm.cmd run badges:build -- --badge days-30
npm.cmd run badges:check -- --badge days-30 --materials-only
node --test scripts/badges/materialPipeline.test.mjs
```

完整参数、配置示例与文件职责见[工具说明](../../../scripts/badges/README.md)。观察台地址为 <http://127.0.0.1:4197>；原版／底色／GLSL 与 96／70／44px 小图在同一页面检查。`badges:render` 用隔离 Electron profile 渲染全部状态，生成 330×370 预览、总览和运行报告，不启动生产主进程。

资产位于 `src/renderer/features/archive/assets/milestones/materials/`。运行时只加载五张贴图；height 与底色 SVG 留作诊断。静态预览指纹包括五张运行贴图和共享 renderer／shader，默认检查器会拒绝过期预览。修改贴图或共享渲染后重新导出；不能仅更新 manifest 冒充匹配。

每轮验证输出独立保存在 `output/badge-glsl-validation/run-<时间戳>/`，`latest.json` 指向最近通过记录。真实页面验证使用 `output/archive-badge-placement/verify-integration.cjs`：保留实际 Renderer、Preload 和档案只读查询，其他 IPC 使用 inert preview 响应；不会写入真实数据库，也不等同于完整生产主进程端到端验收。

自动化固定重复劳动，每枚仍需确认图层语义和视觉结果。新增现有系列徽章只需补源文件、哈希与 profile；首页精选按产品需要人工选择，图鉴自动读取 manifest，缺少翻译时使用配置名称。

排查遇到问题时，参考[珐琅徽章 GLSL 复盘](../../lessons/2026-10-24-enamel-glsl-debugging-lessons.md)：从首轮记录执行阶段；最小探针成功后比较验收脚本差异；输入后先等待状态变化；分别检查初始化、DPR 和法线精度。

## 收藏盒与三维检视

正式路径：聆听档案 → 聆听纪念的“查看全部” → 小时／天数／专辑 → 单击徽章。

- 陈列与页面小尺寸徽章使用同一批静态 GLSL PNG；只有被取出的一枚实时渲染。
- `ArchiveMilestoneGallery.vue` 负责分类、外观与 UI 组合，铝盒直接作为整个弹层，分类、外观和关闭操作整合进盒沿；没有额外标题栏、说明段落或 middle dot 拼接标题。AppDialog 通过可选 header 插槽保留背景隔离和焦点管理，其他弹窗沿用默认标题栏。检视无详情文字；Esc／空白／关闭先放回，随后 Esc 关闭盒子。
- `useBadgeInspection.ts` 负责约 1080ms 的移动放大与自身竖轴整周翻转、鼠标微倾斜、方向键调整和约 420ms 的归还。左右按钮连续检视同类徽章。减弱动效偏好下直接到达最终状态。
- `badgeInspectRenderer.ts` 负责模型、五张正面材质贴图和一个共享 WebGL 上下文，复用既有 badgeShaders；加载并行、纹理上传与预编译先于翻转，切换和取消丢弃过期结果。
- `badgePressureSurface.ts` 拥有海绵压力、画布和 Worker，像素内核只更新变化区域；取出后保留 82% 压缩。静置停帧，离开页面或关闭盒子释放资源。
- 外轮廓由已有 badges:build 写入同一 manifest 的 contour 字段，海绵与三维几何共同消费。纹理是功能内资源，不依赖 demo 路径或本地 HTTP 服务。

材质内核的历史像素／性能证据见原型 README；正式集成须另以构建后 Electron 的实际入口检查分类、22 种外观、检视与放回、焦点和资源释放，性能测量期间不截图。已有有效静态资产检查继续复用。

2026-10-25 正式接入验收：完整 build（含类型、语言键、构建预算）、徽章资产 11 枚／22 状态、定向 Lint 与格式检查通过；像素缓存单测 2 项和材质流水线单测 9 项通过。构建后完整应用的 55 项运行检查通过，覆盖实际 Preload／IPC、原生播放隔离 PCM 样本、22 种外观、取消、焦点、DPR、900×620 最小窗口、离页释放和失败回退；[运行报告与源码快照标识](../../../output/badge-player-integration/report.json)。没有访问真实曲库或音乐文件。

同机原生窗口、DPR 1.5、630×706 检视画布下，原型与正式播放器的两次热启动各采集 519 个 GL 提交更新间隔，P95 均约 4.3ms；最长分别 5.2ms／12.9ms，超过 25ms 均为 0。正式播放器同时原生播放隔离样本。原生回调节奏约 240Hz，不等同屏幕呈现 FPS；窗口与海绵尺寸略有差别，不能与旧 60Hz 离屏报告直接作数值比较。[性能对照与环境](../../../output/badge-player-performance/comparison.json)。首次准备 176ms 是单次样本，不作统计性提速结论。

容器收敛的实际 Electron 检查覆盖铝盒与弹层边界一致、无外层底板和说明文字、盒沿操作、最小窗口、检视／连续切换／两级退出、错误图标与重试，以及设置弹窗默认标题栏；见 [容器检查报告](../../../output/badge-case-shell/report.json)。
