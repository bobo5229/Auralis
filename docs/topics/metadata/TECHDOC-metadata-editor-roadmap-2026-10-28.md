# 元数据编辑面板扩展技术方案

日期：2026-10-28

状态：E1 至 E6 已实现并通过独立验收（2026-10-29），验证范围见第 6 节

源码基线：`d5affe3b`。本方案承接[元数据体系优化](TECHDOC-metadata-system-optimization-2026-10-28.md)，沿用已实现的文件真实值、历史覆盖、修改集、编辑 token、暂存写回和读回校验。

## 1. 目标与交付顺序

让用户安全地完成单曲纠错和整张专辑整理：编辑中断时保留输入，可以修正排序信息，能够批量统一专辑标签，并管理内嵌封面。

| 阶段                  | 交付内容                                             | 完成条件                                         |
| --------------------- | ---------------------------------------------------- | ------------------------------------------------ |
| E1 编辑恢复与输入反馈 | 冲突核对、修改状态、关闭保护、重置、日期与多值提示   | 冲突不丢草稿；误关可取消；输入提示与真实能力一致 |
| E2 曲目与碟片编号     | 曲目号、曲目总数、碟号、碟片总数                     | 排序字段往返一致，修改一个分量保留另一个分量     |
| E3 专辑批量编辑       | 固定曲目集合、混合值、修改预览、进度、取消与逐曲结果 | 专辑改名不改变任务目标；成功和失败可分别核对     |
| E4 内嵌封面编辑       | 图片预览、添加、替换、移除及来源解释                 | 只改变指定图片，保留其他图片、标签和媒体内容     |
| E5 更多标签           | 作曲者、版权、ISRC                                   | 读取、编辑、校验与文件读回形成完整链路           |
| E6 历史值逐字段合并   | 文件值与历史保留值逐字段选择                         | 用户可以混合取值，写回成功后再解除历史覆盖       |

按 E1 → E2 → E3 → E4 → E5 → E6 实施，每阶段分别验证和交付。E1、E2 构成首批交付；后续阶段复用其表单、能力描述及冲突流程。

本轮规划覆盖本地文件编辑。歌词继续使用独立编辑器；年份由发行日期派生。原始发行日期、任意自定义标签、文件重命名、自动编号、在线匹配和应用重启后恢复草稿留作独立需求。

## 2. 共用交互与技术边界

### 2.1 表单与编辑状态

沿用统一编辑宿主 `TrackEditorDialog` 内的 `MetadataEditPage` 和 `AppDialog`。基础区域保持现有六类字段，编号放入“曲目与碟片”，作曲者等放入默认折叠的“更多标签”。封面使用独立区域。只读摘要显示文件名、格式及目标曲目数，文件路径可展开查看。

会话在 Renderer 中分别持有打开时基线、当前文件快照、用户草稿和已成功提交值。表单归一化与修改集使用共享规则；多值仍按 `; ` 编码，日期仍派生年份。修改状态以最近成功提交值为基线，防止写回成功但曲库刷新失败时再次写入文件。

`getTrackEditSnapshot` 增加只读文件摘要和字段能力描述：字段是否可编辑、拒绝原因、日期支持精度。能力来自主进程的实际格式适配器；Renderer 用其展示控件和即时反馈，主进程在保存时再次校验。能力未知时明确禁用对应字段。

### 2.2 数据与写回职责

Renderer 管理草稿、差异展示和用户选择；主进程管理文件身份、能力校验、任务及写入资源；repository 提交真实文件读回值和曲库投影。保持显式类型化 Preload/IPC，不接收 Renderer 提供的写入路径。

继续使用现有暂存文件、未修改标签保护、媒体校验、发布、数据库补交和播放租约。新增字段同时扩展解析、修改集、格式写入、读回比较和标签保留白名单；白名单仅放行实际修改字段。失败返回安全 reason code，完整文件路径和工具错误留在主进程日志。

普通编辑成功后保持文件权威。历史覆盖仍只作用于既有七字段；新增编号和更多标签直接使用文件值，不自动纳入旧覆盖掩码。任何新迁移使用实施时尚未占用的递增编号，不改写已发布迁移。

## 3. 各阶段实施方案

### E1 编辑恢复与输入反馈

**关闭与重置。** 有修改时，关闭按钮、取消和 Esc 统一进入面板内的“继续编辑 / 放弃修改”确认状态；无修改直接关闭。曲库页路由离开时使用同一判定。重置操作恢复最近成功提交的标签；存在未提交修改时先确认。保存进行中保持既有关闭限制。应用进程退出不承诺保留内存草稿。

**冲突恢复。** 收到 `metadata-conflict` 或 `file-changed` 时保留草稿，提供“读取最新标签并核对”。重读成功后取得新 token，比较旧基线、最新文件值和用户草稿：

| 字段状态                       | 重读后的处理                                   |
| ------------------------------ | ---------------------------------------------- |
| 用户未改                       | 采用最新文件值                                 |
| 仅用户改                       | 保留用户草稿                                   |
| 文件和用户均修改，归一化后相同 | 采用共同值，不显示冲突                         |
| 文件和用户均修改，归一化后不同 | 展示最新值和我的输入，用户逐字段选择后才能保存 |

重读失败保留旧基线和草稿，提供重试；禁止使用旧 token 强制覆盖。第二次文件变化重新进入核对流程。token 到期但文件未变时，取得新 token 后直接保留草稿。当前文件进入历史覆盖状态时转入历史核对流程，原草稿仍可查看和复制。

**写回后刷新失败。** 分别展示“标签已保存”和“曲库刷新失败”，提供仅重试刷新操作；沿用 `libraryMetadataSaveCommit` 的提交记录。用户继续修改时，基于最近已提交值生成新修改集。

**输入反馈。** 日期提示明确接受 `YYYY`、`YYYY-MM`、`YYYY-MM-DD`，按当前文件能力显示可用精度；当前 MP3 写入器不支持仅年月时，在输入阶段提示并阻止该日期修改。未修改的日期不因能力提示而被重写。多艺术家、专辑艺术家与流派增加示例 `Artist A; Artist B`，明确分号后需空格，`AC/DC`、`R&B/Soul` 保持单值。首版保留文本输入，不引入新的标签控件或候选词服务。

### E2 曲目与碟片编号

新增四个独立可选整数：`trackNo`、`trackTotal`、`discNo`、`discTotal`。输入留空表示清除该分量；新输入范围统一为 1–65535。编号与总数均存在时，编号不得大于总数；已有不合规数据在编辑其他字段时保持原样，仅在用户修改相应编号组合时要求纠正。

`tracks` 增加可空的 `track_total`、`disc_total` 列，已有编号列继续复用。旧库总数保留 `NULL`，由正常解析器回填补齐；升级过程不遍历和修改音乐文件。读取快照和共享真实标签类型增加四字段，曲库 DTO 仅向需要总数的消费者提供它们。

格式适配器按完整“编号 / 总数”组合读写：ID3 的 TRCK/TPOS、MP4 的 trkn/disk、FLAC/OGG/Opus 的对应字段。保存只改编号时，从打开时真实快照保留总数；清除总数时保留编号。同步该格式内已存在且受支持的总数字段别名，私有命名空间继续保护。

文件提交后通过既有投影刷新曲目顺序和碟片分组，保留 track ID、歌单与收听关联。新解析器版本使旧文件的数据库总数可以在正常扫描中回填。

### E3 专辑批量编辑

首版入口为专辑封面菜单中的“编辑整张专辑”。保留现有“编辑当前曲目”入口，并用明确文案区分两者。首版批量字段为专辑名、专辑艺术家、流派和发行日期；曲目标题、曲目艺术家和编号仍逐曲编辑。

主进程按当前有效专辑身份解析并固定 track ID 集合。任务准备后，专辑改名、排序或页面过滤变化均不改变目标。最多 5000 曲，超出时显示需缩小目标，不截断集合。准备阶段并发读取最多 2 个文件，写入阶段串行执行。

混合值以占位文字显示，不能当作标签内容。每个字段默认“保持原值”，可切换“替换”或“清空”；流派额外支持“添加值 / 移除值”，按既有多值规则逐曲处理。保存前展示将修改的字段、目标数量及逐曲差异，可展开完整目标清单。

准备阶段标出文件缺失、格式不支持和历史覆盖待处理曲目。默认要求先处理这些阻塞项；用户显式选择“跳过不可编辑曲目”后，预览显示将跳过的曲目及原因。保存开始后的文件冲突按单曲失败报告，继续处理剩余曲目。

采用主进程专属任务清单保存每曲基线、指纹及修订，不为整张专辑占用当前最多 256 个单曲 token 的会话池；共享单曲保存的冲突检查和事务协调能力。任务最多同时保留 1 个，准备完成后 30 分钟未启动则过期。运行中的任务不因准备有效期到期而中断，每曲写入前仍检查实际源文件。

新增任务契约覆盖准备、执行、查询、订阅进度、取消与释放。状态为 preparing、ready、running、completed、cancelled、failed；单曲结果分别记录成功、失败、跳过及未执行。取消等待当前单曲安全收尾，再停止后续写入；已完成文件保留成果。任务结果提供仅失败曲目的重新准备入口，冲突需重新核对后提交。任务只在本次进程中有效，底层已发布文件的数据库补交沿用现有恢复机制。

整组文件不宣称原子事务，不做自动跨文件回滚。使用既有安全通知机制分批更新曲库，并在任务结束时刷新最终快照。保持单一任务进度面板，切换路由不取消主进程任务；返回后可以查看状态和结果。

### E4 内嵌封面编辑

展示每张内嵌图片的预览、类型、尺寸和大小，默认选中当前用于展示的第一张。目录封面与专辑回退以只读来源单独标明。首版支持 FLAC、MP3、AAC/ALAC M4A 的内嵌图片编辑；其他格式在完成对应图片保护验证后再启用。

添加图片默认写为正面封面；替换和移除只作用于用户选中的内嵌图片，其余图片的类型、描述、顺序及内容必须保留。删除最后一张内嵌图片时提示后续实际回退来源。目录 `cover.jpg` 的创建、覆盖和删除不进入本阶段。

通过主进程原生文件选择器导入 JPEG 或 PNG，限制 20 MiB、4000 万像素，并实际解码验证。主进程保存临时副本，返回绑定当前编辑会话的图片 token 及受控预览地址；保存仅接收 token 和操作，不接收任意路径或图片字节。导入 token 随会话释放，过期和取消导入会清理临时资源。图片预览沿用受控资源协议。

封面修改加入同一修改集，并在一次暂存文件事务中与文字标签共同保存。版本检查覆盖图片选择时的音频指纹；校验允许指定图片的变化，继续保护全部未选图片、文本标签和音频媒体。成功读回后走既有封面来源投影、旧新专辑代表选择及 GC 引用规则。格式适配器无法保证其他图片不变时，提交前拒绝该操作。

### E5 更多标签

首版增加作曲者、版权和 ISRC，映射到已有读取及数据库字段。作曲者沿用多值 `; ` 规则，版权按现有文件读取语义往返，ISRC 保留文本值；仅对实际修改的字段执行清洗和边界校验，不自动改写旧值。清空使用显式 `null`。

三个字段加入单曲真实快照、修改集、IPC 校验、格式适配和读回比较。沿用现有文本长度上限；格式不支持时通过能力描述禁用。首版不加入专辑批量字段，也不建立任意键值标签编辑器。

### E6 历史值逐字段合并

保留“全部采用文件值”和“全部采用历史值”的快捷动作。对存在差异的字段新增“文件值 / 历史值”选择，初始不默认选择；用户完成全部差异选择后可进入编辑表单继续修改。年份与日期作为一个选择单元，保持年份派生规则。

新增 `legacyAction: 'apply-merged'`。请求仍通过当前 token 绑定历史快照，由主进程以文件真实值为基线合并显式修改集；选择历史空值时必须发送 `null`。字段全部最终采用文件值且没有额外修改时，只更新数据库并解除覆盖；其他情况经正常文件写回和读回校验成功后，才解除该曲全部历史覆盖。失败保持历史值和覆盖位。新增编号和更多标签不受历史选择影响。

## 4. 接口与兼容约定

| 边界     | 变更                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| 单曲读取 | 扩展编辑 snapshot 的文件摘要、字段能力、编号和更多标签；历史快照保持既有七字段语义  |
| 单曲提交 | 保留 `trackId / editToken / changes`；按阶段扩展字段及封面操作；增加 `apply-merged` |
| 格式能力 | 主进程集中维护，读取返回给 Renderer，保存再次校验；不按扩展名在面板内复制规则       |
| 批量编辑 | 独立任务契约和有界清单，复用单曲写入协调器；禁止以循环调用公共保存接口规避会话边界  |
| 图片导入 | 原生选择器、会话绑定 token、受控预览和主进程临时资源；Renderer 无通用文件权限       |
| 数据库   | 增加两列总数；既有字段和七字段历史覆盖保持兼容；新迁移前沿用一致性备份              |

每次新增 IPC 同步契约、运行时通道、Preload、主进程发送方及 payload 校验、浏览器预览适配、测试 fixture 和中英语言键。升级后的旧 Renderer 请求不自动降级为整组写回，重新加载应用后使用新契约。

## 5. 验收与交付

| 阶段  | 必须覆盖的验收场景                                                                                                                                                         |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1    | 无修改直接关闭；修改后取消关闭；确认放弃；重置；路由离开；token 到期；文件与草稿分别变化及同字段冲突；重读失败和再次冲突；写回成功但曲库刷新失败仅重试刷新                 |
| E1    | 年、年月、完整日期和非法日期；MP3 年月在保存前明确反馈；多值与裸分号、逗号、斜杠保持现有语义；中英文长文本、键盘焦点和深浅主题                                             |
| E2    | FLAC、MP3、AAC/ALAC M4A、OGG、Opus 的编号及总数往返；只改一个分量；清空；越界；历史不合规值；同类字段别名；媒体、其他标签和歌单/收听关系保持                               |
| E3    | 混合值不写入文件；保持/替换/清空及流派增删；超过 256 曲不驱逐单曲会话；5000 曲上限；改名后集合固定；缺失/不支持/历史覆盖的显式跳过；取消、部分成功、重试、切页与关闭 drain |
| E4    | JPEG/PNG 导入；无效、超大和超像素图片；多内嵌图片添加/替换/移除；未选图片完整保护；内嵌清空后目录回退；文字与封面同时保存；冲突、转换失败及资源清理；GC 不删除有效引用     |
| E5/E6 | 多作曲者、版权原值、ISRC 和清空往返；文件值与历史值混合、显式空值、日期联动；仅采用文件值不写文件；写回失败不解除覆盖                                                      |

单测覆盖修改集、三方合并、状态流转和 IPC 边界；原生测试使用生成音频、实际标签写入器及隔离数据库；组件测试保留生产表单与真实事件路径。日期与多值提示等低风险修改按必要检查交付。涉及数据库、音乐文件写回和 IPC 边界的阶段必须通过未参与施工的只读审查者独立验收。

E3 使用人工生成的 5000 曲目录验证实际准备、执行和取消路径，记录环境、峰值内存及界面响应，不以纯算法微基准代替任务运行。写入并发固定为 1；观察到性能瓶颈后另行评估调整。

每阶段更新本节对应状态、实际检查命令和结果。开发与验证使用隔离数据；真实曲库批量操作由用户在产品预览中明确选择目标后执行。实施阶段分别提交，提交和远端操作仍以当次用户授权为准。
