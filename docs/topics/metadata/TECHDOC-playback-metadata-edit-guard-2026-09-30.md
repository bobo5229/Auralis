## 目标

播放器使用中的音乐文件，其元数据面板保持只读，并说明解除限制的方法。文件释放后自动恢复编辑。保存入口执行同一规则，保护原文件与曲库数据。

本轮覆盖歌曲页现有元数据编辑入口及保存链路，保留现有排版、标签校验、文件替换回滚和曲库刷新行为。采用显式保存，播放过程中不自动停播或排队写标签。

## 当前实现与问题

- `MetadataEditDialog.vue` 目前仅根据 `saving` 禁用输入与按钮，没有播放占用提示。
- `useLibraryMetadataEditor.ts` 调用保存接口后刷新曲库；错误统一映射为保存失败。
- `MetadataRefreshService.writeTrackMetadata()` 调用 `writeAudioTags()`，写后核验，再提交数据库；目前没有播放占用检查。
- `audioTagWriteService.ts` 生成新文件，通过原文件改名、替换和备份回滚完成写入。Windows 文件占用可能阻止替换。
- `NativePlaybackService` 包含当前文件、下一首预加载、过渡准备与切换状态。Renderer 的 `currentTrackId`、`isPlaying` 无法独立描述这些文件的使用生命周期。

本次只读检查确认了上述源码结构，尚未运行文件占用复现。实施时应使用隔离音频验证真实释放行为。

## 面板行为

| 状态 | 输入与保存 | 提示及草稿 |
| --- | --- | --- |
| 编辑可用状态尚未确认 | 禁用 | 显示“正在检查编辑状态…” |
| 文件由播放器使用 | 禁用 | 显示占用提示，保留草稿 |
| 文件已释放 | 启用 | 移除占用提示，保留草稿 |
| 正在保存 | 禁用 | 保留现有保存反馈 |
| 状态查询失败 | 禁用 | 显示“无法确认编辑状态，请重试。”并提供重试 |

占用提示固定为：

> 此歌曲正由播放器使用，暂时无法修改元数据。请切换到其他歌曲后再试。

提示放在面板内容区，使用现有主题与辅助信息样式，与字段校验错误、普通保存失败分别管理。所有元数据输入及保存按钮受限，关闭按钮沿用当前保存期间规则。状态变化使用温和的可访问播报，不抢夺焦点；被禁用的控件仍清晰可读。

打开面板可查看原始字段。编辑期间目标歌曲开始播放，立即锁定输入与保存，已经输入的内容保持不变。切走后确认文件释放，再恢复输入。恢复时只更新可用状态，避免重新赋值 `metadata` 导致表单草稿被初始化。关闭后重新打开沿用现有加载逻辑。

占用状态独立于字段合法性；保存必须同时满足状态已确认且可编辑、字段有效、当前未保存。保存被主进程拒绝时，面板保持打开并保留草稿。

## 文件使用边界

按播放器实际使用的文件判断限制：

- 当前播放、暂停、缓冲及加载中的文件均受限。
- 下一首已预加载、正在读取以准备无缝衔接或过渡的源文件均受限；只存在于普通队列中的曲目可编辑。
- 切歌、结束、加载失败和引擎退出后，文件实际释放才解除限制。播放栏继续展示曲目信息，不构成文件占用证据。
- 同一音乐文件对应多个曲目 ID 时，共用占用与写入保护。
- 桥接临时音频与原始歌曲分别追踪；限制针对仍被使用的原始歌曲文件。

文件身份在主进程解析，复用现有合法路径校验并统一规范化策略。覆盖 Windows 路径大小写与规范路径别名；Renderer 只接收曲目可用状态，不接收任意文件操作能力。实施时记录符号链接及硬链接别名的支持范围，不能宣称路径规范化已经识别全部物理文件别名。

## 状态与 IPC

主进程维护文件使用与标签写入协调器，供播放加载、预加载、过渡读取和元数据保存共用。按文件记录读使用权与写入权；多个读取者分别释放，最后一个读取者释放后才允许写入。

编辑状态采用类型化结果，例如 `editable`、`playback-in-use`、`write-in-progress`；通信异常单独处理。名称可按现有契约惯例调整，语义保持一致。

面板打开时订阅状态变更并获取一次初始状态。用单调递增版本或等价机制处理“查询晚于事件返回”的乱序；切换编辑目标、关闭面板与卸载后，旧响应不能更新新面板。订阅应及时清理。事件按生命周期变化发送，不轮询播放进度，也不广播整份曲库状态。

修改契约时同步更新 `src/shared/ipc/contracts.ts`、`channels.ts`、Preload 显式 API、处理器及运行时 payload 校验，保留现有发送方、frame 和可信 URL 验证。

播放后端接入范围以 `playbackAudioRuntime.ts` 的实际可用路径为准。原生后端在主进程获取使用权；若存在 Renderer 音频或解码回退，必须通过显式 IPC 在读取前获取使用权，释放媒体资源后归还。内存解码完成并释放源文件后可解除文件占用。实施交付需列明实际覆盖的后端。

## 保存与加载的并发规则

主进程在任何标签写入动作前，原子地检查并获取该文件写入权。存在播放读取者时直接返回业务拒绝；检查与占有之间不能留下异步空隙。

建议保存接口采用可序列化的判别结果：成功、播放器使用中、同文件写入中。业务拒绝通过类型化字段传递，避免依赖 Electron 序列化后的错误文本。普通 I/O、核验和数据库异常沿用现有失败处理。

保存先获取写入权时，同文件的新播放加载等待写入结束；其他文件的播放正常进行。等待期间若用户切歌、停止、播放会话替换或窗口销毁，取消旧加载请求。等待结束后再次检查 session、请求代际与目标有效性，只有最新请求可继续。预加载等待不得阻塞当前歌曲播放；过时预加载应直接取消。

写入权保持到文件替换、写后核验及数据库提交流程结束，通过 `finally` 释放。失败与关闭路径也必须释放等待者。采用按文件协调，避免把全部播放命令排在一次标签写入之后；复用现有播放串行队列时，应防止释放命令被等待任务阻塞。

播放器占用拒绝发生在现有写入 `try/catch` 与文件变更通知之前，因而不生成临时文件、不更新数据库、不抑制 watcher，也不加入写后 reconciliation。真正执行写入后的失败继续沿用原有核验、回滚与修复流程。

面板状态用于即时反馈，保存入口的原子保护负责最终裁决。状态变化不能中途取消已经获得写入权的正常保存，也不能触发自动保存。

## 验收

### 定向自动化

- 协调器：同文件读取阻止写入、多个读取者释放、不同文件独立运行、原子竞争、写入后加载等待与取消。
- Metadata Service：占用拒绝不调用写文件、数据库提交、watch 抑制或 reconciliation；成功与失败均释放写入权；现有写后核验继续通过。
- Playback：播放、暂停、加载、预加载与过渡均登记使用；切歌、异常、dispose 清理完整；等待保存时取消旧 session，不恢复旧目标。
- 编辑 composable 与面板：初始查询、事件乱序、查询失败重试、编辑中锁定、解锁保留草稿、保存业务拒绝、目标切换与卸载清理。
- IPC：请求校验、判别结果、事件版本与 Preload 暴露同步。

更新现有 `useLibraryMetadataEditor.test.ts`、`metadataRefreshService.test.ts`、相关播放 runtime/service 测试，并为新增协调模块添加行为测试。运行类型检查及修改文件的 lint、格式检查。

### 隔离运行检查

使用临时合成音频与独立曲库，在深浅主题分别查看面板。覆盖播放、暂停、编辑期间开始播放、切歌后解锁、预加载下一首、连续快速切歌、保存失败、关闭与重开面板。

占用时直接调用保存接口，确认音乐文件字节及数据库字段均未改变。保存与加载同时触发时，确认先获得的使用权决定执行顺序；保存完成后只执行最新有效加载。验证正常元数据保存、标签核验和刷新仍然成立。
