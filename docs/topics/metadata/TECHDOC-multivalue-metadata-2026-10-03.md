# 多值元数据统一处理规则

日期：2026-10-03；2026-10-04 补充 foobar2000 的 ID3v2.3 流派兼容规则。适用于艺术家、专辑艺术家、流派、作曲者和版权信息。

本规则取代[旧流派分隔方案](plan-genre-delimiter-atomic-compounds.md)中的分隔符集合。

## 目标与数据流

同一组值在文件读取、数据库存储、关联、筛选、统计和展示中保持一致。

```text
文件原生数据项 → 按格式与字段解码 → 候选值列表
编辑字符串 → 按 "; " 拆分 → 候选值列表
    → 字段提取 → 值列表清洗 → "; " 存储
    → 共享拆分器 → 匹配、统计或展示
```

## 统一规则

1. 文件提供的多个原生数据项是多个候选值，包括数组、重复标签和 MP4 的多个 data 项。
2. 文件读取先应用明确的格式与字段兼容规则，得到候选值列表；通用字符串拆分器只按半角分号加半角空格 `; ` 拆分。
3. 通用规则中，逗号、斜杠、`&`、全角分号、单独的半角分号均属于值的内容。`AC/DC`、`R&B/Soul`、`Tyler, The Creator` 保持完整。ID3v2.3 `TCON` 的分号兼容规则见下节。
4. 清洗去除每项首尾空白和空项，忽略大小写去重，保留首次出现顺序与写法。
5. 内部规范化结果使用数组；现有数据库和 IPC 字符串使用 `joinDelimitedValues` 拼成 `; `，空字段使用 null。
6. 编辑保存先规范化请求，再将同一个结果用于文件写入、读回核对和数据库提交。
7. 只读展示使用 `A`、`A & B`、`A, B & C`，或按项排列。展示字符串不作为存储来源。

在通用字符串拆分器和编辑输入中，`A;B` 是一个值；`A; B` 是两个值。`A;  B` 包含合法分隔符，拆分后清理额外空白并存成 `A; B`。文件格式兼容规则在通用清洗前执行。

## 字段提取与来源

各格式的标签映射属于主进程读取层。Renderer 只消费规范化字段。

艺术家和专辑艺术家优先使用明确的复数字段；有效数组存在时，合并后的单数字符串不再追加为一个艺术家。读取器没有映射的原生字段由 Auralis 的明确字段映射补取。

流派与作曲者收集 common 和支持的 native 字段，按同一规则清洗去重。版权信息保留 native 多项及 `; ` 字符串。

文件没有专辑艺术家时，只在展示规范化结果中回退到艺术家；写入核对比较真实标签，不使用该回退值。标题、专辑标题、日期等标量字段不按多值规则拆分。

旧 ID3v2.2 / ID3v2.3 的读取库会按 `/` 展开部分文本帧。统一文件读取入口在出现这种展开时读取原始文本，保留斜杠，并继续支持重复帧和 NUL 数据项。读取具有长度边界；无法可靠解析的文本返回明确错误。

## ID3v2.3 流派兼容规则

foobar2000 的属性窗口使用 `; ` 表达多个值，窗口中的空格属于显示与编辑形式。其 ID3v2 流派处理使用分号作为多值分隔符，见[官方更新记录 1.1.13](https://www.foobar2000.org/changelog-old)。文件解码应依据原始标签的格式与字段。

2026-10-04 对《Concert YY 黃偉文作品展》32 首 MP3 的只读核对确认：fb2k 属性窗口显示 `Live; Cantopop`，文件实际使用 ID3v2.3，单个 `TCON` 文本为 `Live;Cantopop`。修复前，读取结果与数据库均为一个值；读取兼容规则如下。

1. 在主进程统一文件读取入口，对 ID3v2.3 的 `TCON` 文本按半角分号 `;` 解码多个流派，允许分号两侧存在空白；每项随后按通用规则清洗去重。`Live;Cantopop` 与 `Live; Cantopop` 均得到 `['Live', 'Cantopop']`。
2. 同一字段的 common 与 native 候选使用同一解码结果，避免将未解码的 `Live;Cantopop` 再追加为第三个流派。保留重复帧、原生数据项和已有流派代码映射的处理。
3. 此兼容规则限定于文件读取层的 ID3v2.3 `TCON`。通用拆分器、编辑输入、其他字段和其他标签格式继续遵循各自规则；新增兼容范围需有对应格式或实际文件证据。
4. 规范化后的值列表统一存为 `Live; Cantopop`，只读展示为 `Live & Cantopop` 或两个独立项。扫描、增量导入、文件监听、刷新和编辑后的文件读回共用此行为。
5. 存量记录按当前文件标签复核后更新，沿用下节的数据保护要求。fb2k 的合法多值标签可由读取层直接兼容。

2026-10-04 已实现统一读取入口的兼容处理，并在备份后更新上述专辑 32 首歌的 `tracks.genre` 与 `track_metadata.genre_display`，音乐文件保持原样。实际编码的 MP3 读取、数据库存储和还原试验已验证；其他存量记录可通过元数据刷新应用此读取规则。

## 存储与数据保护

扫描、增量导入、文件监听和元数据刷新共用文件读取与字段规范化。刷新仓库从规范值列表生成两层字段，关联表使用同一列表。已有 `user_edit` 字段保留。

现有数据修复以当前音乐文件的原生值为证据，按记录核对。逗号字符串不进行全库替换。执行前生成包含 WAL 已提交数据的一致备份；提交时重新检查文件指纹、路径、原字段和来源，并限定修改目标字段。

用户编辑覆盖具有优先级。文件不可读或来源不明的记录保留原数据并报告；名称差异不自动作同义词映射。

文件已缺失时，仅对两层值存在精确 `; ` → `, ` 对应、来源为 `file_tag` 且符合已确认旧写入路径的记录修复序列化格式，沿用已有底层值；不推测文件内容或新增标签值。

| --- | --- | --- | --- |
| 两个原生 GENRE：Pop、Live | Pop / Live | `Pop; Live` | `Pop & Live` |

| ID3v2.3 `TCON`：`Live;Cantopop` | Live / Cantopop | `Live; Cantopop` | `Live & Cantopop` |
