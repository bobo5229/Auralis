# 侧边栏 UI 迭代经验

复盘日期：2026-10-14。

本次迭代涉及侧边栏品牌、导航图标、底部工具区、状态文案和相邻面板的配色、材质。本文记录对话中可复用的设计与实施方法；具体图标、颜色和尺寸以当前产品规格及源码为准，不将一次选择固定为全局设计约束。

## 图标尺寸与视觉重量分别判断

导航和工具图标统一尺寸后，单音符、叠层、矩形内光盘和复杂线框仍会呈现不同的视觉重量。同一宽高或 viewBox 只约束几何尺寸，笔画、实心区域、图形占用面积和内部留白共同影响观感。

后续先在同一组图标中比较笔画与造型，再将候选放进真实导航行，结合文字、行高及选中背景观察。必要的局部尺寸修正应服务于光学一致性，不凭单个图标放大后的画面判断整组是否统一。

品牌 SVG 的来源、导出及内联路径一致性维护沿用[应用资源说明](../../resources/README.md)，不另建品牌图形来源。

## 对齐先说明参照物

品牌与导航左对齐、设置入口与导航文字对齐、绿点与文案居中，是不同的对齐关系。文案换行或预留轮播空间后，首行、当前文字块和整个容器的中心也可能不同。

实施前用具体对象表达对齐目标：哪些图标共用左边界、文字从哪里开始、圆点相对哪个文字块居中。长短内容切换时继续保持已确认的关系，避免仅让容器居中而可见内容仍偏移。空间边界沿用[动态布局与滚动](../rules/renderer.md#动态布局与滚动)。

## 完整文案作为内容约束

用户明确喜欢趣味文案的完整表达，并确认固定字号后，压缩文案或缩小字号会改变已接受的体验。此时需要调整内容占用的空间：文案独占一行宽度、工具另起一行，或按后续明确需求采用局部滚动等方式。

选择方式时同时考虑阅读时间、换行高度、工具位置和轮播造成的布局变化。根据当前语言的真实内容安排空间，避免只按一条短中文样例设计。暂停与恢复应围绕阅读和界面可见性处理，具体时长及展示方式留在功能规格中。

排版与溢出约束直接引用[通用文字规格](../rules/renderer.md#通用文字规格)和[动态布局与滚动](../rules/renderer.md#动态布局与滚动)。

## 趣味表达保留真实状态来源

常驻轮播提供氛围，曲库状态仍决定圆点、无障碍说明和刷新按钮是否可用。趣味句子不能被当作扫描阶段或完成结果；移除状态区 tooltip 后，真实状态也不能失去表达渠道。

状态展示应覆盖所有扫描入口，包括设置页启动的扫描。异步读取目录和扫描记录时，防止旧查询覆盖较新的进度；完成、失败及重试也要恢复相应操作状态。轮播定时器与状态订阅各自处理暂停和卸载，不以趣味轮播替代真实状态订阅。

跨进程能力沿用[架构与 IPC](../rules/architecture.md)，当前行为的测试与验收按[风险与验收](../rules/validation.md)执行。

## 视觉符号与交互行为分别确认

截图中的 `⌘,` 可以是快捷键提示，也可能只是本次要求展示的视觉符号。显示符号、调整大小和增加容器都不自动授权新增键盘绑定；是否存在绑定需核对当前实现，并分别说明展示与执行行为。

tooltip 也应按目标入口处理。移除状态文案的悬停提示，不等于移除三个工具的提示，更不等于删除悬停暂停轮播。修改前沿事件和状态链确认具体行为，防止共享样式或监听逻辑扩大改动范围。焦点及临时状态约束引用[临时状态与菜单交互](../rules/renderer.md#临时状态与菜单交互)。

## 回滚以本轮差异为边界

系统毛玻璃实现被用户认为效果不佳并要求撤回时，先前确认的浅色面板颜色仍需保留。文件中还可能存在其他任务的修改，因此回滚应识别并撤销本轮新增的窗口材质、能力标记和透明样式，复查剩余差异的归属。

这次反馈能够证明用户不接受呈现效果；施工阶段没有运行验收证据，不能进一步推断为 Electron API 失效或系统材质不可用，也不应据此禁止后续使用毛玻璃。技术原因留给后续有证据的诊断。

保护已有修改和差异复查沿用[施工者规则](../rules/implementation.md#职责与权限)；需求收缩后的关联清理引用[UI 冗余清理经验](2026-10-06-ui-cleanup-lessons.md)。

## 配色与材质的规则落点

侧边栏颜色 token 同时被设置与筛选弹窗使用，说明按面板名称修改仍可能影响其他表面。共享变量的范围判断已补入[颜色 token 的影响范围](../rules/renderer.md#颜色-token-的影响范围)。

从应用内毛玻璃到桌面毛玻璃的澄清，以及原生材质效果回滚，已补入[材质与采样对象](../rules/renderer.md#材质与采样对象)。时间范围选择器的三方案 HTML 对比用于布局与交互选择；桌面材质需另用原生窗口呈现。通用原型方法引用[原型与音频效果](../rules/validation.md#原型与音频效果)。
